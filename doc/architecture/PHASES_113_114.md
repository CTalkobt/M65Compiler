# Phases 113-114: DWARF Debug Support & Enhanced Error Messages

## Overview

These two phases significantly improve the compiler's usability by adding source-level debugging support and making error messages more helpful.

## Phase 113: DWARF 4 Debug Information

### Objectives
- Enable source-level debugging in emulators and hardware debuggers
- Track source file, line number, and column information
- Generate DWARF 4 debug sections (.debug_info, .debug_line, .debug_abbrev, .debug_str)
- Preserve type information through compilation

### Key Features

#### 1. Source Location Tracking
```c
struct SourceLocation {
    std::string filename;
    int line;       // 1-based
    int column;     // 1-based
    int endColumn;  // For ranges
};
```

#### 2. DWARF Sections Generated
- **.debug_info**: Debug information entries (DIEs)
- **.debug_line**: Line number program and file info
- **.debug_abbrev**: Abbreviation declarations
- **.debug_str**: String pool for names

#### 3. Metadata Tracked
- Source files and directories
- Function definitions and boundaries
- Variable declarations and locations
- Type information (primitives, structs, pointers)
- Line number program for address → line mapping

## Phase 114: Enhanced Error Messages

### Objectives
- Display source context (surrounding code)
- Show exact error position (column + caret)
- Provide actionable suggestions
- Categorize errors clearly
- Enable typo detection with suggestions

### Key Features

#### 1. Error Message Format
```
file:line:column: severity: message
 line | source code with error
      | ^^^^^ error position
      | ~~~~~ error range

Suggestions:
  • Did you mean 'xyz'?
  • Use explicit cast: (int)x
```

#### 2. Source Context Display
```c
// Before:
error.c:5: undefined identifier 'prntf'

// After:
error.c:5:5: error: undefined identifier 'prntf'
  4 | int main(void) {
  5 |     prntf("hello");
    |     ^^^^^
    
Suggestions:
  • Did you mean 'printf'?
```

#### 3. Suggestion Categories
- **Typos**: Levenshtein distance-based suggestions
- **Type Mismatches**: Show expected vs. actual types
- **Common Mistakes**: Missing semicolons, = vs ==, unreachable code
- **Type Conversions**: Suggest explicit casts
- **Function/Variable**: Similar names for undefined symbols

#### 4. Error Categories
1. **Lexer Errors** - Invalid tokens, unterminated strings
2. **Parser Errors** - Syntax violations, unmatched braces
3. **Semantic Errors** - Type mismatches, undefined symbols
4. **Code Generation** - Optimization failures, unsupported constructs
5. **Linker Errors** - Undefined symbols, address conflicts

## Technical Notes

### DWARF 4 Rationale
- Mature, stable standard
- Good balance of features vs. complexity
- Widely supported by debuggers
- Efficient encoding (abbrev table)

### Error Message Strategy
- Context-first: Show code first, suggestions later
- Progressive detail: Basic → detailed on request
- High confidence: Only suggest when confident
- Actionable: Every suggestion should be fixable

### Performance Impact
- Debug info optional (can be disabled with flag)
- Line tracking minimal overhead (1-2% compile time)
- Error messages same performance as before
