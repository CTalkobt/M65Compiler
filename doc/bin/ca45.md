# ca45 — MEGA65 45GS02 Assembler

`ca45` assembles 45GS02 source into a flat binary, a `.prg`, or a relocatable `.o45` object for `ln45`. Besides the native instruction set it offers procedures with named parameters, local labels and scopes, compile-time loops and arrays, and a set of *simulated* instructions (multi-instruction macros such as `add.16` or `mul.32`) that `cc45` also emits.

## Getting Started

### A first program

```assembly
        .basicUpstart start     ; BASIC stub "10 SYS 8205" at $2001
start:
        ldx #0
@loop:  lda message,x
        beq @done               ; zero byte ends the string
        sta $0800,x             ; MEGA65 screen RAM
        inx
        bne @loop
@done:  rts
message: .screencode "HELLO"
        .byte 0
```

```bash
ca45 hello.s45 -o hello.prg
xemu-xmega65 -prgmode 65 -prg hello.prg     # or load it on the MEGA65 and RUN
```

`.basicUpstart` sets the start address to `$2001` (when no `.org` precedes it) and emits a 12-byte `SYS` line; because the output name ends in `.prg`, a 2-byte load address is prepended.

### Common patterns

```assembly
        lda #<table             ; low byte of an address
        ldx #>table             ; high byte
        jsr subroutine          ; call / rts returns

        ldx #10
@loop:  dex                     ; @labels are local to the previous plain label
        bne @loop

counter = $20                   ; an equate (assembler constant)
        inc counter             ; base-page access ($20 < $100)
```

### Things that commonly go wrong

- **Labels need a colon** (`main:`), and **all symbols are case-sensitive** (`foo` and `FOO` are different labels). Mnemonics, register names and directive names are case-insensitive.
- **Write binary minus with spaces**: `lbl - 1`, `5 - 1`. A `-` directly followed by a digit is lexed as a negative number, so `lbl-1` and `5-1` silently drop the `-1`.
- **Code after `rts`/`rtn`/`rti` is discarded until the next label** (at every `-O` level). Put a label on code that is reached by other means.
- `.byte`, `.dword`/`.long`, `.org` and the fill value of `.res`/`.align` take **literal numbers only** (`.byte` also takes character literals); use `.word` for symbol values.
- `.text` is the PETSCII string directive, not a segment switch — use `.code`.
- In a flat binary, a segment without its own `.org` starts at address 0 (see *Segments*).
- `nop` is rejected: `$EA` is the 45GS02 `EOM` prefix.

## Command-Line Usage

```bash
ca45 [options] <input_file>
```

| Option | Meaning |
|--------|---------|
| `-c` | Produce a relocatable `.o45` object (default output `out.o45`) instead of a flat binary. |
| `-o <file>` | Output file (default `out.bin`, or `out.o45` with `-c`). A name ending in `.prg` gets a 2-byte load address taken from the first `.org` (or `$2001` after `.basicUpstart`); without either, no header is written. |
| `-L <file>` | Write a listing: address, up to 4 bytes per line, source line, then the symbol table. |
| `-l <level>` | `1` (default) normal output. `2` writes the *expanded assembly* (simulated instructions expanded, after optimisation) to the `-o` file instead of a binary. |
| `--dry-run` | Assemble and optimise, then print the symbol count, the number of byte-producing statements and the total size; no output file. |
| `--source-map <file>` | Write an address → source-line map plus the symbol table. |
| `--emulator` | After writing a `.prg`, launch the first of `x64`, `x64sc`, `mega65`, `mega65_emu` found on `PATH`. |
| `--emulator-path <path>` | Emulator to launch with `--emulator`. |
| `--watch` | After assembling, poll the input once a second and reassemble when it changes (flat/`.prg` output only). |
| `-O<n>` | Optimisation level, default `-O2`. `-O0` disables every optimiser pass; `-O1`, `-O2` and `-O3` enable the same peephole passes (`-O2`/`-O3` also run the striped-array passes that only match `cc45` output). `-O` alone or an unknown digit means `-O2`. |
| `-P<Name>` / `-PNo<Name>` | Enable/disable one optimiser pass after `-O` (see below). Unknown names are ignored. |
| `--experimental` | Allow the `SeqExtract` pass (duplicate-sequence extraction). Experimental; not for production code. |
| `-Roptimizer` | Report each optimisation to stderr, e.g. `opt: f.s45:asm:2: [tail-call] JSR sub + RTS → JMP (saved 1 byte)`. |
| `-Rmachstate` | Trace the optimiser's register/flag state tracking. |
| `-I<path>` | Add an include directory (see *Preprocessor*). |
| `-D<name>[=<value>]` | Define a preprocessor macro **and** an assembler symbol (value `$hex`, `%binary` or decimal; default 1). |
| `-Woverflow`, `-Wunderflow` (`--warn-overflow`, `--warn-underflow`) | Accepted but currently have no effect (the 8-bit truncation warning below is always on). |
| `-v` / `-vv` | Print the phases (`Preprocessing…`, `Lexing…`); `-vv` also dumps every token. |
| `-V`, `--version` | Print the version. |
| `-?`, `--help`, `--help=<section>` | Help; sections `input-output` (`io`), `optimization` (`opt`), `debugging` (`debug`), `preprocessor` (`prep`), `diagnostics` (`diag`). |

Predefined symbols: `cc45.zeroPageStart` (default `$02`; base of the `.zp_uses` bit numbering) and `__sp_base` (default `$0101`; page-1 stack base used by the `TSX`-based operations). Override them with `-D`, e.g. `-D__sp_base=$4001`. The scratch base-page byte used by several simulated instructions is `__zp_scratch` if defined, else `$02`.

### Optimiser passes (`-P<Name>` / `-PNo<Name>`)

| Name | Pass |
|------|------|
| `TailCall` | `JSR x` + `RTS` → `JMP x` |
| `JmpBra` | `JMP` → 8-bit `BRA` when the target is local and in range |
| `JSRRelocate` | `JSR` → `BSR` (16-bit relative) for local, non-relocatable targets |
| `NoOpBra` | Remove a `BRA` to the next instruction |
| `BranchInvert` | Conditional branch over a `BRA` → one inverted branch |
| `CmpElimination` | Remove `CMP #0` when the flags already reflect A |
| `RedundantLoad` | Remove loads of a value a register already holds |
| `StoreLoadPair` | Store/load pairs on base-page addresses |
| `DeadStore` | Remove overwritten `stw.sp` frame stores |
| `TailDedup` | Merge identical code tails |
| `PreserveXSP` | Keep X = SP across `TSX`-based stack accesses |
| `TSXRedundant` | Remove a `TSX` when X already holds SP |
| `FCmpOpt` | Float-compare result patterns from `cc45` |
| `SeqExtract` | Extract duplicate sequences (only with `--experimental`) |

`-P` also accepts the `cc45` IR pass names (`StrengthReduction`, `CSE`, `LICM`, …); they have no effect in ca45.

```bash
ca45 -O2 -PNoTailCall prog.s45 -o prog.o45 -c
ca45 -O0 -PRedundantLoad prog.s45
ca45 -Roptimizer prog.s45 2>&1 | grep redundant
```

Independently of `-O`, branches always get the shortest form, `rtn #0` becomes `rts`, and code after a return is dropped (see *Optimizations*).

### Configuration files and environment

Before the command line, ca45 reads arguments from, in this order: `~/.config/m65/ca45.conf`, `.ca45rc` in the current directory, then `CA45_OPTIMIZE=<n>` (→ `-O<n>`) and `CA45_WARNINGS=overflow:underflow` (colon-separated → `-W…`). Later arguments override earlier ones. Files hold one argument per line; blank lines and lines starting with `#` are ignored; each whole line is one argument (no quoting, no trailing comments, so write `-Ipath`, not `-I path`).

> **Known defect**: while any of these sources supplies an argument, options that take a separate value (`-o`, `-L`, `-l`, `--source-map`, `--emulator-path`) read the wrong argument — `ca45 -o out.bin in.s45` can even overwrite `in.s45`. Use these sources only when you pass no such options.

`CC45_INCLUDE` adds colon-separated include directories, searched before `-I` paths.

### Preprocessor

Source first goes through the suite's C preprocessor: `#define` (object- and function-like), `#undef`, `#if`/`#ifdef`/`#ifndef`/`#elif`/`#else`/`#endif`, `#error`, `#warning`, `#pragma once` and line continuation all work; `-D` names are visible to `#ifdef`.

> **Known defect**: `#include` currently fails in ca45 (the `#line` markers the preprocessor inserts are rejected as `Unknown instruction '#'`). There are no `.include`/`.if`/`.ifdef` directives — such lines are silently ignored like any unknown directive.

## Syntax

- **Comments**: `;`, `//` and `/* … */`.
- **Labels**: `name:` at the start of a statement. A label may share the line with an instruction or directive.
- **Local labels**: `@name:` is scoped under the nearest preceding plain label (stored as `parent:@name`), so `@loop` can be reused in every routine. Inside a `proc`, labels are scoped by the procedure name. Duplicate labels in one scope are an error. `@` labels do not reset the optimiser's register tracking.
- **Scoped names**: `cc45` output uses colon-separated names such as `main:L0`; resolution tries the innermost scope first, then enclosing scopes, then the global name.
- **Anonymous scopes**: `{ … }` opens a local scope (internally `_S<n>`) for labels.
- **Equates**: `NAME = expr` (redefinable; evaluated when encountered). See also `.const`, `.var`.
- **Program counter**: `*` in an operand is the current address when followed by `+`, `-` (with a space before a number), `,`, `)`, `]` or the end of the line: `bra *+4`, `lda * - 2`. `* = $addr` sets the origin like `.org`.
- **Addressing-mode syntax**: `#imm`, `bp`/`abs` (chosen by value), `addr,x`, `addr,y`, `(bp,x)`, `(bp),y`, `(bp),z`, `[bp],z` (32-bit flat, emits the `EOM` prefix), `(bp,sp),y`, `(abs)`, `(abs,x)`, `bp, target` (BBR/BBS), `A` or nothing (accumulator), `offset, sp` (simulated frame access). Plain `(bp)` is not a 45GS02 mode — write `(bp),z`.

### Literals

| Form | Example |
|------|---------|
| Hex / decimal / binary | `$1234`, `123`, `%1010` (`0x…` is **not** supported — `0x10` reads as `0`) |
| Negative number | `-1` (32-bit two's complement) |
| Character | `'A'` = PETSCII (letters case-swapped: `'a'`→`$41`, `'A'`→`$61`), `s'A'` = screen code (`$01`), `p'A'` = PETSCII |
| String | `"text"` with escapes `\n \r \t \a \b \f \v \xHH \ooo \" \\`; prefix `s"…"`/`p"…"` to force screen codes/PETSCII |

### Expressions

Values are 32-bit unsigned. Precedence, high to low:

| Level | Operators |
|-------|-----------|
| 1 | literals, symbols, `( )`, `defined(sym)`, `lo(e)`, `hi(e)`, `bank(e)`, `array[i][j]`, `*` (PC) |
| 2 | `*` `/` (integer division; division by zero is an error) |
| 3 | `+` `-` |
| 4 | `<<` `>>` (logical) |
| 5 | `&` |
| 6 | `^` |
| 7 | `\|` |
| 8 | `==` `!=` `<` `<=` `>` `>=` (1 or 0) |
| 9 | `&&` |
| 10 | `\|\|` |

- **Prefix operators apply to everything that follows**: `-`, `~`, `!`, `<` (low byte), `>` (high byte). `<lbl + 1` is `<(lbl + 1)`; `~0 & $FF` is `~(0 & $FF)`. Use parentheses: `(~0) & $FF`.
- `lo(e)`, `hi(e)`, `bank(e)` give bits 0–7, 8–15 and 16–23.
- `defined(sym)` is 1 if the symbol exists at that point, else 0.
- There is no `%` (modulo), `**` or `?:` operator, and `$` is not the program counter.

## Directives

Unknown directives are **silently ignored** — check spelling.

### Data

| Directive | Effect |
|-----------|--------|
| `.byte v, …` | One byte per argument. Numeric literals and character literals only. |
| `.word v, …` | 16-bit little-endian words. Each argument may be a literal, a symbol, `symbol + n`/`symbol - n`, or `sym1 - sym2`; symbols get relocations in `-c` mode. Other expressions are mis-assembled (`.word 1+2` gives 1, `.word K*2` is an error). |
| `.dword v, …` / `.long v, …` | 32-bit little-endian; numeric literals only. |
| `.float v, …` | 5-byte CBM floating point (`.float 1.5` → `81 40 00 00 00`). |
| `.text "s"` | PETSCII string (letters case-swapped; `\n` → `$0D`). Exactly one string argument. |
| `.ascii "s"` | Raw ASCII (`\n` → `$0A`). |
| `.screencode "s"` | Screen codes (`@`→0, `A`/`a`→1 …). |
| `.res n[, fill]` | Reserve `n` bytes (`n` may be an expression; `fill` a literal, default 0). In `.bss` no bytes are emitted. |
| `.fill n`, `.space n` | Reserve `n` zero bytes (a fill argument is ignored). |
| `.align n[, fill]`, `.balign n[, fill]` | Pad to a multiple of `n` (`n` non-zero literal). |
| `.fillto addr[, fill]` | Pad up to `addr`; error if already past it. |
| `.incbin "file"`, `.import binary "file"` | Insert a file's bytes (path relative to the current directory). |
| `.array name, elsize, dim0[, dim1 …]` | Reserve a zero-filled row-major array; see *Arrays*. |
| `.basicUpstart addr` | 12-byte BASIC line `10 SYS addr`; sets the origin to `$2001` if no `.org` came first. |

### Location and segments

| Directive | Effect |
|-----------|--------|
| `.org addr`, `* = addr` | Set the program counter (numeric literal). |
| `.segment name` / `.segment "name"` | Switch segment; `.segment "name" { … }` switches back after the block. |
| `.code`, `.data`, `.bss` | Shortcuts for the segments `code`, `data`, `bss`. |
| `.segmentOrder a, b, …` | Order in which segments are written (default `init, code, data, bss`, then the others in order of appearance, including `default` — the segment used before any switch). |
| `.cpu name` | Accepted and ignored. |

**Flat binaries**: segments are concatenated in segment order and `bss` is never written. A segment whose first statement is not preceded by its own `.org` starts at address **0** (its labels evaluate from 0), so in a flat program either stay in one segment or give every segment an `.org`. Gaps between `.org` addresses are filled with zeros.

**`-c` objects**: `code`, `text`, `init`, `default` and any other name go to the TEXT section, `data` to DATA, `bss` to BSS, `zp` to ZP; `ln45` places them.

### Symbols

| Directive | Effect |
|-----------|--------|
| `.const NAME = expr` | Constant; redefining it (or assigning it with `=`) is an error. |
| `.var NAME = expr`, `.var NAME++`, `.var NAME--` | Assembler variable that can be reassigned; reassignments are tracked by position. |
| `.global a, b` | Export symbols from a `.o45`. |
| `.weak a, b` | Export as weak: a strong (`.global`) definition in another object wins at link time. |
| `.extern a, b` | Import symbols (value 0 until linked). An `.extern` base-page symbol is assembled as absolute. |
| `.local NAME = offset` | Name a frame offset for the `.fp` instructions. |

### Compile-time loops

`.repeat n` … `.endrepeat` copies its body `n` times (any constant expression; nesting allowed):

```assembly
        .repeat 8               ; 8 × 5 bytes, no loop overhead
            lda (src),y
            sta (dst),y
            iny
        .endrepeat
```

### Arrays

`.array name, elsize, d0[, d1 …]` defines label `name`, reserves `elsize × d0 × d1 × …` zero bytes, and defines the constants `name.__elsize`, `name.__dims`, `name.__dimN` and `name.__strideN` (row-major: `stride[i] = product(dims[i+1..]) × elsize`).

```assembly
        .array board, 1, 8, 8           ; stride0 = 8, stride1 = 1
        expr .a, board[2][5]            ; lda board+21
        expr .a, board[.y][.x]          ; index computed at run time
        lda board + 2 * board.__stride0 + 5 * board.__stride1
```

Run-time indices use `ASL` for power-of-two strides and the hardware multiplier otherwise.

### Procedure and object metadata

| Directive | Effect |
|-----------|--------|
| `.func_flags f, …` | Function attribute flags: `zp_call`, `stack_call`, `leaf`, `reentrant`, `static_alloc`, `zeroalloc`, `isr`. |
| `.reg_clobbers A, X, Y, Z` | Registers not preserved. |
| `.flag_clobbers C, N, Z, V` | Flags not preserved. |
| `.zp_uses a, …` / `.zp_clobbers a, …` / `.zp_release a, …` | Base-page bytes read as parameters / overwritten / consumed. Addresses `cc45.zeroPageStart+1` … `+32` (default `$03`–`$22`) are recorded; lower ones are ignored, higher ones are an error. |
| `.frame_size n` | Frame/activation record size (0–65535). |
| `.param_sizes s, …` | Parameter sizes in bytes (1–255). |
| `.param_const fn idx value` | Constant-argument hint for the linker. |
| `.cleanup n` | Add `n` bytes to the procedure's parameter size. |
| `.frameptr_zp $nn` | Base-page address of the frame pointer used by `offset, sp` and `.fp` accesses (default `$FD`). |
| `.sac` | Mark the current procedure as statically allocated (compiler use). |
| `.loc "file", line` | Attribute following code to a source line (listings, `-Roptimizer`, debug info). |
| `.noopt_start`, `.vtable_entry …` | Compiler markers. |

All of these except `.frameptr_zp`, `.sac`, `.loc`, `.noopt_start` and `.vtable_entry` must be inside `proc`/`endproc`. In `-c` mode the attributes are written as a function attribute record for the procedure's symbol (`nm45 -f` shows them; `ln45` uses them for calling-convention checks and clobber-aware optimisation). The record attaches only to a **named** procedure, `proc <name>` together with `.global <name>`; in a bare `proc` the assembler warns `.func_flags in an unnamed 'proc' is ignored: name the function with 'proc <name>' (and .global <name>)`. Objects without attributes are treated conservatively (clobber everything).

```assembly
        .global _add_words
proc _add_words
        .func_flags zp_call, leaf
        .zp_uses $03, $04, $05, $06
        .zp_clobbers $03, $04
        .reg_clobbers A, X
        .flag_clobbers C, N, Z, V
        lda $03
        clc
        adc $05
        sta $03
        lda $04
        adc $06
        tax
        lda $03
endproc
```

`nm45 -f` then prints `_add_words  [zp_call leaf uses:03-06 clobbers:03-04 releases:- regs:AX flags:CNZV]`.

## Procedures

```assembly
proc name[, [B#|W#|D#|F#]param, …]
        …
endproc
```

- `proc` emits no code; it defines the label `name`, opens a scope and defines each parameter as a frame offset. The size prefix is upper-case: `B#` byte, `W#` word (default), `D#` dword, `F#` 5-byte float. Byte parameters still occupy a 2-byte slot. The first parameter is at offset 2, the next follows it; `ARG1`, `ARG2`, … are aliases.
- Parameters are used with the frame-relative forms, e.g. `lda count, sp` or `ldax ptr, sp`.
- `endproc` emits `rts` (1 byte) unless the previous instruction already returned; the caller removes arguments. Use `rtn #n` to return and drop `n` bytes.
- Nested `proc`, `endproc` without `proc`, and a `proc` left open at end of file are errors.

`call name, arg, …` pushes each argument with `phw` (or `lda #v`/`pha` for a `B#` argument) and then `jsr name`. Arguments are pushed left to right — the opposite of the order `proc` assumes — and a non-immediate argument is pushed as its value as a constant, so prefer explicit `phw`/`jsr` sequences.

## Supported Instructions

The native 45GS02 instruction set, encodings and the auto-selection between base-page and absolute modes are listed in the [45GS02 Instruction Reference](../architecture/opcodes.md). Highlights:

- Z register (`ldz`, `stz` (stores Z), `inz`, `dez`, `phz`, `plz`, `taz`, `tza`, `cpz`), base page (`tab`, `tba`), 16-bit stack pointer (`tsy`, `tys`), `map`, `eom`, `cle`/`see`, `neg`, `asr`, word operations (`inw`, `dew`, `asw`, `row`, `phw`), `bsr`, `rtn #n`, bit operations (`smbN`, `rmbN`, `bbsN`, `bbrN`).
- 16-bit relative branches: every conditional branch and `bra` is assembled in its 8-bit form when the target is in range and its 16-bit form otherwise; `bsr` is always 16-bit.
- Quad (32-bit) instructions `ldq`, `stq`, `adcq`, `sbcq`, `andq`, `oraq`, `eorq`, `cmpq`, `aslq`, `lsrq`, `rolq`, `rorq`, `incq`, `decq`, `negq` (emitted with the `$42 $42` prefix).
- `lda ($nn,sp),y` / `sta ($nn,sp),y` (`$E2`/`$82`) are the native stack-relative *indirect* modes.
- `[bp],z` flat 32-bit indirect for `adc and cmp eor lda ora sbc sta ldq stq` and the Q arithmetic (adds `EOM`).
- `nop` is rejected (`nop disallowed`); write `eom` for an `$EA` byte, or `clv` as a one-byte no-op.

**Base-page warning.** An instruction with a base-page operand (< `$100`) but no base-page form is assembled absolute (`$00xx`), which ignores the relocated base page (B register). ca45 warns, e.g.

```
f.s45:2:5: warning: 'ldz $20' has no base-page mode: assembled as absolute $0020, which ignores the base page register
```

Affected: `ldz $nn` / `ldz $nn,x` (use `ldq`, or `lda` + `taz`), `lda/sta/… $nn,y` except `ldx`/`stx` (use `,x` or `(bp),y`), `phw $nn`. `jmp ($nn)` and `jsr ($nn)` are always absolute indirect, without a warning.

## Simulated Instructions

These expand to native code at assembly time. Register sets: `.a .x .y .z`, `.ax .ay .az .xy` (first letter = low byte), `.q`/`.axyz` (A = byte 0 … Z = byte 3). Unless stated otherwise a memory operand must be a **label** or plain address, `#` marks an immediate, and flags are those left by the last generated instruction.

Several instructions use base-page scratch bytes starting at `__zp_scratch`/`$02` (`cmp.s16`, `cmp.32`, `bfext16`, `bfins*`, `bfext32`, the `.ax` frame loads/stores). The `offset, sp` and `.fp`/`.param`/`.local` forms access the frame through the frame pointer at `$FD/$FE` (or `.frameptr_zp`): `ldy #offset; lda ($FD),y`, so **Y is clobbered** and the frame pointer must have been set up (as `cc45`-generated functions do). Offsets above 255 go through `$FB/$FC`.

### Loads and stores

| Instruction | Forms | Notes |
|-------------|-------|-------|
| `ldax` `lday` `ldaz` `ldxy` | `#imm`, `label`, `param, sp` | Load a 16-bit value (low byte in the first register). |
| `stax` `stay` `staz` `stxy` | `label`, `param, sp` | Store a register pair. |
| `ldw` / `ldw.sp` | `.ax\|.ay\|.az\|.xy, src` | Like `ldax`…; `.sp` treats `src` as a frame offset. |
| `stw` / `stw.sp` | `.ax\|.ay\|.az\|.xy\|#imm, dst` | Store a pair or a 16-bit immediate. A zero high byte of an immediate is written with `stz`, which stores the Z register — keep Z = 0. |
| `lda` `sta` `ldx` `ldy` `ldz` `stx` `sty` `stz` | `offset, sp` | 8-bit frame access through A (`ldx/ldy/ldz` end with `tax/tay/taz`). |
| `lda.sp` / `sta.sp` | `offset` | Same as `lda offset, sp`. |
| `inc`/`dec offset, sp`, `inw`/`dew offset, sp` | | 8/16-bit increment/decrement via `TSX` + `__sp_base+offset,X` (SP-relative on the page-1 stack, not frame-relative; wrong on a 16-bit stack). |
| `phw.sp offset` | | Push the word at `__sp_base+offset,X` (via `TSX`; same restriction). |
| `ptrderef bp` | | AX = 16-bit value pointed to by the pointer at `bp` (Y clobbered). |
| `ptrstack name` | | AX = address of `name` (immediate for a label; computed from the frame pointer or SP for a stack variable). |
| `swap r1, r2` | | Exchange two of A/X/Y/Z through the stack; swapping two non-A registers clobbers A. |
| `push r…` / `pop r…` | `.a .x .y .z .ax .q …` | Push/pull the named registers (pop in reverse). |
| `zero r, …` | `.a .x .y .z` | Load 0 into each register. |

`ldax`/`stax`/`ldw`… with a *numeric* `n, sp` operand do not work (the operand is taken as address `n`); use a named parameter or `ldw.sp`/`stw.sp`.

### 16-bit arithmetic and logic

| Instruction | Destination | Source | Notes |
|-------------|-------------|--------|-------|
| `add.16` `sub.16` (`add.s16` `sub.s16` identical) | `.ax .ay .az`, or a label | `#imm` or memory | `clc`/`sec` included. A numeric destination address is mis-assembled as `$0000`; register-pair sources are not supported. |
| `and.16` `ora.16` `eor.16` | `.ax` only | `#imm` or memory | |
| `cmp.16` (alias `cpw`) | `.ax` | `#imm` or memory | Unsigned: compares X first, then A; use `beq/bne/bcc/bcs`. |
| `cmp.s16` | `.ax` | `#imm` or memory | Signed (sign bit flipped); clobbers A and scratch `$02`. |
| `neg.16` `not.16` (`neg.s16`) | `.ax` or memory | — | Two's / one's complement. `neg.16` on memory is currently off by one (5 → −4). |
| `abs.16` (`abs.s16`) | `.ax` or memory | — | **Currently wrong**: on `.ax` the low byte is lost (−5 → 1); on memory the result is off by one (−7 → 8). |
| `lsl.16` `lsr.16` `asr.16` `rol.16` `ror.16` (+ `.s16` aliases) | `.ax` or memory | — | One-bit shift/rotate through C. |
| `asw` / `row` | `.ax` (simulated) or `abs` (native) | — | Shift left / rotate right a word. |
| `sxt.8` | — | — | X = sign extension of A. |
| `sxt.16` | — | — | Y = Z = sign extension of X (AX → Q). |
| `chkzero.8` / `chkzero.16` | — | — | A = 1 if A (AX) is zero, else 0. |
| `chknonzero.8` / `chknonzero.16` | — | — | A = 1 if A (AX) is non-zero, else 0. |
| `select r, #t, #f` | — | — | A = `t` if Z is clear, else `f` (`r` is ignored). |

### 32-bit operations

| Instruction | Destination | Source |
|-------------|-------------|--------|
| `add.32` `sub.32` (`.s32` aliases) | `.q` or a label | `#imm` or memory |
| `and.32` `ora.32` `eor.32` | `.q` | `#imm` or memory |
| `cmp.32` / `cmp.s32` | `.q` | `#imm` or memory (compares from the high byte down; uses scratch `$02`/`$03`) |
| `neg.32` `not.32` `abs.32` (`.s32` aliases) | `.q` or a label | — |
| `lsl.32` `lsr.32` `asr.32` `rol.32` `ror.32` (`.s32` aliases) | `.q` or a label | — |

### Hardware multiply and divide

`mul.<w> dest, src` and `div.<w> dest, src` (unsigned; `w` = 8, 16, 24 or 32 bits; plain `mul`/`div` = 8) use the math unit (`$D770` inputs A, `$D774` inputs B, product at `$D778`, quotient at `$D76C`; `div` waits for `$D70F` bit 7). `dest` is `.a`, `.ax`, `.q`/`.axyz` (the register set fixes which registers are used; the result is the low `w` bits) or a label/address; `src` is `#imm`, one of those register sets, or a label/address — `$04` without `#` is a memory read. `div` by an immediate 0 is an error. 24-bit register sets (`.axy`) are not supported; use memory.

| Instruction | Operands | Notes |
|-------------|----------|-------|
| `mul.s16`, `div.s16` | `.ax, #imm\|label` | Signed (absolute values, then sign fix-up); Y is clobbered. Division truncates toward zero. |
| `mod.16`, `mod.s16` | `.ax, #imm\|label` | Remainder = dividend − quotient × divisor. **Currently wrong when the low-byte subtraction borrows** (e.g. 256 mod 7 gives 260). |
| `mul.s32`, `div.s32`, `mod.32`, `mod.s32` | `.q, #imm\|label` | 32-bit variants. |

```assembly
        ldax #300
        mul.16 .ax, #3          ; AX = 900
        ldax #1000
        div.16 .ax, #8          ; AX = 125
        ldax #-300
        mul.s16 .ax, #3         ; AX = -900
```

### Bit fields

| Instruction | Operands | Effect |
|-------------|----------|--------|
| `bfext #off, #w` | value in A | A = bits `off…off+w-1` of A (right-aligned), X = 0 |
| `bfext16 #off, #w` | value in AX | AX = extracted field |
| `bfext32 #off, #w` | value in Q | Q = extracted field |
| `bfins addr, #off, #w` | new value in A | Read-modify-write of the byte at `addr` (`TRB`/`TSB`); A = the updated byte |
| `bfins.sp offset, #off, #w` | A | Same on a frame byte (Y clobbered) |
| `bfins.ind bp, #off, #w` | A | Same through the pointer at `bp` (Y clobbered) |
| `bfins16`, `bfins16.sp`, `bfins16.ind` | AX | 16-bit storage unit; AX = updated word |
| `bfins32`, `bfins32.sp`, `bfins32.ind` | Q | 32-bit storage unit |

`lda #3` / `bfins $4000, #0, #2` stores 3 into bits 0–1 of `$4000`.

### Expressions in code

`expr target, expression` evaluates an expression into `.a`, `.ax`, or a label (stored as a word). Constant expressions become immediate loads (`lda #lo` / `ldx #hi`, so `.ay`, `.az` and `.q` targets do not get their upper bytes); array indexing with run-time indices is supported (see *Arrays*). The `P.C`-style flag operands are not recognised.

### Frame and parameter access (compiler use)

`lda.fp sta.fp ldax.fp stax.fp lday.fp stay.fp ldaz.fp staz.fp ldaxyz.fp staxyz.fp offset|name` access frame slots through the frame pointer (`name` from `.local`); `move.fp dst, src, len` copies between frame slots; `inc.16f`/`dec.16f offset` increment/decrement a frame word. `cc45` also emits `lda.param`, `ldax.param`, `leax.param`, `lda.local`, … (`ld/st` × `a x y z ax ay az axyz`, plus `leax`, with `.param`/`.local`) and `struct_elem`; they resolve to the frame or static-allocation storage of the current function.

### DMA and far memory

`fill dest, len` / `fill.sp` and `move src, dest[, len]` / `move.sp` build an F018 DMA list and trigger it through `$D702/$D701/$D700`. **They are not reliable at present**: the DMA list address is only correct after `ln45` relocation (in a flat binary the list is written at `$0000`), `fill`'s list layout and fill value are wrong, and an immediate (`#n`) length is ignored. `ldw.f`, `stw.f`, `inc.f`, `dec.f` and `branch.16` are recognised but emit placeholder code (an `EOM` byte or a zero-offset branch). Use the DMA controller (see `dma.h`) or explicit code instead.

## Register References

In operands of simulated instructions and `expr`: `.a .x .y .z .sp .pc`, `.ax .ay .az .xy`, `.q`/`.axyz`. `.xz`, `.yz`, `.axy` … are not register tokens.

## Optimizations

The optimiser runs on every pass-2 iteration (see `-O`, `-P` above for which peephole passes run). Always active:

- **Branch sizing**: branches are re-sized (8-bit ↔ 16-bit relative) until addresses converge (at most 100 iterations; otherwise `pass2 failed to converge`).
- **Dead code after returns**: after `rts`, `rtn` or `rti`, instructions are dropped until the next label (directives are kept). A trailing `endproc` then emits nothing.
- **Return shortening**: `rtn #0` is assembled as `rts`.

## Relocatable Objects (`-c`)

With `-c` the output is a `.o45` object (format: [lib45.md](../architecture/lib45.md)): TEXT/DATA/BSS/ZP section bodies, relocations for operands that reference relocatable or external symbols, exported (`.global`, `.weak`) and imported (`.extern`) symbols, function attribute records and `.loc` line information. A `jsr`/`jmp`/`bsr` to a name that is neither defined nor `.extern` is an error.

A C-callable routine (C names get a leading underscore; 16-bit results are returned in A/X):

```assembly
; answer.s45 — unsigned int get_answer(void)
        .global _get_answer
proc _get_answer
        .func_flags zp_call, leaf
        .reg_clobbers A, X
        lda #<1234
        ldx #>1234
endproc
```

```c
/* main.c */
extern unsigned int get_answer(void);
int main(void) { return get_answer() == 1234 ? 0 : 1; }
```

```bash
ca45 -c answer.s45 -o answer.o45
cc45 -c main.c -o main.o45
ln45 -basic -o prog.prg main.o45 answer.o45 -L lib/build -l c45.lib
nm45 -f answer.o45            # function attributes
objdump45 -d -r answer.o45    # disassembly + relocations
```

## Implementation Notes

- `AssemblerLexer` tokenises the preprocessed source; `AssemblerParser::pass1()` builds statements, sizes them and fills the symbol table; `pass2()` repeatedly runs `AssemblerOptimizer`, recomputes addresses and sizes until nothing changes; `AssemblerGenerator` emits the bytes through `M65Emitter`; `O45Emitter` packages `-c` output.
- Simulated instructions live in `AssemblerSimulatedOps.cpp` (one `dispatch_*` function each, also used for sizing); the mnemonic must also be added to the lexer's instruction list in `AssemblerLexer.cpp` and dispatched in `AssemblerParser::pass1()`.
- Native opcodes are in `AssemblerOpcodeDatabase.cpp` (`getOpcodeMap()`, keyed by mnemonic and `AddressingMode`); add the mnemonic to the lexer list as well.
- Directives are handled in `pass1()` (and sized in `calculateDirectiveSize()`) and emitted in `AssemblerGenerator::generate()`.
- `OpEffect.cpp` describes the registers/flags each instruction changes for the optimiser's state tracking.

## FAQ

**When should I use ca45 instead of cc45?** For hand-tuned routines, interrupt code or hardware access. `cc45` also accepts inline assembly (`asm("…")`), and `.o45` objects from both link together.

**What does `lda 2, sp` read?** The byte at frame pointer + 2 (`ldy #2; lda ($FD),y`), not SP + 2. Set up `$FD/$FE` first (the CPU stack is 16-bit by default in `cc45` programs, so `$0100,x` addressing does not reach it). The native `lda ($nn,sp),y` dereferences a pointer stored on the stack.

**How do I get a symbol's byte into data?** `.byte` takes literals only; use `.word sym` (and ignore the high byte) or `lda #<sym` in code.

**How are structs laid out?** `cc45` packs structs; `int` is 2 bytes, so `struct Point { int x; int y; }` has `x` at offset 0 and `y` at offset 2.

**Where is the screen?** In MEGA65 (C65) mode screen RAM starts at `$0800`; in C64 mode at `$0400`.

**How do I see the generated code?** `ca45 -L out.lst …` for a listing, `ca45 -l 2 -o out.s45 in.s45` for expanded assembly, or `objdump45 -d -b '$2001' prog.prg`/`objdump45 -d obj.o45`.
