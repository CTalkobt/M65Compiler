# ca45 — MEGA65 45GS02 Assembler

`ca45` assembles 45GS02 source into a flat binary, a `.prg`, or a relocatable `.o45` object for `ln45`. Besides the native instruction set it offers procedures with named parameters, local labels and scopes, compile-time loops and arrays, and a set of *simulated* instructions (multi-instruction macros such as `add.16` or `mul.32`) that `cc45` also emits.

## Getting Started

### A first program

```assembly
        .basicUpstart start     ; BASIC stub "10 SYS 8205" at $2001
start:
        ldx #0
@loop:  lda message,x
        beq @done               ; zero byte ends the string
        sta $0800,x             ; MEGA65 screen RAM
        inx
        bne @loop
@done:  rts
message: .screencode "HELLO"
        .byte 0
```

```bash
ca45 hello.s45 -o hello.prg
xemu-xmega65 -prgmode 65 -prg hello.prg     # or load it on the MEGA65 and RUN
```

`.basicUpstart` sets the start address to `$2001` (when no `.org` precedes it) and emits a `10 SYS` line (12 bytes for a 4-digit address); because the output name ends in `.prg`, a 2-byte load address is prepended.

### Common patterns

```assembly
        lda #<table             ; low byte of an address
        ldx #>table             ; high byte
        jsr subroutine          ; call / rts returns

        ldx #10
@loop:  dex                     ; @labels are local to the previous plain label
        bne @loop

counter = $20                   ; an equate (assembler constant)
        inc counter             ; base-page access ($20 < $100)
```

### Things that commonly go wrong

- **Labels need a colon** (`main:`), and **all symbols are case-sensitive** (`foo` and `FOO` are different labels). Mnemonics, register names and directive names are case-insensitive.
- **Code after `rts`/`rtn`/`rti` is discarded until the next label** (at every `-O` level). Put a label on code that is reached by other means.
- `.text` is the PETSCII string directive, not a segment switch — use `.code`.
- In a flat binary, a segment without its own `.org` starts at address 0 (see *Segments*).
- `nop` is rejected: `$EA` is the 45GS02 `EOM` prefix.

## Command-Line Usage

```bash
ca45 [options] <input_file>
```

| Option | Meaning |
|--------|---------|
| `-c` | Produce a relocatable `.o45` object (default output `out.o45`) instead of a flat binary. |
| `-ffunction-sections` | With `-c`: write a section table, as `.function_sections` in the source ([Sections](#sections-per-function-linking)). |
| `-o <file>` | Output file (default `out.bin`, or `out.o45` with `-c`). A name ending in `.prg` gets a 2-byte load address taken from the first `.org` (or `$2001` after `.basicUpstart`); without either, no header is written. |
| `-L <file>` | Write a listing: address, up to 4 bytes per line, source line, then the symbol table. |
| `-l <level>` | `1` (default) normal output. `2` writes the *expanded assembly* (simulated instructions expanded, after optimisation) to the `-o` file instead of a binary. |
| `--dry-run` | Assemble and optimise, then print the symbol count, the number of byte-producing statements and the total size; no output file. |
| `--source-map <file>` | Write an address → source-line map plus the symbol table. |
| `--emulator` | After writing a `.prg`, launch the first of `x64`, `x64sc`, `mega65`, `mega65_emu` found on `PATH`. |
| `--emulator-path <path>` | Emulator to launch with `--emulator`. |
| `--watch` | After assembling, poll the input once a second and reassemble when it changes (flat/`.prg` output only). |
| `-O<n>` | Optimisation level, default `-O2`. `-O0` disables every optimiser pass; `-O1`, `-O2` and `-O3` enable the same peephole passes (`-O2`/`-O3` also run the striped-array passes that only match `cc45` output). `-O` alone or an unknown digit means `-O2`. |
| `-P<Name>` / `-PNo<Name>` | Enable/disable one optimiser pass after `-O` (see below). Unknown names are ignored. |
| `--experimental` | Enable experimental optimiser passes (none at present). |
| `-Roptimizer` | Report each optimisation to stderr, e.g. `opt: f.s45:asm:2: [tail-call] JSR sub + RTS → JMP (saved 1 byte)`. |
| `-Rmachstate` | Trace the optimiser's register/flag state tracking. |
| `-I<path>` | Add an include directory (see *Preprocessor*). |
| `-D<name>[=<value>]` | Define a preprocessor macro **and** an assembler symbol (value `$hex`, `%binary` or decimal; default 1). |
| `-Woverflow`, `-Wunderflow` (`--warn-overflow`, `--warn-underflow`) | Also warn about an absolute address or `phw #` value above `$FFFF` (`-Woverflow`) and about a negative immediate or address (`-Wunderflow`, e.g. `lda #-1`). An 8-bit operand above `$FF` (or below −128) always warns. Also settable through `CA45_WARNINGS=overflow,underflow`. |
| `-v` … `-vvvv`, `-v0` | Log to stderr, each line `[ca45:LEVEL] …`: `-v` (INFO) the phases (`Preprocessing…`, `Lexing…`); `-vvvv` (TRACE) also every token. Cumulative (`-v -v` = `-vv`), at most 4; `-v0` off. The toolchain's format (`include/Logger.hpp`); cc45 passes its level on. |
| `-V`, `--version` | Print the version. |
| `-?`, `--help`, `--help=<section>` | Help; sections `input-output` (`io`), `optimization` (`opt`), `debugging` (`debug`), `preprocessor` (`prep`), `diagnostics` (`diag`). |

Predefined symbols: `cc45.zeroPageStart` (default `$02`; base of the `.zp_uses` bit numbering) and `__sp_base` (default `$0101`; page-1 stack base, used by `ptrstack` and `select` when no frame pointer is set up). Override them with `-D`, e.g. `-D__sp_base=$4001`. The scratch base-page byte used by several simulated instructions is `__zp_scratch` if defined, else `$02`.

### Optimiser passes (`-P<Name>` / `-PNo<Name>`)

| Name | Pass |
|------|------|
| `TailCall` | `JSR x` + `RTS` → `JMP x` |
| `JmpBra` | `JMP` → 8-bit `BRA` when the target is local and in range |
| `JSRRelocate` | `JSR` → `BSR` (16-bit relative) for local, non-relocatable targets |
| `NoOpBra` | Remove a `BRA` to the next instruction |
| `BranchInvert` | Conditional branch over a `BRA` → one inverted branch |
| `CmpElimination` | Remove `CMP #0` when the flags already reflect A; also `ORA #0` / `EOR #0` / `AND #$FF` (an `LDX`/`LDY`/`LDZ #imm` between A's load and the test moves before the load) |
| `RedundantLoad` | Remove loads of a value a register already holds (kept when its N/Z flags may be read); a load of a slot another register holds becomes a transfer (`tax` …), moved to right after the store when that register changed since; and an `ldx #imm` whose X and flags are written again before any read on every path (branches and labels followed; calls, returns and simulated instructions count as reads) |
| `StoreLoadPair` | Store/load pairs on base-page addresses |
| `DeadStore` | Remove overwritten `stw.sp` frame stores |
| `TailDedup` | Merge identical code tails (a base-page operand of a proc with a `.zar` block matches only in that proc: it is relocated against the proc's own block) |
| `PreserveXSP` | Keep X = SP across `TSX`-based stack accesses |
| `TSXRedundant` | Remove a `TSX` when X already holds SP |
| `QuadMove` | `sta x` `stx x+1` `sty x+2` `stz x+3` (base page or absolute) → `stq x` (4 bytes instead of 8, 5 instead of 12); the same loads → `ldq x` when nothing reads N or Z before they are set again (`ldq` sets them from all 32 bits) |
| `FCmpOpt` | Float-compare result patterns from `cc45` |
| `SeqExtract` | A run of 4 instructions (8+ bytes) repeated in one `proc` becomes a routine at the end of the proc, called with `BSR` (saves bytes; each use costs a `BSR` and an `RTS`). Only plain instructions move: no labels, branches, stack instructions or simulated instructions, no operand naming an `@` local, a `.var` symbol or `*`. |

`-P` also accepts the `cc45` IR pass names (`StrengthReduction`, `CSE`, `LICM`, …); they have no effect in ca45.

```bash
ca45 -O2 -PNoTailCall prog.s45 -o prog.o45 -c
ca45 -O0 -PRedundantLoad prog.s45
ca45 -Roptimizer prog.s45 2>&1 | grep redundant
```

Independently of `-O`, branches always get the shortest form, `rtn #0` becomes `rts`, and code after a return is dropped (see *Optimizations*).

### Configuration files and environment

Before the command line, ca45 reads arguments from, in this order: `~/.config/m65/ca45.conf`, `.ca45rc` in the current directory, then `CA45_OPTIMIZE=<n>` (→ `-O<n>`) and `CA45_WARNINGS=overflow:underflow` (colon-separated → `-W…`). Later arguments override earlier ones. Files hold one argument per line; blank lines and lines starting with `#` are ignored; each whole line is one argument (no quoting, no trailing comments, so write `-Ipath`, not `-I path`).

> **Known defect**: while any of these sources supplies an argument, options that take a separate value (`-o`, `-L`, `-l`, `--source-map`, `--emulator-path`) read the wrong argument — `ca45 -o out.bin in.s45` can even overwrite `in.s45`. Use these sources only when you pass no such options.

`CC45_INCLUDE` adds colon-separated include directories, searched before `-I` paths.

### Preprocessor

Source first goes through the suite's C preprocessor: `#define` (object- and function-like), `#undef`, `#if`/`#ifdef`/`#ifndef`/`#elif`/`#else`/`#endif`, `#error`, `#warning`, `#pragma once` and line continuation all work; `-D` names are visible to `#ifdef`.

`#include "file"` inserts a file (searched in the including file's directory, then `-I` paths and `CC45_INCLUDE`); diagnostics name that file and give the line within it.

A `#define` is C's: in its replacement `#param` is the argument as a string, so `#define LOAD(v) lda #v` gives `lda "4"` (as with gcc's assembler preprocessing); write `lda #(v)`. Multi-line macros are `.macro` (below). There are no `.include`/`.if`/`.ifdef` directives — such lines are ignored with a warning, like any unknown directive.

## Syntax

- **Comments**: `;`, `//` and `/* … */`.
- **Labels**: `name:` at the start of a statement. A label may share the line with an instruction or directive.
- **Local labels**: `@name:` is scoped under the nearest preceding plain label (stored as `parent:@name`), so `@loop` can be reused in every routine. Inside a `proc`, labels are scoped by the procedure name. Duplicate labels in one scope are an error. `@` labels do not reset the optimiser's register tracking.
- **Scoped names**: `cc45` output uses colon-separated names such as `main:L0`; resolution tries the innermost scope first, then enclosing scopes, then the global name.
- **Anonymous scopes**: `{ … }` opens a local scope (internally `_S<n>`) for labels.
- **Equates**: `NAME = expr` (redefinable; evaluated when encountered). See also `.const`, `.var`.
- **Program counter**: `*` in an operand is the current address when followed by `+`, `-`, `,`, `)`, `]` or the end of the line: `bra *+4`, `lda *-2`. `* = expr` sets the origin like `.org`.
- **Addressing-mode syntax**: `#imm`, `bp`/`abs` (chosen by value; a mnemonic suffix forces one: `lda.abs $12`, `lda.zp lbl`, `lda.abs $12,x`, also `.imm .ind .xind .indy .indz .accum`/`.a`), `addr,x`, `addr,y`, `(bp,x)`, `(bp),y`, `(bp),z`, `[bp],z` (32-bit flat, emits the `EOM` prefix), `(bp,sp),y`, `(abs)`, `(abs,x)`, `bp, target` (BBR/BBS), `A` or nothing (accumulator), `offset, sp` (simulated frame access). Plain `(bp)` is not a 45GS02 mode — write `(bp),z`.

### Literals

| Form | Example |
|------|---------|
| Hex / decimal / binary | `$1234` or `0x1234`, `123`, `%1010` or `0b1010` |
| Negative number | `-1` (unary minus: 32-bit two's complement; `5-1` is a subtraction) |
| Character | `'A'` = PETSCII (letters case-swapped: `'a'`→`$41`, `'A'`→`$C1`), `s'A'` = screen code (`$01`), `p'A'` = PETSCII |
| String | `"text"` with escapes `\n \r \t \a \b \f \v \xHH \ooo \" \\`; prefix `s"…"`/`p"…"` to force screen codes/PETSCII |

### Expressions

Values are 32-bit unsigned. Precedence, high to low:

| Level | Operators |
|-------|-----------|
| 1 | literals, symbols, `( )`, `defined(sym)`, `lo(e)`, `hi(e)`, `bank(e)`, `bit(e, n)`, `bits(e, lo, hi)`, `array[i][j]`, `*` (PC) |
| 2 | `*` `/` (integer division; division by zero is an error) |
| 3 | `+` `-` |
| 4 | `<<` `>>` (logical) |
| 5 | `&` |
| 6 | `^` |
| 7 | `\|` |
| 8 | `==` `!=` `<` `<=` `>` `>=` (1 or 0) |
| 9 | `&&` |
| 10 | `\|\|` |

- **Unary `-`, `~`, `!` bind tightest** (to the next operand: `-2 * 3`, `~0 & $FF` is `(~0) & $FF`). **`<` (low byte) and `>` (high byte) apply to everything that follows**: `<lbl + 1` is `<(lbl + 1)`.
- `lo(e)`, `hi(e)`, `bank(e)` give bits 0–7, 8–15 and 16–23.
- `bit(e, n)` is bit `n` of `e` (0 or 1); `bits(e, lo, hi)` bits `lo` to `hi` shifted down (`bits(%10110100, 4, 7)` is `$B`; `lda #bits(MODE, 4, 5)`). An operand's commas inside `( )` do not end it.
- `*` is the PC also before a comparison (`* <= $2000`); `*<lbl` / `*>lbl` stay a dereference.
- `defined(sym)` is 1 if the symbol exists at that point, else 0.
- There is no `%` (modulo), `**` or `?:` operator, and `$` is not the program counter.

## Directives

An unknown directive is ignored with a warning (`unknown directive '.bogus' is ignored`); the warning suggests the lower-case name for a known directive written in another case (`.BYTE`), `#include` for `.include`, and `.ascii` plus `.byte $00` for `.asciiz`.

### Data

| Directive | Effect |
|-----------|--------|
| `.byte v, …` | One byte per argument: an expression or a character literal (`-1` is `$FF`). |
| `.word v, …` | 16-bit little-endian words; each argument is an expression. A relocatable symbol (`lbl`, `lbl + n`, `lbl - n`) gets a relocation in `-c` mode; a difference of two labels of one segment (`end - start`, `end - start + 1`) is a constant (see *Label expressions* under Relocatable Objects). |
| `.dword v, …` / `.long v, …` | 32-bit little-endian; each argument is an expression. |
| `.float v, …` | 5-byte CBM floating point, rounded to nearest (`.float 1.5` → `81 40 00 00 00`; `-1.0`, `1.0e20`). |
| `.text "s"` | PETSCII string (letters case-swapped: `a`-`z` → `$41`-`$5A`, `A`-`Z` → `$C1`-`$DA`; `\n` → `$0D`). Exactly one string argument. |
| `.ascii "s"` | Raw ASCII (`\n` → `$0A`). |
| `.screencode "s"` | Screen codes (`@`→0, `A`/`a`→1 …). |
| `.res n[, fill]`, `.fill n[, fill]`, `.space n[, fill]` | Reserve `n` bytes of `fill` (default 0); both are expressions. In `.bss` no bytes are emitted. |
| `.align n[, fill]`, `.balign n[, fill]` | Pad to a multiple of `n` (`n` non-zero literal; `fill` an expression). |
| `.fillto addr[, fill]` | Pad up to `addr`; error if already past it. |
| `.incbin "file"`, `.import binary "file"` | Insert a file's bytes (path relative to the current directory). |
| `.array name, elsize, dim0[, dim1 …]` | Reserve a zero-filled row-major array; see *Arrays*. |
| `.basicUpstart addr` | BASIC line `10 SYS addr` (8 bytes plus the address's decimal digits: 12 for `$080D`, 13 for an address of 10000 or more); sets the origin to `$2001` if no `.org` came first. A label defined *after* the stub is assumed to have 4 digits (an error says so if it has 5). |

### Location and segments

| Directive | Effect |
|-----------|--------|
| `.org addr`, `* = addr` | Set the program counter (an expression of symbols defined before it: `* = base + $10`). |
| `.segment name` / `.segment "name"` | Switch segment; `.segment "name" { … }` switches back after the block. Text segments other than `code` (`init`, `far` — cc45's `__far` functions, which ln45 keeps in far memory) are text sub-segments of the `.o45`: references into them are relocated to their place in the object's text, and a call or jump into another segment is never shortened to a relative `BSR`/`BRA`. |
| `.code`, `.data`, `.bss` | Shortcuts for the segments `code`, `data`, `bss`. `.segment "zp"` holds base-page variables: in an object ln45 places them in the program's base page (see Relocatable Objects). |
| `.segmentOrder a, b, …` | Order in which segments are written (default `init, code, data, bss`, then the others in order of appearance, including `default` — the segment used before any switch). |
| `.cpu name` | Accepted and ignored. |

**Flat binaries**: segments are concatenated in segment order and `bss` is never written. A segment whose first statement is not preceded by its own `.org` starts at address **0** (its labels evaluate from 0), so in a flat program either stay in one segment or give every segment an `.org`. Gaps between `.org` addresses are filled with zeros.

**`-c` objects**: `code`, `text`, `init`, `default` and any other name go to the TEXT section, `data` to DATA, `bss` to BSS, `zp` to ZP; `ln45` places them.

### Symbols

| Directive | Effect |
|-----------|--------|
| `.const NAME = expr` | Constant; redefining it (or assigning it with `=`) is an error. |
| `.var NAME = expr`, `.var NAME++`, `.var NAME--` | Assembler variable that can be reassigned; reassignments are tracked by position (`++`/`--` change it by exactly one). |
| `.global a, b` | Export symbols from a `.o45`. |
| `.weak a, b` | Export as weak: a strong (`.global`) definition in another object wins at link time. In `-c` objects every reference to a weak *label*, also from the defining object, is relocated by name, so it reaches the strong definition when one is linked. A weak *absolute* symbol (`.weak x` / `x = value`) is used at its value in the defining object (so a base-page value keeps its base-page addressing); the object records the weak absolute symbols its code used (`OPT_WEAKUSE`), and ln45 refuses a program that defines one of them with another value (a default nothing in the object uses may be overridden freely). For a default that other code overrides, declare the symbol `.extern` where it is used and define the weak default in another object. |
| `.extern a, b` | Import symbols (value 0 until linked; one the file also defines as a label is that definition, as `extern int x; int x;` in C). An `.extern` base-page symbol is assembled as absolute. Only an object (`-c`) is linked: in a flat binary or `.prg`, using an `.extern` symbol that the source does not define is an error. An imported symbol can be used only in a form a relocation holds: `sym`, `sym + n`, `n + sym`, `sym - n`, `<` or `>` of those (as operands, `.word`/`.long` data); anything else (`sym * 3`, `.word sym / 2`), a use where the value is needed while assembling (`.res`, `.fill`, `.align`, `.org`, `x = sym + 1`), and a form the assembler cannot relocate (`#(sym + 2)`, `.byte <sym`) are errors. |
| `.local NAME = offset` | Name a frame offset for the `.fp` instructions. |

### Compile-time loops

`.repeat n` … `.endrepeat` copies its body `n` times (any constant expression; nesting allowed):

```assembly
        .repeat 8               ; 8 × 5 bytes, no loop overhead
            lda (src),y
            sta (dst),y
            iny
        .endrepeat
```

### Assertions

`.assert expr[, "message"]` stops assembly with an error when `expr` is 0: `file: line N: message`, or `assertion failed: expr` without a message. It is checked when the code is generated, so every symbol has its value (also one defined further on), and `*` is the address where the `.assert` is. No bytes.

```assembly
        .assert * <= $2000, "code ran into the buffer"
        .assert end - start < 256, "the table must fit a page"
        .assert bits(MODE, 6, 7) == 2
```

In an object (`-c`) a label is its offset in its segment, so compare differences of labels there (`end - start`); a symbol imported with `.extern` has the value 0 until linked. Test: `src/test-resources/test_ca45_bits.s45`.

### Macros

`.macro NAME [param, …]` … `.endmacro` (or `.endm`) defines a multi-line macro; a line that starts with its name (after an optional `label:`) is replaced by its body, the arguments (split at the commas outside parentheses, brackets and literals) in place of the parameters:

```assembly
        .macro store val, addr
            lda #(val)
            sta addr
        .endmacro
        .macro wait n
@w\@:      dex                     ; \@: a number of its own in each use
            bne @w\@
        .endmacro

        store 5, $d020
        store (2+3)*2, $d021
        ldx #3
        wait 1
        wait 2                  ; another label than wait 1's: no clash
```

- A parameter is replaced where it is a whole word, not inside a string, a character constant or a comment. Missing arguments are empty; too many are an error.
- A body may use other macros and define macros (`.macro` … `.endmacro` inside it is defined when the body is expanded). A macro that goes on using itself stops at 64 levels with an error.
- Expansion runs after the C preprocessor (a body's `#define` names are already replaced) and before assembly; messages about an expanded line give the line of the use.
- `NAME = value` is still an assignment, even when a macro has that name.

### Arrays

`.array name, elsize, d0[, d1 …]` defines label `name`, reserves `elsize × d0 × d1 × …` zero bytes, and defines the constants `name.__elsize`, `name.__dims`, `name.__dimN` and `name.__strideN` (row-major: `stride[i] = product(dims[i+1..]) × elsize`).

```assembly
        .array board, 1, 8, 8           ; stride0 = 8, stride1 = 1
        expr .a, board[2][5]            ; lda board+21
        expr .a, board[.y][.x]          ; index computed at run time
        lda board + 2 * board.__stride0 + 5 * board.__stride1
```

Run-time indices use `ASL` for power-of-two strides and the hardware multiplier otherwise.

### Procedure and object metadata

| Directive | Effect |
|-----------|--------|
| `.func_flags f, …` | Function attribute flags: `zp_call`, `stack_call`, `leaf`, `reentrant`, `static_alloc`, `zeroalloc`, `isr`. |
| `.reg_clobbers A, X, Y, Z` | Registers not preserved. |
| `.flag_clobbers C, N, Z, V` | Flags not preserved. |
| `.zp_uses a, …` / `.zp_clobbers a, …` / `.zp_release a, …` | Base-page bytes read as parameters / overwritten / consumed. Addresses `cc45.zeroPageStart+1` … `+32` (default `$03`–`$22`) are recorded; lower ones are ignored, higher ones are an error. |
| `.frame_size n` | Frame/activation record size (0–65535). |
| `.param_sizes s, …` | Parameter sizes in bytes (1–255). |
| `.param_const fn idx value` | Constant-argument hint for the linker. |
| `.cleanup n` | Add `n` bytes to the procedure's parameter size. |
| `.frameptr_zp $nn` | Base-page address of the frame pointer used by `offset, sp` and `.fp` accesses (default `$FD`). |
| `.sac` | Mark the current procedure as statically allocated (compiler use). |
| `.zpsym name, start, len` | Base-page bytes `start`…`start+len-1` stand for the linker-placed variable `name` (cc45 `__zp` globals; declare it `.extern` too). In `-c` mode every base-page operand in that range, in any procedure, gets an `R_LOWX` relocation against `name` (the offset in the range as its byte), and an operand of an instruction without a base-page mode (`ldz`, `lda abs,y`) an `R_WORD` against it: `name` is the variable's full address in the program's base page, so both reach the same byte. Ignored when assembling a flat binary. |
| `.zar start, len` | The procedure's own base-page bytes `start`…`start+len-1` (cc45 uses `$80`). In `-c` mode every base-page operand in that range — plain, indexed, indirect, `bbs`/`bbr`, and inside simulated instructions — gets an `R_LOWX` relocation against the import `<proc>__zar`, with its offset in the block as the byte; ln45 defines `<proc>__zar` where it places the block (see ln45, base-page blocks). Ignored when assembling a flat binary. |
| `.bptop $nn` | The end of the register pool (`$30`–`$7F`) the object uses, `$30`–`$80`, instead of the one ca45 finds (see below). For code that names the ROM's page 0 while the base page is switched there (the library's float code reads the ROM's FAC at `$63`–`$71` that way). |
| `.bpindex n` | The indexed base-page operands that follow (`$nn,x`, `$nn,y`, `($nn,x)`) reach at most `n` bytes from theirs (0, the default: any byte above it), until the next `.bpindex`. cc45 says 5 around its float copies. |
| `.loc "file", line` | Attribute following code to a source line (listings, `-Roptimizer`, debug info). |
| `.dbg_var "kind scope name type location"` | A C variable for a debugger (cc45 writes them after each `endproc`, and the module's after its data): an `OPT_DEBUG_VARS` entry in `-c` mode. A `sym:NAME[+n]` location is resolved to the object's segment and offset (`seg:bss+12`), an import (`imp:NAME+n`), an equate's value (`abs:$XXXX`) or `none` when the symbol is not defined (a local optimised away). No bytes. See lib45.md 1.12. |
| `.dbg_type "struct NAME SIZE member@offset:type ..."` | A struct / union layout for the debug types (`OPT_DEBUG_TYPES`; a long one goes on in further entries). No bytes. |
| `.noopt_start`, `.noopt_end` | The statements between them are left as written by every optimization pass (cc45's `#pragma cc45 optimize(off)`). |
| `.vtable_entry …` | Compiler marker. |

All of these except `.frameptr_zp`, `.sac`, `.bptop`, `.bpindex`, `.loc`, `.noopt_start`, `.noopt_end` and `.vtable_entry` must be inside `proc`/`endproc`. In `-c` mode the attributes are written as a function attribute record for the procedure's symbol (`nm45 -f` shows them; `ln45` uses them for calling-convention checks and clobber-aware optimisation). The record attaches only to a **named** procedure, `proc <name>` together with `.global <name>`; in a bare `proc` the assembler warns `.func_flags in an unnamed 'proc' is ignored: name the function with 'proc <name>' (and .global <name>)`. Objects without attributes are treated conservatively (clobber everything).

```assembly
        .global _add_words
proc _add_words
        .func_flags zp_call, leaf
        .zp_uses $03, $04, $05, $06
        .zp_clobbers $03, $04
        .reg_clobbers A, X
        .flag_clobbers C, N, Z, V
        lda $03
        clc
        adc $05
        sta $03
        lda $04
        adc $06
        tax
        lda $03
endproc
```

`nm45 -f` then prints `_add_words  [zp_call leaf uses:03-06 clobbers:03-04 releases:- regs:AX flags:CNZV]`.

**The register pool an object uses.** In `-c` mode every object exports the weak absolute symbol `cc45.bptop`: the end of the register pool (`$30`–`$7F`) its instructions name directly (a Q instruction and a `[$nn],z` pointer reach 4 bytes, `($nn),y`/`($nn),z` pointers and `inw`/`dew`/`asw`/`row` 2; `$30` when it names none). ln45 places the functions' base-page blocks above the largest. An indexed operand counts as reaching every byte above it, and one below `$30` (`lda $10,x`) too, unless `.bpindex` says how far it reaches; an address the code computes and indexes from is not seen: hand-written asm that reaches the pool that way must say `.bptop`.

### Sections (per-function linking)

With `.function_sections` in the source (or `ca45 -c -ffunction-sections`), the `.o45` object gets a section table ([lib45 1.10](../architecture/lib45.md#110-sections-opt_sections-opt_sectref)): ln45 can keep or drop each section as a whole. Without it the object is byte-for-byte what it was.

| Directive | Effect |
|-----------|--------|
| `.function_sections` | Write a section table: one section per `proc` … `endproc` in a text segment, plus `.split` sections. |
| `.overlay name` | The object's code is in the code overlay `name`: exports `cc45.overlay.name` (ln45 [Code Overlays](ln45.md#code-overlays)). |
| `.split ["name"]` | Start a section in the current segment (text, data, BSS); it ends at the next `.split`/`.nosplit` of that segment or at the segment end. |
| `.nosplit` | End the open section; what follows is residual (kept whenever anything of the object is). |
| `.keep` | Always keep the current section (a root for ln45). |
| `.ref name, …` | The current section needs `name` (an import; no bytes, no relocation): ln45 links its definition only while the section is kept. Without sections it is an `.extern`. cc45 uses it for the printf digit hooks. |

An `.align N` right before a `proc` or a `.split` becomes the section's alignment. With sections the optimiser's tail deduplication (a function ending in a branch into another's identical ending) is off: it would tie the two functions together. Sections tied together without a relocation are merged: a relative branch (`beq`, `bra`, `bbr`…, also `*+n`) from one into another, code falling through from one into the next (its last instruction is not `rts`/`rti`/`jmp`/`bra`/`rtn`/`endproc`), and a label difference (`.word a - b`). A section tied that way to bytes outside any section, or to a section of another segment, becomes residual. An internal relocation whose stored value lies in another section than its symbol's (`_t1+3` one past the end of `_t1`'s section) gets a section reference. `nm45 -S` / `objdump45 -h` show the table.

## Procedures

```assembly
proc name[, [B#|W#|D#|F#]param, …]
        …
endproc
```

- `proc` emits no code; it defines the label `name`, opens a scope and defines each parameter as a frame offset. The size prefix is upper-case: `B#` byte, `W#` word (default), `D#` dword, `F#` 5-byte float. Byte parameters still occupy a 2-byte slot. The first parameter is at offset 2, the next follows it; `ARG1`, `ARG2`, … are aliases.
- Parameters are used with the frame-relative forms, e.g. `lda count, sp` or `ldax ptr, sp`.
- `endproc` emits `rts` (1 byte) unless the previous instruction already returned; the caller removes arguments. Use `rtn #n` to return and drop `n` bytes.
- Nested `proc`, `endproc` without `proc`, and a `proc` left open at end of file are errors.

`call name, arg, …` pushes the arguments last to first, each as a little-endian word, so the first lands at the callee's offset 2, then `jsr name`. `#expr`/`W#expr` push the value, `B#expr` its low byte (in a word slot, as `proc` lays byte parameters out), and a plain address pushes the word stored there. Constants are pushed with `phw` (bytes swapped: the 45GS02's `phw` leaves the high byte at the lower address); addresses of relocatable symbols and memory words go through A, so **A is changed**. The callee sets up its frame pointer (`$FD/$FE` = SP + 1 at entry) before using `name, sp`; the caller drops the arguments (`pla` × 2 per argument, or `rtn #n` in the callee).

## Supported Instructions

The native 45GS02 instruction set, encodings and the auto-selection between base-page and absolute modes are listed in the [45GS02 Instruction Reference](../architecture/opcodes.md). Highlights:

- Z register (`ldz`, `stz` (stores Z), `inz`, `dez`, `phz`, `plz`, `taz`, `tza`, `cpz`), base page (`tab`, `tba`), 16-bit stack pointer (`tsy`, `tys`), `map`, `eom`, `cle`/`see`, `neg`, `asr`, word operations (`inw`, `dew`, `asw`, `row`, `phw`), `bsr`, `rtn #n`, bit operations (`smbN`, `rmbN`, `bbsN`, `bbrN`).
- 16-bit relative branches: every conditional branch and `bra` is assembled in its 8-bit form when the target is in range and its 16-bit form otherwise; `bsr` is always 16-bit.
- Quad (32-bit) instructions `ldq`, `stq`, `adcq`, `sbcq`, `andq`, `oraq`, `eorq`, `cmpq`, `aslq`, `lsrq`, `rolq`, `rorq`, `incq`, `decq`, `negq` (emitted with the `$42 $42` prefix). `inq` and `deq`, the 45GS02's names, are `incq` and `decq` (`inq` alone: Q itself; `inq $30`, `inq label`: in memory).
- `lda ($nn,sp),y` / `sta ($nn,sp),y` (`$E2`/`$82`) are the native stack-relative *indirect* modes.
- `[bp],z` flat 32-bit indirect for `adc and cmp eor lda ora sbc sta ldq stq` and the Q arithmetic (adds `EOM`).
- `nop` is rejected (`nop disallowed`); write `eom` for an `$EA` byte, or `clv` as a one-byte no-op.

**Base page or absolute.** An operand that fits in a byte uses the base-page form, which the base page register (B) relocates: under cc45's relocated base page `sta $D0` writes `__zp_page + $D0`. An address written with its leading zeros (`$00D0`, 3 or more hex digits, the operand alone or indexed) is absolute, as in ACME: `sta $00D0` writes memory `$00D0` (cc45 writes a C pointer to a constant address this way). A symbol in `(sym,x)` or `(sym)` takes the base-page form unless the instruction has the absolute one (`jmp`, `jsr`).

**Base-page warning.** An instruction with a base-page operand (< `$100`) but no base-page form is assembled absolute (`$00xx`), which ignores the relocated base page (B register). ca45 warns, e.g.

```
f.s45:2:5: warning: 'ldz $20' has no base-page mode: assembled as absolute $0020, which ignores the base page register
```

Affected: `ldz $nn` / `ldz $nn,x` (use `ldq`, or `lda` + `taz`), `lda/sta/… $nn,y` except `ldx`/`stx` (use `,x` or `(bp),y`), `phw $nn`. `jmp ($nn)` and `jsr ($nn)` are always absolute indirect, without a warning.

## Simulated Instructions

These expand to native code at assembly time. Register sets: `.a .x .y .z`, `.ax .ay .az .xy` (first letter = low byte), `.q`/`.axyz` (A = byte 0 … Z = byte 3). Unless stated otherwise a memory operand must be a **label** or plain address, `#` marks an immediate, and flags are those left by the last generated instruction.

Several instructions use base-page scratch bytes starting at `__zp_scratch`/`$02` (`cmp.s16`, `cmp.32`, `bfext16`, `bfins*`, `bfext32`, the `.ax` frame loads/stores). The `offset, sp` and `.fp`/`.param`/`.local` forms access the frame through the frame pointer at `$FD/$FE` (or `.frameptr_zp`): `ldy #offset; lda ($FD),y`, so **Y is clobbered** and the frame pointer must have been set up (as `cc45`-generated functions do). Offsets above 255 go through `$FB/$FC`.

### Hardware multiply and divide

`mul.<w> dest, src` and `div.<w> dest, src` (unsigned; `w` = 8, 16, 24 or 32 bits; plain `mul`/`div` = 8) use the math unit (`$D770` inputs A, `$D774` inputs B, product at `$D778`, quotient at `$D76C`; `div` waits for `$D70F` bit 7). `dest` is `.a`, `.ax`, `.q`/`.axyz` (the register set fixes which registers are used; the result is the low `w` bits) or a label/address; `src` is `#imm`, one of those register sets, or a label/address — `$04` without `#` is a memory read. `div` by an immediate 0 is an error. 24-bit register sets (`.axy`) are not supported; use memory. At 32 bits the operands and the result move with `stq`/`ldq` (a memory destination with a register second operand: byte by byte).

| Instruction | Operands | Notes |
|-------------|----------|-------|
| `mul.s16`, `div.s16` | `.ax, #imm\|label` | Signed (absolute values, then sign fix-up); Y is clobbered. Division truncates toward zero. |
| `mod.16`, `mod.s16` | `.ax, #imm\|label` | Remainder = dividend − quotient × divisor (`mod.s16`: the dividend's sign). |
| `mul.s32`, `div.s32`, `mod.32`, `mod.s32` | `.q, #imm\|label` | 32-bit variants. |

```assembly
        ldax #300
        mul.16 .ax, #3          ; AX = 900
        ldax #1000
        div.16 .ax, #8          ; AX = 125
        ldax #-300
        mul.s16 .ax, #3         ; AX = -900
```

### Bit fields

| Instruction | Operands | Effect |
|-------------|----------|--------|
| `bfext #off, #w` | value in A | A = bits `off…off+w-1` of A (right-aligned), X = 0 |
| `bfext16 #off, #w` | value in AX | AX = extracted field |
| `bfext32 #off, #w` | value in Q | Q = extracted field |
| `bfins addr, #off, #w` | new value in A | Read-modify-write of the byte at `addr` (`TRB`/`TSB`); A = the updated byte |
| `bfins.sp offset, #off, #w` | A | Same on a frame byte (Y clobbered) |
| `bfins.ind bp, #off, #w` | A | Same through the pointer at `bp` (Y clobbered) |
| `bfins16`, `bfins16.sp`, `bfins16.ind` | AX | 16-bit storage unit; AX = updated word |
| `bfins32`, `bfins32.sp`, `bfins32.ind` | Q | 32-bit storage unit |

`lda #3` / `bfins $4000, #0, #2` stores 3 into bits 0–1 of `$4000`.

### Expressions in code

`expr target, expression` evaluates an expression into a register (`.a .x .y .z`, `.ax .ay .az`, `.axy .axz`, `.q`/`.axyz`) or a label (stored as a word). A constant becomes immediate loads into the target's registers in order (`.ay`: `lda #lo` / `ldy #hi`; `.q`: A X Y Z); array indexing with run-time indices is supported (see *Arrays*). `P.C`, `P.Z`, `P.N`, `P.V`, `P.I`, `P.D` are processor flags: 1 when set, else 0 (`expr .a, P.Z`).

### Frame and parameter access (compiler use)

`lda.fp sta.fp ldax.fp stax.fp lday.fp stay.fp ldaz.fp staz.fp ldaxyz.fp staxyz.fp offset|name` access frame slots through the frame pointer (`name` from `.local`); `move.fp dst, src, len` copies between frame slots; `inc.16f`/`dec.16f offset` increment/decrement a frame word. `cc45` also emits `lda.param`, `ldax.param`, `leax.param`, `lda.local`, … (`ld/st` × `a x y z ax ay az axyz`, plus `leax`, with `.param`/`.local`) and `struct_elem`; they resolve to the frame or static-allocation storage of the current function.

### DMA and far memory

`fill dest, len[, value]` and `move src, dest[, len]` (and `fill.sp`, `move.sp`) run one F018B DMA job: the 12-byte list is built on the stack, the controller is pointed at it (`$D702`, `$D701`, then `$D700`, which starts the job, with interrupts held off by `php`/`sei` … `plp`: an interrupt handler's own DMA job in between would leave its list address) and the list is dropped again. **A, X and Y are changed**; register operands are saved to `__zp_scratch`..`+3` first.

- An **address** is an expression up to `$FFFFFFF` (bits 16–19 are the bank; above 1MB the job is sent as an *enhanced* job with megabyte option bytes, started through `$D705`), a register pair `.ax .ay .az .xy .xz .yz` (a bank-0 address), `.axy .axz .ayz .axyz`/`.q` (a 28-bit address), `(bp)` (the address stored at `bp`), or `n, sp` (frame slot `n`). In `fill.sp`/`move.sp` the `#` operand (else the destination) is a frame offset.
- The **length** (up to 65535; 0 means 65536) is an expression (`#n` or `n`) or a register pair; `move` without one uses `.xy`.
- The **fill value** is an expression or `.a .x .y .z`; without one, `fill` uses A.

```assembly
        fill $0800, 1000, $20          ; clear the screen
        move $3000, $FF80000, 80       ; copy into colour RAM (28-bit)
```

`ldw.f`, `stw.f`, `inc.f`, `dec.f` access 28-bit memory through `[bp],z`: the operand is `[bp]` (the 32-bit pointer at `bp`..`bp+3`) or a flat address (put in the scratch pointer `__zp_scratch`..`+3`). `ldw.f` loads AX, `stw.f` stores AX (A and X kept), `inc.f`/`dec.f` change the byte at the address (A = the new value); Z is changed.

`branch.16 [<cond>,] target` (`beq bne bcc bcs bpl bmi bvc bvs bra`; without a condition `bra`) always emits the 3-byte 16-bit relative branch; ordinary branches already switch to that form when the target is out of 8-bit range.

## Register References

In operands of simulated instructions and `expr`: `.a .x .y .z .sp .pc`, `.ax .ay .az .xy`, `.q`/`.axyz`. `.xz`, `.yz`, `.axy` … are not register tokens.

## Optimizations

The optimiser runs on every pass-2 iteration (see `-O`, `-P` above for which peephole passes run). Always active:

- **Branch sizing**: branches are re-sized (8-bit ↔ 16-bit relative) until addresses converge (at most 100 iterations; otherwise `pass2 failed to converge`).
- **Dead code after returns**: after `rts`, `rtn` or `rti`, instructions are dropped until the next label (directives are kept). A trailing `endproc` then emits nothing.
- **Return shortening**: `rtn #0` is assembled as `rts`.

## Relocatable Objects (`-c`)

With `-c` the output is a `.o45` object (format: [lib45.md](../architecture/lib45.md)): TEXT/DATA/BSS/ZP section bodies, relocations for operands that reference relocatable or external symbols, exported (`.global`, `.weak`) and imported (`.extern`) symbols, function attribute records and `.loc` line information. A `jsr`/`jmp`/`bsr` to a name that is neither defined nor `.extern` is an error.

**Label expressions.** An operand or data value naming several labels is relocated by what its value holds: each label's segment is moved and the expression evaluated again. A difference of two labels of one segment (`#<(blk_end - blk)`, `.byte >(end - start)`, `.word end - start + 1`) is a constant, with no relocation; a label plus such a difference (`lda blk + (blk_end - blk) - 1`) is relocated once against the label's segment; anything else (`2 * lbl`, `lbl >> 1`, labels of two segments) is an error (#336).

**The `zp` segment.** Labels in `.segment "zp"` are base-page variables. Their operands keep the base-page form in every base-page mode (`sta ptr`, `ptr,x`, `(ptr),y`, `(ptr,x)`, `[ptr],z`, `bbr`), with an `R_LOWX` relocation against the segment, so the byte is the variable's place in the program's base page; an instruction without a base-page form (`ldz ptr`, `lda ptr,y`) is absolute with an `R_WORD`, the variable's full address in the base page (`__zp_page` + its place): both reach the same byte. ln45 places the objects' `zp` segments in the program's base page below the `__zp` variables (#335; see ln45). Code an `__interrupt` handler reaches must not use them in base-page form: the handler runs on its own base page. In a flat binary the segment starts at 0 unless it has an `.org`.

An address in any other relocatable segment is always assembled absolute (two bytes, also when its offset in the segment is below `$100`), including the operand of a 32-bit instruction (`ldq`/`stq`/`adcq` … `label`: the relocation is on the operand after the `$42 $42` prefix). Simulated instructions relocate a memory operand that is such a label in `add.16`/`sub.16`, `and.16`/`ora.16`/`eor.16`, `cmp.16`, `cmp.s16`, the 32-bit `add`/`sub`/bitwise/`cmp` forms, `mul`/`div` (also signed and `mod`) and `bfins`; any other simulated instruction given one is an error (`'neg.16' can't relocate '_w' (an address in a relocatable segment)`) rather than an object with the address left out.

A C-callable routine (C names get a leading underscore; 16-bit results are returned in A/X):

```assembly
; answer.s45 — unsigned int get_answer(void)
        .global _get_answer
proc _get_answer
        .func_flags zp_call, leaf
        .reg_clobbers A, X
        lda #<1234
        ldx #>1234
endproc
```

```c
/* main.c */
extern unsigned int get_answer(void);
int main(void) { return get_answer() == 1234 ? 0 : 1; }
```

```bash
ca45 -c answer.s45 -o answer.o45
cc45 -c main.c -o main.o45
ln45 -basic -o prog.prg main.o45 answer.o45 -L lib/build -l c45.lib
nm45 -f answer.o45            # function attributes
objdump45 -d -r answer.o45    # disassembly + relocations
```

## Implementation Notes

- `AssemblerLexer` tokenises the preprocessed source; `AssemblerParser::pass1()` builds statements, sizes them and fills the symbol table; `pass2()` repeatedly runs `AssemblerOptimizer`, recomputes addresses and sizes until nothing changes; `AssemblerGenerator` emits the bytes through `M65Emitter`; `O45Emitter` packages `-c` output.
- Simulated instructions live in `AssemblerSimulatedOps.cpp` (one `dispatch_*` function each, also used for sizing); the mnemonic must also be added to the lexer's instruction list in `AssemblerLexer.cpp` and dispatched in `AssemblerParser::pass1()`.
- Native opcodes are in `AssemblerOpcodeDatabase.cpp` (`getOpcodeMap()`, keyed by mnemonic and `AddressingMode`); add the mnemonic to the lexer list as well.
- Directives are handled in `pass1()` (and sized in `calculateDirectiveSize()`) and emitted in `AssemblerGenerator::generate()`.
- `OpEffect.cpp` describes the registers/flags each instruction changes for the optimiser's state tracking.

## FAQ

**When should I use ca45 instead of cc45?** For hand-tuned routines, interrupt code or hardware access. `cc45` also accepts inline assembly (`asm("…")`), and `.o45` objects from both link together.

**What does `lda 2, sp` read?** The byte at frame pointer + 2 (`ldy #2; lda ($FD),y`), not SP + 2. Set up `$FD/$FE` first (the CPU stack is 16-bit by default in `cc45` programs, so `$0100,x` addressing does not reach it). The native `lda ($nn,sp),y` dereferences a pointer stored on the stack.

**How do I get a symbol's byte into data?** `.byte` takes literals only; use `.word sym` (and ignore the high byte) or `lda #<sym` in code.

**How are structs laid out?** `cc45` packs structs; `int` is 2 bytes, so `struct Point { int x; int y; }` has `x` at offset 0 and `y` at offset 2.

**Where is the screen?** In MEGA65 (C65) mode screen RAM starts at `$0800`; in C64 mode at `$0400`.

**How do I see the generated code?** `ca45 -L out.lst …` for a listing, `ca45 -l 2 -o out.s45 in.s45` for expanded assembly, or `objdump45 -d -b '$2001' prog.prg`/`objdump45 -d obj.o45`.
