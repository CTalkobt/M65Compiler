# cp45 — Mega65 C Preprocessor

The C preprocessor is the first pass of `cc45`. `cp45` is the same program (`bin/cp45` is a link to `cc45`) started under another name: it stops after preprocessing. `ca45` uses the same preprocessor for assembly sources, without the compiler-only features marked below.

## Usage

```bash
cp45 [options] input.c -o output.i
cc45 -E [options] input.c -o output.i
```

The output is written to the `-o` file. Without `-o` it goes to `<input>.prg` (e.g. `input.c` → `input.prg`); there is no output to stdout.

Options are those of `cc45` (see [cc45](cc45.md)); the ones that matter here:

| Option | Description |
|--------|-------------|
| `-o <file>` | Output file. |
| `-I<path>`, `-I <path>` | Add an include directory. |
| `-D<name>[=<val>]` | Define a macro (`-DNAME` defines it as `1`). |
| `-fno-staticalloc` | Do not predefine `__CC45_STATIC_ALLOC__`. |
| `-v` | Verbose. |

Options are also read from `~/.config/m65/cp45.conf`. `CC45_INCLUDE` adds include directories.

The output keeps the source's line count (removed lines become blank lines) and contains `#line` markers around included files.

## Supported Directives

### `#include`
`#include "file"`, `#include <file>` and `#include MACRO` (the operand is macro-expanded first). Both forms search, in order:
1. the directory of the including file;
2. the `CC45_INCLUDE` directories;
3. the standard headers: `bin/../lib/include` (the build tree) or, if that has no `stdio.h`, `bin/../include/cc45` (an installed tree: `make install` puts them in `PREFIX/include/cc45`);
4. the `-I` directories.

Includes nest up to 16 levels; deeper nesting is an error ("Maximum include depth exceeded").

In the compiler, a unit that uses `long long`, `int64_t`, `__int64`, `__int128`, `__int(N)` or `__uint(N)` gets `#include <intwide.h>` added automatically.

### `#embed` and `#include binary`
A file's bytes as a list of integer constants, for an initializer:

```c
const unsigned char font[] = {
#embed "font.bin"                 // C23: 0x3c, 0x66, 0x6e, ...
};
const unsigned int table[] = {
#include binary word "table.bin" // 16-bit values, little-endian: 0x0201, 0x0403, ...
};
const unsigned long big[] = {
#include binary long "big.bin"   // 32-bit values, little-endian
};
```

- `#include binary [char|word|long] "file"` (or `<file>`): `char` (the default) gives a value a byte, `word` one for each 2 bytes, `long` for each 4. A file that is not a whole number of words or longs warns and the last value is padded with zero bytes.
- `#embed "file"` (C23 6.10.4) gives bytes and takes the standard parameters: `limit(N)` (at most N bytes), `prefix(tokens)` / `suffix(tokens)` (put before / after the list when the file is not empty) and `if_empty(tokens)` (in place of the list when it is); and `cc45::offset(N)` (also `clang::offset`, `gnu::offset`) to skip N bytes first — `#embed "pic.prg" cc45::offset(2)` leaves out a PRG's load address. `__name__` spellings (`__limit__`) work too; an unknown parameter is an error. `limit` and `offset` take constant expressions with macros (`limit(SIZE)`); the operand may be a macro (`#embed DATA_FILE`).
- The file is found as `#include` finds one (the including file's directory first).
- The bytes are the file's own: a text file embedded with `suffix(, 0)` is a string of its bytes (ASCII, not cc45's PETSCII literals: compare it with an `a"..."` literal).
- `__has_embed("file" params)` in `#if`: `__STDC_EMBED_NOT_FOUND__` (0: no such file, or a parameter not supported), `__STDC_EMBED_FOUND__` (1) or `__STDC_EMBED_EMPTY__` (2: nothing left after `limit`/`offset`).
- The list goes over several lines (16 bytes a line); the lines after it keep their numbers. Test: `src/test-resources/test_embed_xemu.c`.

### `#define` / `#undef`
- Object-like and function-like macros.
- **Variadic macros**: `NAME(params, ...)` with `__VA_ARGS__`, and the GNU named form `NAME(args...)`.
- **Comma removal**: `, ##__VA_ARGS__` drops the comma when no variable arguments are given.
- `#` stringification and `##` token pasting.
- **Expansion** as C11 6.10.3 has it: an argument is fully macro-expanded before it is substituted, except as an operand of `#` or `##` (`#define XSTR(x) STR(x)`, `XSTR(N)` with `#define N 4` is `"4"`; `XCAT(v,N)` is `v4`); a replacement is rescanned with the rest of the line (a function-like macro's name at its end takes a `(` that follows); a macro is not expanded again inside its own expansion (`#define SELF SELF + 1` gives `SELF + 1`), also through others (`#define AA BB` / `#define BB AA`); an empty argument next to `##` is a placemarker (`CAT(, y)` is `y`). Output keeps the source's spacing, with a space where two tokens of a replacement would run together (`-MINUS` with `#define MINUS -` is `- -`). `__LINE__` and `__FILE__` are expanded where a macro uses them (`XSTR(__LINE__)`). Test: `src/test-resources/test_pp_expand.c`, gcc's result in `test_pp_expand.expected`.
- **Redefinition**: a `#define` of a macro already defined differently warns (C11 6.10.3p2: the same kind, the same parameter names, and the same replacement list but for the amount of white space are the same definition), naming the previous definition: `file:line: warning: macro 'X' redefined differently` and `file:line: note: the previous definition of 'X'` (or that it was defined on the command line, `-D`, or is predefined). An identical redefinition is silent. The new definition is used.

### Conditionals
`#if`, `#ifdef`, `#ifndef`, `#elif`, `#else`, `#endif`, with `defined(NAME)` / `defined NAME` and these operators in `#if`:
- `__has_include(<file>)` / `__has_include("file")`
- `__has_embed("file" params)` — see [`#embed`](#embed-and-include-binary)
- `__has_builtin(name)` — 1 for a fixed list of `__builtin_*` names (the va builtins, `constant_p`, `offsetof`, `expect`, `trap`, `choose_expr`, `unreachable`, `conjf`, the common string/memory/stdio/malloc aliases, `abs`, `labs`, `exit`, `abort`, `alloca`, `clz`, `ctz`, `ffs`, `popcount`, `bswap16`)
- `__has_attribute(name)` — 1 for `always_inline`, `noinline`, `unused`, `used`, `weak`, `pure`, `const`, `cold`, `hot`, `packed`, `aligned`, `deprecated`, `naked`, `interrupt`, `noreturn`, `section`, `visibility`, `constructor`, `destructor`, `format`, `warn_unused_result`. This does not mean the attribute has an effect: cc45 ignores most of them (and warns about `naked`, `interrupt` and `noreturn`); see [cc45 Attributes](cc45.md#attributes).

### `#error`, `#warning`, `#line`
`#error` stops with an error; `#warning text` prints `Warning: text at file:line` (the directive's own line). `#line N "file"` changes `__LINE__`/`__FILE__`.

### `#pragma`
- `#pragma once` — include the file only once.
- `#pragma push_macro("NAME")` / `#pragma pop_macro("NAME")`.
- Compiler only: `#pragma weak`, `#pragma no_zp_save`, `#pragma encoding …` and `#pragma cc45 …` are turned into `__asm__(".directive");` statements for the compiler (see [cc45 Pragmas](cc45.md#pragmas)). Other pragmas are removed.

Pragmas are processed even inside a false `#if`/`#ifdef` block.

### `_Pragma("string")`
The `#pragma` its string holds (`\"` and `\\` undone; C11 6.10.9), every one a `#pragma` line takes; its output goes first on the line it appears on (line numbers stay). Also when a macro makes it: `#define DO_PRAGMA(x) _Pragma(#x)` and `DO_PRAGMA(cc45 signed_default)`.

## Compiler Pass-through (`#!`)

In the compiler (not in `ca45`), a line starting with `#!` is not processed: in an active region it becomes `__asm__("#directive");`, so the directive reaches the generated assembly and `ca45`'s preprocessor evaluates it. Since it is an `asm` statement, use it inside a function body, around code that is emitted in order — at file scope it is dropped, and two alternative function definitions would both be compiled.

```c
int main(void) {
#!ifdef USE_FAST
    asm("lda #1");
#!else
    asm("lda #2");
#!endif
    asm("ldx #0");
    return __cpu.AX;          // 2 unless USE_FAST is defined for ca45
}
```

Generated assembly:

```asm
    #ifdef USE_FAST
    lda #1
    #else
    lda #2
    #endif
    ldx #0
```
