# cl45 — MEGA65 C linter

`cl45` checks C source for MEGA65- and cc45-specific mistakes and reports
them by rule (#199). It is the same program as `cc45` (`bin/cl45` is a link
to `cc45`) started under another name: it preprocesses, parses and lowers
the file exactly as cc45 compiles it (the same `-I`, `-D`, `-f...` and
`-O<n>`), runs the code generator, and writes no file. The rules are the
ones that need what the compiler knows: types, which addresses are I/O, the
call graph of the file, stack frames. The design is in
`doc/architecture/lint.md`; the assembly linter is `al45`.

## Usage

```bash
cl45 [options] file.c
cl45 -O2 -Iinclude -DNDEBUG file.c          # as the file is compiled
cl45 --format=sarif file.c > out.sarif
cl45 --list-rules
cl45 --explain=mega65-sac-interrupt
make lint-lib                               # the standard library: its C (cl45) and assembly (al45)
```

| Option | Description |
|--------|-------------|
| `-I<path>`, `-D<name>[=<val>]`, `-O<n>`, `-f...` | As for cc45. Lint a file with the options it is compiled with: the calling convention, `-fsigned-default`, `-fno-staticalloc` and the `-O` level (what is inlined) change what the rules see. |
| `--checks=LIST` | Rule globs, applied in order: `mega65-*`, `-mega65-implicit-narrowing`. |
| `--disable=ID[,ID]` | Turn rules off (as `--checks=-ID`). |
| `--severity=ID=LEVEL` | A rule's level: `off`, `info`, `warning`, `error`. |
| `--profile=cc45` / `standalone` | The profile: `cc45` (the default: a program linked with crt0 and c45.lib) or `standalone`. |
| `--config=FILE` | Read this configuration instead of the default files. |
| `--format=text` / `json` / `sarif` | Output format (default text). |
| `--list-rules` | The rules, their level in force and their profile. |
| `--explain=ID` | A rule's description. |
| `-v` … `-vvvv` | Diagnostics of cl45 itself on stderr; the findings do not change. |

Findings go to stdout. Text lines are
`file:line:col: warning: message [mega65-rule-id]`. JSON is an array of
`{file, line, column, severity, rule, message}`; SARIF is version 2.1.0.
The exit status is 1 when a finding has the level `error`, cc45's own
status when the file does not compile, else 0.

cc45's own warnings (an unused variable, an implicit declaration…) still go
to stderr. The warnings cc45 gives that a rule covers (the plain-integer
ones, the parameter notes, the recursion warning) are reported as that
rule's findings instead, so they can be configured and suppressed like the
others; cc45 itself prints them as before.

Findings in the system headers (`lib/include`, or an installed
`include/cc45`) are not reported; those in the project's own headers are,
at the header's line. A macro's finding is reported where it is used.

## Rules

| Rule | Default | Profile | What |
|---|---|---|---|
| `mega65-dma-trigger-order` | warning | all | `$D701`/`$D702`/`$D704` (the DMA list address) written after `$D700`/`$D705` (the trigger) in the same block, with no later trigger (which would make them the next job's). Addresses through casts, register structs and pointer variables set in the block. |
| `mega65-io-not-volatile` | warning | all | I/O (`$D000`-`$DFFF`) reached through a pointer that is not to a `volatile` type: `*(char *)0xD020`, `((struct regs *)0xD400)->x`, `char *p = (char *)0xD020`, `p = (char *)0xD020`; a variable placed in I/O (`__section` of a `#pragma section` at an I/O address) that is not `volatile`. |
| `mega65-io-personality` | info | standalone | A VIC-III/IV register (`$D030`-`$D07F`) written in a file that never writes the knock to `$D02F` (crt0 does it for linked programs). |
| `mega65-isr-rom-call` | warning | cc45 | An `__interrupt` handler, or a function of the file it calls, calls the ROM: `putchar`/`printf`/the stdio file functions, the `<cbm.h>` functions (`cbm_*`), `__rom_call`, inline assembly with `jsr $E000`+. The library keeps its own state across a handler; the ROM's routines are not reentrant, so this is safe only when the program is never inside the ROM when the interrupt arrives. |
| `mega65-sac-interrupt` | warning | cc45 | A static-allocation function reachable from an `__interrupt` handler of the same file. ln45 refuses the program at link time; this says so at the function. |
| `mega65-recursion-frame` | info | all | A function on a call cycle within the file (it gets a stack frame instead of static allocation). `#pragma cc45 recurse` before it says it is meant. |
| `mega65-stack-frame-limit` | warning | all | A stack frame larger than the option `mega65-stack-frame-limit` (default 256 bytes). Functions with static allocation have no frame. |
| `mega65-narrow-param` | info | all | A static function's `int` parameter that every call gives a constant of 0-255 (it could be `unsigned char`), or, when declared signed, only non-negative values. |
| `mega65-wide-arith` | info | all | `long` `+ - * & \| ^` whose operands were widened from `int`/`char` (or are small constants) and whose result is used as an `int`/`char`. |
| `mega65-signedness` | warning | all | A plain `char`/`short`/`int`/`long` (unsigned in cc45) given or compared with a negative constant, `x < 0`, `?:` mixing a signed and a plain operand, and `/ % >>` of what standard C would have negative: `x / -2`, `(a - b) / 2`, `(a - b) >> 1`, `-a / 4`. |
| `mega65-implicit-narrowing` | info | all | A wider integer stored in a narrower one without a cast (`c = n`, `char c = f()`, `n = 0x12345`). An expression is as wide as it is written: `c + 1` is a `char`'s, `n & 0xFF` a byte. |

Notes on the rules:

- **What cc45 does with non-volatile I/O.** cc45 never merges or drops an
  access through a pointer, volatile or not, so `*(char *)0xD020 = x` works
  today; it does reuse a value read from a non-volatile *variable*. The
  rule is about what the C standard allows (and other compilers do).
  `<mega65.h>`'s register structs and macros are volatile.
- **Blocks.** `mega65-dma-trigger-order` follows constants through one basic
  block: a pointer variable set before a loop or an `if` is not known
  inside it, and nothing is reported.
- **The `-O` level.** The call-graph rules see the file as lowered: a small
  function inlined at `-O2` is not called, so a handler that uses it reaches
  nothing. `cl45 -O0` shows every call.
- **One file.** A handler's calls into other files are ln45's to check; a
  call cycle through another file is not seen.
- **`mega65-signedness`** follows named variables and parameters declared
  plain (no `signed`/`unsigned`, not a typedef). With `-fsigned-default`
  nothing is plain.

## Suppressing a finding

```c
c = n;                  // NOLINT(mega65-implicit-narrowing): the low byte is the value
// NOLINTNEXTLINE(mega65-signedness)
if (x < 0) return;
v = *(char *)0xD012;    /* NOLINT (every rule on this line) */

#pragma cc45 lint(ignore, mega65-implicit-narrowing)
...                     /* the rule is off from here */
#pragma cc45 lint(restore, mega65-implicit-narrowing)
```

`#pragma cc45 lint(ignore, id[, id])` holds to the end of the file or to the
matching `restore`; cc45 itself ignores the pragma. A reason after a NOLINT
comment is a good habit; the library's suppressions carry one.

## Configuration: `.cc45-lint.yml`

The first `.cc45-lint.yml` found from the source file's directory upward,
over `~/.config/m65/cc45-lint.yml`; the command line over both (#278):

```yaml
profile: cc45
c_checks:
  enabled: "mega65-*,-mega65-implicit-narrowing"
  options:
    mega65-stack-frame-limit: 512
overrides:
  mega65-signedness: error
  mega65-recursion-frame: off
```

`asm_rules` (al45's) is read and left to it.

## Notes

- The library's C lints clean, in both calling conventions:
  `make lint-lib`, `src/test/test_cl45.sh`. Getting there took four
  parameters narrowed to `unsigned char` (`strftime`, `rtc`, the directory
  reader), casts where a digit is stored in a `char`, a constant that did
  not fit its field (`0xFFFFFFFF` in an `unsigned int`), and three
  `#pragma cc45 recurse`.
- Not rules, on purpose: calling-convention mismatches (ln45 checks every
  cross-object call and bridges them), optimization advice, C-to-assembly
  mapping (`objdump45 --source`).
- The LSP server (`tools/ide/lsp-server`) does not run the linters yet.
