# cl45 — MEGA65 C linter

`cl45` checks C source for MEGA65- and cc45-specific mistakes and reports
them by rule (#199). It is the same program as `cc45` (`bin/cl45` is a link
to `cc45`) started under another name: it preprocesses, parses and lowers
the file exactly as cc45 compiles it (the same `-I`, `-D`, `-f...` and
`-O<n>`), runs the code generator, and writes no file. The rules are the
ones that need what the compiler knows: types, which addresses are I/O, the
call graph of the file, stack frames. The design is in
`doc/architecture/lint.md`; the assembly linter is `al45`.

## Usage

```bash
cl45 [options] file.c
cl45 -O2 -Iinclude -DNDEBUG file.c          # as the file is compiled
cl45 --format=sarif file.c > out.sarif
cl45 --list-rules
cl45 --explain=mega65-sac-interrupt
make lint-lib                               # the standard library: its C (cl45) and assembly (al45)
```

| Option | Description |
|--------|-------------|
| `-I<path>`, `-D<name>[=<val>]`, `-O<n>`, `-f...` | As for cc45. Lint a file with the options it is compiled with: the calling convention, `-fsigned-default`, `-fno-staticalloc` and the `-O` level (what is inlined) change what the rules see. |
| `--checks=LIST` | Rule globs, applied in order: `mega65-*`, `-mega65-implicit-narrowing`. |
| `--disable=ID[,ID]` | Turn rules off (as `--checks=-ID`). |
| `--severity=ID=LEVEL` | A rule's level: `off`, `info`, `warning`, `error`. |
| `--profile=cc45` / `standalone` | The profile: `cc45` (the default: a program linked with crt0 and c45.lib) or `standalone`. |
| `--config=FILE` | Read this configuration instead of the default files. |
| `--format=text` / `json` / `sarif` | Output format (default text). |
| `--list-rules` | The rules, their level in force and their profile. |
| `--explain=ID` | A rule's description. |
| `-v` … `-vvvv` | Diagnostics of cl45 itself on stderr; the findings do not change. |
| `-?`, `--help`, `-V` | The options above; the version. |

Findings go to stdout. Text lines are
`file:line:col: warning: message [mega65-rule-id]`. JSON is an array of
`{file, line, column, severity, rule, message}`; SARIF is version 2.1.0.
The exit status is 1 when a finding has the level `error`, cc45's own
status when the file does not compile, else 0.
An option cl45 (and cc45) does not know is a warning on stderr and
ignored (`cl45: warning: unknown option '--foo' ignored`); the file is
linted.

cc45's own warnings (an unused variable, an implicit declaration…) still go
to stderr. The warnings cc45 gives that a rule covers (the plain-integer
ones, the parameter notes, the recursion warning) are reported as that
rule's findings instead, so they can be configured and suppressed like the
others; cc45 itself prints them as before.

Findings in the system headers (`lib/include`, or an installed
`include/cc45`; also a `CC45_INCLUDE` directory that holds a copy of them) are not reported; those in the project's own headers are,
at the header's line. A macro's finding is reported where it is used.

## Rules

| Rule | Default | Profile | What |
|---|---|---|---|
| `mega65-dma-trigger-order` | warning | all | `$D701`/`$D702`/`$D704` (the DMA list address) written after `$D700`/`$D705` (the trigger) in the same block, with no later trigger (which would make them the next job's). Addresses through casts, register structs and pointer variables set in the block. |
| `mega65-io-not-volatile` | warning | all | I/O (`$D000`-`$DFFF`) reached through a pointer that is not to a `volatile` type: `*(char *)0xD020`, `((struct regs *)0xD400)->x`, `char *p = (char *)0xD020`, `p = (char *)0xD020`; a variable placed in I/O (`__section` of a `#pragma section` at an I/O address) that is not `volatile`. |
| `mega65-io-personality` | info | standalone | A VIC-III/IV register (`$D030`-`$D07F`) written in a file that never writes the knock to `$D02F` (crt0 does it for linked programs). |
| `mega65-isr-rom-call` | warning | cc45 | An `__interrupt` handler, or a function of the file it calls, calls the ROM: `putchar`/`printf`/the stdio file functions, the `<cbm.h>` functions (`cbm_*`), `__rom_call`, inline assembly with `jsr $E000`+. The library keeps its own state across a handler; the ROM's routines are not reentrant, so this is safe only when the program is never inside the ROM when the interrupt arrives. |
| `mega65-sac-interrupt` | warning | cc45 | A static-allocation function reachable from an `__interrupt` handler of the same file. ln45 refuses the program at link time; this says so at the function. |
| `mega65-recursion-frame` | info | all | A function on a call cycle within the file (it gets a stack frame instead of static allocation). `#pragma cc45 recurse` before it says it is meant. |
| `mega65-stack-frame-limit` | warning | all | A stack frame larger than the option `mega65-stack-frame-limit` (default 256 bytes). Functions with static allocation have no frame. |
| `mega65-narrow-param` | info | all | A static function's `int` parameter that every call gives a constant of 0-255 (it could be `unsigned char`), or, when declared signed, only non-negative values. |
| `mega65-wide-arith` | info | all | `long` `+ - * & \| ^` whose operands were widened from `int`/`char` (or are small constants) and whose result is used as an `int`/`char`. |
| `mega65-signedness` | warning | all | A plain `char`/`short`/`int`/`long` (unsigned in cc45) given or compared with a negative constant, `x < 0`, `?:` mixing a signed and a plain operand, and `/ % >>` of what standard C would have negative: `x / -2`, `(a - b) / 2`, `(a - b) >> 1`, `-a / 4`. |
| `mega65-implicit-narrowing` | info | all | A wider integer stored in a narrower one without a cast (`c = n`, `char c = f()`, `n = 0x12345`). An expression is as wide as it is written: `c + 1` is a `char`'s, `n & 0xFF` a byte. |
| `mega65-unpack-format` | warning | cc45 | A pack45 stream unpacked (`unpack`, `unpack_to`, `load_unpack`) whose format's decoder the file does not link (#666): format 2 without `UNPACK_FORMAT2;` (or `UNPACK_IMAGES;`), format 1 without `UNPACK_FORMAT1;` when `UNPACK_EXPLICIT_FORMATS` is defined (else `<unpack.h>` links it). Only streams whose format byte it can read: an array initialized in the file (`#embed` too), or `load_unpack` of a literal name whose file (as written, in lower or upper case, or with `.prg` / `.pak` / `.bin`) is beside the source or in an `-I` directory; a stream of no known format is not guessed. Only in the file with `main()`: the decoder may be named in any one file of the program, so a file without `main()` is left to ln45, which checks the whole program (`ln45: warning: format 2 stream unpacked at FILE:LINE, ...`). |

Notes on the rules:

- **What cc45 does with non-volatile I/O.** cc45 never merges or drops an
  access through a pointer, volatile or not, so `*(char *)0xD020 = x` works
  today; it does reuse a value read from a non-volatile *variable*. The
  rule is about what the C standard allows (and other compilers do).
  `<mega65.h>`'s register structs and macros are volatile.
- **Blocks.** `mega65-dma-trigger-order` follows constants through one basic
  block: a pointer variable set before a loop or an `if` is not known
  inside it, and nothing is reported.
- **The `-O` level.** The call-graph rules see the file as lowered: a small
  function inlined at `-O2` is not called, so a handler that uses it reaches
  nothing. `cl45 -O0` shows every call.
- **One file.** A handler's calls into other files are ln45's to check; a
  call cycle through another file is not seen.
- **`mega65-signedness`** follows named variables and parameters declared
  plain (no `signed`/`unsigned`, not a typedef): a negative constant stored in
  a parameter (`x = -1`) as in a variable. With `-fsigned-default` nothing is
  plain.
- **`mega65-narrow-param`** looks at the calls left after inlining: a static
  function inlined into every caller (at `-O2` a small one is) has no calls,
  and nothing is reported (`cl45 -O1`, or `-fno-inline-small-functions`, shows
  it). It names the function as written in C (`nar`), not by its symbol in the
  object (`nar__c`).

## Sample output

A finding of each rule but `mega65-io-personality` (standalone), from one file at `-O1` (at `-O2`
`nar`, `tick` and `hello` are inlined and `mega65-narrow-param` / `mega65-sac-interrupt` have no call
to see):

```c
#include <stdio.h>
#include <unpack.h>

static const unsigned char img[] = { 2, 0, 0, 0 };
static unsigned char nar(int n) { return (unsigned char)(n + 1); }
int fact(int n) { return n ? n * fact(n - 1) : 1; }

#pragma cc45 recurse
int big(int i) {
    char buf[300];
    buf[i] = 1;
    return buf[i + 1];
}

int ticks;
void tick(void) { ticks++; }
void hello(void) { putchar('x'); }
__interrupt void isr(void) { tick(); hello(); }

int main(void) {
    int x = 5;
    char c;
    unsigned int k = 7, m = 9;
    *(unsigned char *)0xD020 = 0;
    *(volatile unsigned char *)0xD700 = 0;
    *(volatile unsigned char *)0xD701 = 0x10;
    if (x < 0) return 1;
    c = k;
    k = (long)k + m;
    unpack((unsigned long)(unsigned int)img);
    return nar(3) + nar(4) + c + big(k) + fact(m);
}
```

```text
$ cl45 -O1 lint.c
lint.c:5:1: info: parameter 1 of 'nar' could be 'unsigned char' (all call sites pass 0-255) [mega65-narrow-param]
lint.c:6:1: info: 'fact' calls itself: it gets a stack frame instead of static allocation (#pragma cc45 recurse before it says so) [mega65-recursion-frame]
lint.c:9:1: warning: 'big' has a stack frame of 300 bytes (limit 256) [mega65-stack-frame-limit]
lint.c:16:1: warning: 'tick' uses static allocation and is reachable from the interrupt handler 'isr': ln45 will refuse it (put #pragma cc45 recurse before it) [mega65-sac-interrupt]
lint.c:17:1: warning: 'hello' uses static allocation and is reachable from the interrupt handler 'isr': ln45 will refuse it (put #pragma cc45 recurse before it) [mega65-sac-interrupt]
lint.c:17:1: warning: putchar() calls the ROM in 'hello', which the interrupt handler 'isr' reaches: the ROM is not reentrant (the program may be inside it) [mega65-isr-rom-call]
lint.c:24:5: warning: I/O ($D020) accessed through a pointer that is not to a volatile type: cast the address to (volatile T *) [mega65-io-not-volatile]
lint.c:26:1: warning: DMA list address byte $D701 written after the trigger (line 25) and no trigger follows: the job started with the old value [mega65-dma-trigger-order]
lint.c:27:11: warning: 'x' is unsigned (plain int is unsigned in cc45): 'x < 0' is always false; declare it 'signed' (or use -fsigned-default) [mega65-signedness]
lint.c:28:7: info: an int value is stored in 'c' (char): its upper byte is dropped; cast it if that is meant [mega65-implicit-narrowing]
lint.c:29:1: info: long '+' of operands that fit an int, its result used as one: 16-bit arithmetic gives the same value [mega65-wide-arith]
lint.c:29:7: info: a long value is stored in 'k' (int): its upper bytes are dropped; cast it if that is meant [mega65-implicit-narrowing]
lint.c:30:5: warning: a format 2 stream (array 'img') is unpacked here, but this file does not link its decoder: put UNPACK_FORMAT2; at file scope (unless another file of the program does, unpack() returns UNPACK_ERROR for it) [mega65-unpack-format]
```

`big` is `#pragma cc45 recurse` so that it has a frame (a static-allocation function has none). The
standalone profile's rule:

```text
$ cat io.c
void main(void) { *(volatile unsigned char *)0xD031 = 0x40; }
$ cl45 -O2 --profile=standalone io.c
io.c:1:1: info: a MEGA65 I/O register is written, but nothing writes $47, $53 to $D02F (the knock that makes it visible) [mega65-io-personality]
```

Both exit 0 (no finding of the level `error`); `--severity=mega65-signedness=error` makes the first
exit 1.

## Suppressing a finding

```c
c = n;                  // NOLINT(mega65-implicit-narrowing): the low byte is the value
// NOLINTNEXTLINE(mega65-signedness)
if (x < 0) return;
v = *(char *)0xD012;    /* NOLINT (every rule on this line) */

#pragma cc45 lint(ignore, mega65-implicit-narrowing)
...                     /* the rule is off from here */
#pragma cc45 lint(restore, mega65-implicit-narrowing)
```

`#pragma cc45 lint(ignore, id[, id])` holds to the end of the file or to the
matching `restore`; cc45 itself ignores the pragma. A reason after a NOLINT
comment is a good habit; the library's suppressions carry one.

## Configuration: `.cc45-lint.yml`

The first `.cc45-lint.yml` found from the source file's directory upward,
over `~/.config/m65/cc45-lint.yml`; the command line over both (#278):

```yaml
profile: cc45
c_checks:
  enabled: "mega65-*,-mega65-implicit-narrowing"
  options:
    mega65-stack-frame-limit: 512
overrides:
  mega65-signedness: error
  mega65-recursion-frame: off
```

`asm_rules` (al45's) is read and left to it.

The keys (a key not listed is an error, *"unknown key 'x' (profile, c_checks,
asm_rules, overrides, options)"*, and so is one inside `c_checks` or an
`asm_rules` entry):

| Key | Value |
|-----|-------|
| `profile` | `cc45` or `standalone` (as `--profile=`) |
| `c_checks.enabled` | cl45's rules on or off: globs, `-` removes, in order (as `--checks=`) |
| `c_checks.options` | Rule options, `name: value` |
| `asm_rules` | A list of al45's rules by `id`, each with `severity`, `message` (the text that replaces the built-in one) and `options` |
| `overrides` | `rule-id: off`, `info`, `warning` or `error`, for either linter (as `--severity=`) |
| `options` | Rule options, `name: value`, for either linter |

The three `options` maps (top-level, `c_checks.options`, an `asm_rules`
entry's) fill one table: an option is named by the rule it belongs to, and
the last one read wins. The options (`src/main/CLint.cpp`, `src/main/AsmStyle.cpp`):

| Option | Read by | Default | Value |
|---|---|---|---|
| `mega65-stack-frame-limit` | cl45 | `256` | The largest stack frame not reported, in bytes; a value that is not a whole number is a warning, and 256 is used |
| `mega65-style-instruction-column` | al45, af45 | `4` | Spaces before an instruction, 0-200 |
| `mega65-style-operand-column` | al45, af45 | `0` | Spaces before an operand, 0-200; `0`: one space after the mnemonic |
| `mega65-style-comment-column` | al45, af45 | `28` | Spaces before a trailing comment, 0-200 |
| `mega65-style-label-name` | al45 | `^[A-Za-z_.][A-Za-z0-9_.]*$` | A regular expression (ECMAScript, `std::regex`) for global labels and procs |
| `mega65-style-local-name` | al45 | `^@[A-Za-z0-9_]+$` | The same for local labels |
| `mega65-style-constant-name` | al45 | `^[A-Za-z_][A-Za-z0-9_.]*$` | The same for constants |

A style option that is not a column or not a regular expression is an error for al45 and af45, whichever
rules are on (cl45 does not read them; `al45: error: mega65-style-comment-column: '300' is not a column (0-200)`, exit status 1); a name
no tool reads is a warning naming the file and the line, and the rest of the file applies. With
this `.cc45-lint.yml` beside the source:

```yaml
options:
  mega65-stack-frame-limt: 512
  mega65-stack-frame-limit: 1k
overrides:
  mega65-unreachble: error
c_checks:
  enabled: "mega65-*,-mega65-dmaa-*"
```

```
cl45: warning: ./.cc45-lint.yml:2: options: unknown option 'mega65-stack-frame-limt' ignored
cl45: warning: ./.cc45-lint.yml:3: options: mega65-stack-frame-limit: '1k' is not a number; 256 is used
cl45: warning: ./.cc45-lint.yml:5: overrides: unknown rule 'mega65-unreachble' ignored
cl45: warning: ./.cc45-lint.yml:7: c_checks.enabled: 'mega65-dmaa-*' matches no rule
```

A rule id (in `overrides`, `asm_rules`, `--severity=`, `--disable=`) that is neither al45's nor cl45's
is a warning too, and so is a glob (`c_checks.enabled`, `--checks=`, `--disable=`) that matches no rule:
one file serves both linters, so either tool knows the other's rules and options and says nothing
about them (`src/main/LintRules.cpp`). A warning does not change the exit status. Options come only from the
configuration: al45 and cl45 have no command-line option for them (af45 has `--option=ID=VALUE`).

cc45's options can also come from `~/.config/m65/cl45.conf` (read as cc45
reads `cc45.conf`; `cc45.conf` itself is not read by cl45): put there the
`-O<n>` and `-f...` options the project is compiled with.

## Notes

- In an editor: the language server (`tools/ide/lsp-server`) runs cl45 on the
  text being edited (`cl45 --format=json <file>`: cc45's default options, or those of
  `~/.config/m65/cl45.conf`; the rules those of `.cc45-lint.yml`) and shows
  its findings as diagnostics, the rule as the code. Settings:
  `m65.lint.enabled` (on by default) and `m65.cl45Path` (else the `cl45`
  beside cc45); assembly files get al45 the same way (`m65.al45Path`);
  `tools/ide/IDE-SETUP.md`.
- The library's C lints clean, in both calling conventions:
  `make lint-lib`, `src/test/test_cl45.sh`. Getting there took four
  parameters narrowed to `unsigned char` (`strftime`, `rtc`, the directory
  reader), casts where a digit is stored in a `char`, a constant that did
  not fit its field (`0xFFFFFFFF` in an `unsigned int`), and three
  `#pragma cc45 recurse`.
- Not rules, on purpose: calling-convention mismatches (ln45 checks every
  cross-object call and bridges them), optimization advice, C-to-assembly
  mapping (`objdump45 --source`).
