# cc45 — Mega65 C Compiler

`cc45` is a C compiler for the MEGA65 (45GS02). It compiles one C file to `ca45` assembly, and by default goes on to assemble it with `ca45` and link it with `ln45` into a BASIC-startable PRG.

Behaviour described here was checked against cc45 v1.0.4 (`cc45 --version`); examples were compiled with `./bin/cc45` and, where a result is given, run on xemu (`xemu-xmega65 -prgmode 65`), reading the exit status that crt0 leaves at `$FD/$FE`.

## Quick Start

```bash
cc45 hello.c                  # hello.prg: compile, assemble, link (10 SYS 8205)
cc45 hello.c -o hello.prg     # same, explicit output name
cc45 -c hello.c               # hello.o45 relocatable object
cc45 -S hello.c               # hello.s45 assembly
cc45 -E hello.c -o hello.i    # preprocess only
```

The one-step build links against the standard library of the selected calling convention (`c45.lib`, or `c45_stack.lib` with `-fno-zpcall`), looked up in `bin/../lib/build`, then `bin/../lib/cc45`; if neither exists it passes `-l <name>` to `ln45`, which searches `CC45_LIB`. The library's `crt0` member is the startup code.

## Command-Line Usage

```bash
cc45 [options] <input_file.c>
```

Exactly one input file is compiled (the last non-option argument). An unrecognised option starting with `-` (for example `-Wall`) gives *"cc45: warning: unknown option '-Wall' ignored"*.

### Options

| Option | Description |
|--------|-------------|
| `-E` | Preprocess only. The output goes to the `-o` file, or to `<input>.prg` when no `-o` is given (there is no stdout output). |
| `-S` | Stop after code generation. Writes the standalone assembly form (a small startup stub at `* = $2000`, or the `--prg-base` address), meant for inspection. |
| `-c` | Compile and assemble to a relocatable `.o45` object. |
| `-o <file>` | Output file. Its extension selects the stage: `.s`/`.s45` assembly (as `-S`), `.o45` object (as `-c`), anything else a program. Defaults: `<input>.prg`, `<input>.o45` with `-c`, `<input>.s45` with `-S`. |
| `--prg-base <hex>` | Link a plain PRG loaded at that address (hex digits, e.g. `3000` or `0x3000`; no `$`) instead of the BASIC-startable PRG. Start it with `SYS`. |
| `-O<n>` | Optimization level, a digit `0`–`9` (default `2`). See [Optimization Levels](#optimization-levels). `-Osize` is `-O2`, `-Ospeed` is `-O3`; any other suffix (including `-Os`) is `-O0`. |
| `-I<path>`, `-I <path>` | Add an include directory (searched after the default directory; see [Include Search](#include-search)). |
| `-D<name>[=<val>]` | Define a preprocessor macro (`-DNAME` defines it as `1`). |
| `-v` | Verbose: stage progress. |
| `-vv` | More verbose (sub-steps, ca45 `-v`). |
| `-fzpcall` | ZP calling convention (default). |
| `-fno-zpcall` | Stack calling convention; links `c45_stack.lib`. |
| `-fstaticalloc` / `-fno-staticalloc` | Static allocation (SAC) of locals of non-recursive functions (default on). Also defines `__CC45_STATIC_ALLOC__`. |
| `-fstack16` / `-fno-stack16` | 16-bit CPU stack topped at `$BFFF` (default) / the ROM's 8-bit page-1 stack. See [CPU Stack](#cpu-stack). |
| `-fstack-top=<addr>` | Top byte of the 16-bit CPU stack (`0x9FFF`, `$9FFF` or decimal). |
| `-fbss-fill=<byte>` | The byte crt0 fills BSS with at startup (default `$00`; `0xFF`, `$FF` or decimal). Set by the module containing `main` (`__bss_fill`); a non-zero value breaks C's zero initialization on purpose, to find code that relies on it. ln45 `--bss-fill=` does the same at link time. |
| `-finline-functions` | Inline small functions (also enabled by `-O2` and up). |
| `-f<optimization>` / `-fno-<optimization>` | Turn one optimization on or off, e.g. `-fno-cse`, `-floop-invariant-code-motion`, `-fno-tail-call-optimization`. See [optimizations.md](../architecture/optimizations.md#optimization-switches) for the names. |
| `--future` | Warn when an optimization that is not implemented yet is requested (`-fprocedure-inlining`, `#pragma cc45 optimize(cross-function-inlining)`, …); without it such requests are ignored silently. |
| `-Roptir` | Report what the IR optimization passes change, on stderr. |
| `-fmax-inline-ir-size=<N>` | Largest function (in IR instructions) that is inlined; default 11. |
| `-fmax-unroll-bytes=<N>` | Largest estimated code size of an unrolled vector operation or (with `-floop-unrolling`) loop; default 128. |
| `-fsigned-default` / `-fno-signed-default` | Plain `char`/`short`/`int`/`long` are signed (standard C) / unsigned (default). |
| `-funsigned-char` / `-fsigned-char` | With `-fsigned-default`, keep plain `char` unsigned / make it signed. |
| `-fimplicit-function-declaration` / `-fno-…` | Allow calls to undeclared functions with a warning (default: error). |
| `-V`, `--version` | Print the version and exit. |
| `-?`, `--help` | Print a short help and exit. |

The following options are accepted but currently have **no effect**: `--pragma <text>`, `--save-temps` (the intermediate `temp_<pid>.s45`/`.o45`, written in the current directory, are always removed), `--emit-ir` and `-Rcodegen`. To see the optimized IR, set `CC45_DUMP_IR=1` (printed to stderr).

### Optimization Levels

| Level | Effect |
|-------|--------|
| `-O0` | AST constant folding and the always-on code generation and assembler optimizations; only `inline` functions (and `-finline-functions`) are inlined. |
| `-O1` | Adds the IR passes: strength reduction, algebraic simplification, type narrowing, branch folding, CSE, loop-invariant code motion, copy propagation, address fusion. |
| `-O2` (default), `-O3` | Additionally inlines small functions automatically (up to `-fmax-inline-ir-size`). `-O3` currently produces the same code as `-O2`. |
| `-O4` and up | Adds loop interchange (`-floop-interchange`) and loop unrolling (`-floop-unrolling`). `-O5`…`-O9` currently produce the same code as `-O4`. |

`-f<name>` / `-fno-<name>` switch single optimizations on top of the level, and `#pragma cc45 optimize(...)` switches IR passes per function; see [optimizations.md](../architecture/optimizations.md).

### Exit Codes

| Code | Stage |
|------|-------|
| 0 | Success |
| 1 | Preprocessor error (e.g. `#include` not found, `#error`) |
| 43 | Parse error |
| 85 | AST optimization failure |
| 127 | Code generation / semantic error (undeclared identifier, invalid construct) |
| exit status of `ca45` / `ln45` (normally 1) | Assembler or linker error |
| 253 | Internal/pipeline error (e.g. input file cannot be opened) |

### Configuration File

Options are read from `~/.config/m65/cc45.conf` (`cp45.conf` when run as `cp45`) before the command line, one or more per line; `#` starts a comment line. Later options override earlier ones, so command-line flags win. See [CONFIGURATION.md](CONFIGURATION.md).

```
-O2
-finline-functions
```

### Environment Variables

| Variable | Description |
|----------|-------------|
| `CC45_INCLUDE` | Colon-separated include directories, searched before the default `bin/../lib/include` and the `-I` directories. |
| `CC45_LIB` | Colon-separated library directories used by `ln45` (for the one-step build only when the library is not found next to `bin/`). |
| `CC45_DUMP_IR` | Non-zero: print the optimized IR to stderr. |
| `CA45_OPTIMIZE`, `CA45_WARNINGS` | Read by `ca45` when cc45 runs it. |

### Include Search

`#include "f"` and `#include <f>` search the same list, in order: the directory of the including file, `CC45_INCLUDE`, `bin/../lib/include`, then the `-I` directories. A file under `-I` therefore cannot override a standard header of the same name.

## Compilation Pipeline

1. **Preprocess** (`cp45`, integrated): macros, includes, conditionals; `#pragma cc45 …` lines become `__asm__(".directive")` statements. A unit that uses `long long`, `int64_t`, `__int64`, `__int128`, `__int(N)` or `__uint(N)` gets `<intwide.h>` included automatically.
2. **Parse** to an AST, then AST constant folding and function analysis.
3. **IR generation and optimization** (IRBuilder): inlining, static allocation, register allocation, IR passes.
4. **Code generation** (IRCodeGen) to `ca45` assembly with `proc`/`endproc` blocks, `.loc` source-line directives and per-function metadata.
5. **Assemble** with `ca45 -c` and **link** with `ln45 -basic` (or `-prg -t <base>`).

## Features

- **Types**: `char`, `short`, `int`, `long`, `long long`, `float`, `double`, `long double`, `_Bool`, `signed`/`unsigned` variants, pointers, arrays (multi-dimensional), `struct`, `union` (including anonymous members), `enum`, bitfields, function pointers, `void *`, `_Complex`, GCC vectors, `__int(N)`.
- **Signedness**: plain `char`/`short`/`int`/`long` are **unsigned** unless declared `signed`; `-fsigned-default` or `#pragma cc45 signed_default` selects standard C (`#pragma cc45 unsigned_default` switches back). `x < 0` on an unsigned value warns.
- **Declarations**: `typedef`, `static`, `extern`, `register`, `auto`, `volatile`, `const`, `restrict`, qualifiers in any order, implicit `int` (`static max;`).
- **Initializers**: scalar, aggregate, designated (`{.x = 1}`, `{[2] = 3}`), flexible array members, string-literal concatenation, compound literals (`(int[]){1, 2}[1]`, `(struct point){.x = 7}`).
- **Operators**: all C operators, `sizeof`, `_Alignof`, `_Generic`, comma, casts, GCC Elvis `a ?: b`, `typeof`/`__typeof__`, statement expressions `({ ... })`, `&&label` and `goto *p`, `__real__`/`__imag__`.
- **Statements**: `if`/`else`, `switch` with GCC case ranges (`case 'A' ... 'Z':`), `while`, `do`, `for` with declarations, `break`, `continue`, `goto`, labels, `return`, `repeat(N)` unrolling, `asm`/`__asm__`, `_Static_assert`.
- **Functions**: prototypes, variadic functions (`<stdarg.h>`), `inline`, `_Noreturn`, GCC nested functions, `__interrupt`, `__naked`, `__regparm`, `__fastcall__`.
- **Floating point**: `float`, `double` and `long double` are all the CBM 40-bit format (5 bytes), computed by the BASIC 65 ROM routines; see [stdlib](../architecture/stdlib.md).
- **Struct extensions**: methods, single inheritance, `virtual`, `final`, operator overloading (see [Object-Oriented Struct Extensions](#object-oriented-struct-extensions)).
- **Weak symbols**: `#pragma weak` / `#pragma cc45 weak` before a definition.
- **MEGA65 extensions**: `__cpu`/`__flags` register access, `__dma_copy`/`__dma_fill`, string encodings (`@"..."`, `#pragma encoding`); `__far` and `__striped` are reserved for future expansion.

## Language Syntax (BNF)

A simplified grammar of the statements and expressions cc45 accepts.

### Statements

```bnf
<statement> ::= <compound-statement>
              | <expression-statement>
              | <selection-statement>
              | <iteration-statement>
              | <jump-statement>
              | <labelled-statement>
              | <declaration>
              | <static-assert>

<compound-statement>   ::= "{" <statement>* "}"
<expression-statement> ::= <expression>? ";"
<labelled-statement>   ::= <identifier> ":" <statement>

<selection-statement> ::= "if" "(" <expression> ")" <statement> ( "else" <statement> )?
                        | "switch" "(" <expression> ")" <statement>
                        | "case" <constant> ( "..." <constant> )? ":" <statement>?
                        | "default" ":" <statement>?

<iteration-statement> ::= "while" "(" <expression> ")" <statement>
                        | "do" <statement> "while" "(" <expression> ")" ";"
                        | "for" "(" ( <expression-statement> | <declaration> ) <expression>? ";" <expression>? ")" <statement>
                        | "repeat" "(" <integer-constant> ")" <statement>
                        | "repeat" "(" <type-name> <identifier> "," <integer-constant> ")" <statement>

<jump-statement> ::= "return" <expression>? ";"
                   | "break" ";"
                   | "continue" ";"
                   | "continue" ( <constant> | "default" ) ";"
                   | "goto" <identifier> ";"
                   | "goto" "*" <expression> ";"
                   | ( "asm" | "__asm__" ) "volatile"? "(" <string-literal> ")" ";"

<static-assert> ::= "_Static_assert" "(" <constant-expression> "," <string-literal> ")" ";"
```

### Expressions

```bnf
<expression>     ::= <assignment> ( "," <assignment> )*
<assignment>     ::= <unary> <assignment-op> <assignment> | <conditional>
<assignment-op>  ::= "=" | "+=" | "-=" | "*=" | "/=" | "%=" | "&=" | "|=" | "^=" | "<<=" | ">>="
<conditional>    ::= <logical-or> ( "?" <expression>? ":" <conditional> )?
<logical-or>     ::= <logical-and> ( "||" <logical-and> )*
<logical-and>    ::= <bitwise-or> ( "&&" <bitwise-or> )*
<bitwise-or>     ::= <bitwise-xor> ( "|" <bitwise-xor> )*
<bitwise-xor>    ::= <bitwise-and> ( "^" <bitwise-and> )*
<bitwise-and>    ::= <equality> ( "&" <equality> )*
<equality>       ::= <relational> ( ("==" | "!=") <relational> )*
<relational>     ::= <shift> ( ("<" | ">" | "<=" | ">=") <shift> )*
<shift>          ::= <additive> ( ("<<" | ">>") <additive> )*
<additive>       ::= <multiplicative> ( ("+" | "-") <multiplicative> )*
<multiplicative> ::= <unary> ( ("*" | "/" | "%") <unary> )*
<unary>          ::= ( "!" | "~" | "-" | "+" | "*" | "&" | "++" | "--" | "__real__" | "__imag__" ) <unary>
                   | "&&" <identifier>
                   | "sizeof" <unary> | "sizeof" "(" <type-name> ")"
                   | ( "_Alignof" | "__alignof__" ) "(" <type-name> ")"
                   | "(" <type-name> ")" <unary>
                   | <postfix>
<postfix>        ::= <primary> ( "[" <expression> "]" | "(" <argument-list>? ")" | "." <identifier>
                                | "->" <identifier> | "++" | "--" )*
<primary>        ::= <identifier> | <constant> | <string-literal>+
                   | "(" <expression> ")"
                   | "(" "{" <statement>* "}" ")"
                   | "(" <type-name> ")" "{" <initializer-list> "}"
                   | ( "typeof" | "__typeof__" ) "(" ( <expression> | <type-name> ) ")"
                   | "_Generic" "(" <assignment> "," <generic-association> ( "," <generic-association> )* ")"
                   | "__builtin_va_start" "(" <expression> "," <identifier> ")"
                   | "__builtin_va_arg" "(" <expression> "," <type-name> ")"
                   | "__builtin_offsetof" "(" <type-name> "," <identifier> ")"
<generic-association> ::= ( <type-name> | "default" ) ":" <assignment>
<argument-list>  ::= <assignment> ( "," <assignment> )*
```

## Statement Descriptions

### Selection Statements (`if`, `else`, `switch`)
- **`if` / `else`**: standard C.
- **`switch`**: transfers control to the matching `case` label; control falls through to the next case unless a `break` intervenes.
    - **`case <min> ... <max>`**: (GCC extension) an inclusive range, for `char`, `int` and `long`. Ranges and single cases mix freely.
    - **`continue <value>` / `continue default`** (extension): `continue <value>` jumps to the `case` of the innermost `switch` that `<value>` selects, as if the `switch` ran again with that value (any expression, so a computed state works too; ranges and `default` apply as usual). `continue default` jumps to `default`, or past the `switch` if it has none. A plain `continue;` still belongs to the enclosing loop.
      ```c
      switch (state) {
      case START: init();  continue RUN;
      case RUN:   if (step()) continue RUN; continue STOP;
      case STOP:  finish(); break;
      }
      ```

### Iteration Statements (`while`, `do`, `for`, `repeat`)
- **`while`**, **`do`**, **`for`**: standard C, including `for (int i = 0; ...)`. `break` leaves the innermost loop or `switch`; `continue` goes to the condition (`while`, `do`) or the increment (`for`) of the innermost loop.
- **`repeat`**: (extension) compile-time unrolling. The body is copied N times with no counter or branch. N must be an integer constant.
    - `repeat(N) { body }`
    - `repeat(type var, N) { body }`: `var` is a constant 1, 2, …, N in the successive copies.

```c
repeat(8) { *dst++ = *src++; }                  // 8 copies, no loop
repeat(unsigned char x, 4) { buf[x - 1] = x; }  // buf = {1, 2, 3, 4}
```

### Jump Statements
- **`return`**: see [Return Values](#return-values) for the registers used.
- **`goto <label>`**, **`goto *expr`** with **`&&label`** (computed goto). Labels are function-scoped.
- **`asm` / `__asm__`**: see [Inline Assembly](#inline-assembly).

## Inline Assembly

`asm("...")` / `__asm__("...")` (optionally `__asm__ volatile (...)`) copies the string into the function's assembly. `\n` in the string separates lines; adjacent string literals are not concatenated here, and there is no GCC operand syntax (`: "r"(x)`). An `asm` statement at file scope is accepted but **dropped**; place assembly inside a function (or in a separate `.s45` module).

```c
int main(void) {
    asm("lda #$34\n ldx #$12");
    return __cpu.AX;            // 0x1234
}
```

After an `asm` statement the compiler assumes nothing about the registers. Local labels in inline assembly use the `@name` form (they are scoped to the function's `proc`).

### Reaching C Variables

| C object | Assembly name | Notes |
|----------|---------------|-------|
| Global `total` | `_total` | Absolute address. |
| `static` global | `_total` | Not exported from the object. |
| `static` local `calls` in `counter` | `__counter__local_calls` | |
| Function `main` | `_main` | A `static` function is `_name__<file>` (e.g. `_helper__util` in `util.c`). |
| Parameter `val` (ZP convention) | `@_p_val` | The parameter's ZP slot (`$10`…). Valid until the function makes a call. |
| Parameter `val` of a SAC function | `_func__param_val` | The function's static copy (both conventions). |
| `register` local `i` | `@_l_i` | Its zero-page address (`$30`…). |

Other locals and stack-frame parameters have no stable symbolic name for inline assembly (SAC locals are numbered, `_func__local_N`; frame offsets change). Pass such values through a global or a `register` variable.

```c
volatile int g_value;

void store_to_global(int val) {
    __asm__("lda @_p_val");       // ZP slot of val ($10/$11)
    __asm__("ldx @_p_val+1");
    __asm__("sta _g_value");
    __asm__("stx _g_value+1");
}
```

Do not use the old `ldax _p_val, sp` / `lda.sp` stack-relative forms: parameters are no longer on the stack in the default modes and the result is wrong. Hand-written code must not address the CPU stack as `$0100,x` either (see [CPU Stack](#cpu-stack)).

## Zero Page Layout

The program runs on a private base page (`__zp_page`, see [Memory Layout](#memory-layout-and-startup)), so these addresses are offsets within that page, not the ROM's page 0:

| Address | Use |
|---------|-----|
| `$06`–`$07` | `__static_chain` (nested functions) |
| `$08`–`$0F` | `__zp_scratch` … `__zp_scratch4` (compiler and runtime scratch) |
| `$10`–`$2F` | ZP calling-convention parameter block (32 bytes) |
| `$30`–`$E9` | Register allocator pool: temporaries and `register` variables |
| `$EA`–`$ED` | 32-bit temporary |
| `$FD`–`$FE` | Frame pointer of functions that use a stack frame |

`-D cc45.zeroPageStart=…` and `-D cc45.zeroPageAvail=…` only define preprocessor macros; the layout above is fixed.

## Memory Layout and Startup

### Startup (crt0)

`ln45` takes the startup code from the library's `crt0` member. Before `main` it:

1. saves the caller's stack pointer and flags, and enables the MEGA65 I/O registers (`$47`, `$53` to `$D02F`);
2. sets the exit status at ROM page-0 `$FD/$FE` to `$FFFF` ("never reached exit");
3. moves the base page to `__zp_page` (`lda #>__zp_page / tab`);
4. switches to the 16-bit CPU stack at `__stack_top` (unless `-fno-stack16`), restoring the caller's I flag;
5. fills BSS (`__bss_start` to `__bss_end`, which includes the private base page) with `__bss_fill` (0 unless `-fbss-fill=` / ln45 `--bss-fill=`), using a DMA fill job;
6. calls `_init_features` (a weak `rts`; define your own `init_features()` to add initialization);
7. calls `main` with `argc`/`argv` from the BASIC line that ran the program (see below), or `argc = 0`, `argv = NULL` when `main` takes no parameters.

**Command-line arguments.** When `main` is defined with parameters (`int main(int argc, char **argv)`), cc45 links the library's `__mainargs` (about 300 bytes; programs with `main(void)` don't get it). It reads the line typed at BASIC's `READY.` prompt, which BASIC 65 keeps in its input buffer at `$0200`:

```
RUN : P1, P2                     argc 3: "", "P1", "P2"
RUN "MYPROG" : P1, "A, B"        argc 3: "MYPROG", "P1", "A, B"
RUN "MYPROG" :REM TOTAL, STOP    argc 3: "MYPROG", "TOTAL", "STOP"
```

- `argv[0]` is the name in `RUN "NAME"`, or `""`; `argc` is at least 1, and `argv[argc]` is `NULL`.
- The arguments follow the first `:` outside quotes; a `REM` right after it is skipped. They are separated by commas and trimmed of spaces; quotes group text (commas, colons) and are removed. They end at the end of the line or at a `:` outside quotes; at most 16.
- **Use `:REM` when an argument contains a BASIC keyword**: BASIC tokenizes the line when RETURN is pressed, and only text after `REM` (or inside quotes) is left as typed. Without it, `TOTAL` arrives as the `TO` token (`$A4`) followed by `TAL`, and `ONE` as the `ON` token followed by `E`.
- The text is PETSCII as BASIC stored it (letters typed in the default mode are `$41`-`$5A`, which cc45 string literals write as lowercase: `strcmp(argv[1], "p1")`). It is copied before `main` runs, since the next line of keyboard input overwrites `$0200`.
- A program started some other way (`SYS`) gets `argc` 1 and `argv[0]` `""`.

When `main` returns, or `exit()` is called, `__exit` sets the base page back to 0, stores the exit status (`main`'s return value, `exit()`'s argument, `$FFFE` after `abort()`) at `$FD/$FE`, restores the caller's 8-bit stack and flags and returns with `rts`. A BASIC caller reads it with `PEEK(253)+256*PEEK(254)`.

crt0 clears BSS (step 5), so globals without an initializer start at 0 on real hardware too, whatever was in memory. Uninitialized `static` locals are placed in the initialized data instead (as zeros), so `-fbss-fill` does not change them.

### Default Memory Map (one-step build / `ln45 -basic`)

```
$2001  BASIC line 10 SYS 8205
$200D  crt0, code, data
       BSS (__bss_start .. __bss_end)
       __zp_page        private base page (page-aligned, last page of BSS)
       __zp_page_isr    handlers' base page (only if the program has an __interrupt function)
       heap             __bss_end .. $B000 (malloc)
$B000  4 KB reserved for the stack
$BFFF  __stack_top: the 16-bit CPU stack grows down from here
$C000  ROM in C65 mode (not usable as RAM)
$D000  I/O
```

`ln45` stops with an error if the program ends above `__stack_top`, and warns when less than 512 bytes are left for the stack.

### Linker Symbols

| Symbol | Default | Description |
|--------|---------|-------------|
| `__bss_start`, `__bss_end` | set by ln45 | Bounds of the BSS segment. |
| `__bss_fill` | `0` (ln45; `--bss-fill=`) | The byte crt0 fills BSS with. Defined by the module containing `main` for `-fbss-fill=`. |
| `__zp_page`, `__zp_page_isr` | set by ln45 | Private base pages. |
| `__stack_top` | `$BFFF` (weak, crt0) | Top of the 16-bit stack; `0` = 8-bit page-1 stack. Defined by the module containing `main` when `-fno-stack16`, `-fstack-top` or the pragmas are used. |
| `__heap_start`, `__heap_end` | `0` (library member `__heap_bounds`) | `0` means automatic: start at `__bss_end`; end 4 KB below `__stack_top`'s page (`$B000`), or `$C000` with the 8-bit stack. |

### Heap

`malloc`/`calloc`/`realloc`/`free` are always available from the library; the heap is initialized by the first `malloc`. To place it explicitly, link an object that defines both bounds, which then replaces the library default:

```asm
; heap.s45 — assemble with: ca45 -c heap.s45 -o heap.o45
.global __heap_start
.global __heap_end
__heap_start = $8000
__heap_end   = $A000
```

```bash
ln45 -basic -o prog.prg prog.o45 heap.o45 -L lib/build -l c45.lib
```

## CPU Stack

Programs run on a 16-bit CPU stack by default. crt0 clears the 45GS02 E flag
(`CLE`) and sets SP to `__stack_top` — `$BFFF`, the last byte below `$C000`
(in C65 mode bank 0 `$C000`-`$CFFF` reads as ROM, so it can't hold a stack).
The stack grows down towards the program's BSS and private base page, so deep
recursion, large stack frames and `alloca` are not capped at 256 bytes.
On exit crt0 sets E again and restores the caller's page-1 SP and flags.
KERNAL calls, the ROM IRQ handler and the BASIC float routines run
unchanged on the relocated stack.

- `-fno-stack16` / `#pragma cc45 no_stack16`: keep the ROM's 8-bit stack on
  page 1. The choice belongs to the module that defines `main`, which then
  defines `__stack_top = 0` (overriding crt0's weak `$BFFF`).
- `-fstack-top=<addr>` / `#pragma cc45 stack_top(<addr>)`: move the top of
  the 16-bit stack (for example below a buffer kept at `$A000`). A pragma in
  the source wins over the command-line flag.
- Hand-written assembly must not address the stack as `$0100,x` (or
  `__sp_base,x`). Read it through a pointer instead:
  `tsx; tsy; stx $08; sty $09; ldy #1; lda ($08),y` (SP+1). When changing SP
  with interrupts enabled, write SPH first when lowering SP and SPL first when
  raising it, so an interrupt between the two writes pushes below live data.

## Pragmas

`#pragma` lines are handled by the preprocessor. Unknown pragmas are ignored silently.

| Pragma | Effect |
|--------|--------|
| `#pragma once` | Include the file only once. |
| `#pragma push_macro("N")` / `pop_macro("N")` | Save / restore a macro definition. |
| `#pragma weak`, `#pragma cc45 weak` | The next function or global is a weak definition. |
| `#pragma cc45 recurse` | The next function uses a stack frame instead of static allocation (needed for functions called both from an `__interrupt` handler and from mainline code; also silences the warning on recursive functions). |
| `#pragma cc45 signed_default` / `unsigned_default` | Plain integer types signed / unsigned from here on. |
| `#pragma cc45 no_stack16` | As `-fno-stack16`. |
| `#pragma cc45 stack_top(<addr>)` (or `stack_top <addr>`) | As `-fstack-top=<addr>`. |
| `#pragma cc45 max_inline_ir_size(<N>)` | As `-fmax-inline-ir-size=N`. |
| `#pragma cc45 max_unroll_bytes(<N>)` | As `-fmax-unroll-bytes=N`. |
| `#pragma cc45 optimize(<name>, no-<name>, …)` | Switch IR optimization passes for the functions that follow (e.g. `optimize(no-licm)`); see [optimizations.md](../architecture/optimizations.md#optimization-switches). |
| `#pragma encoding <ascii\|petscii\|screencode>`, `#pragma encoding(<…>)` | Encoding of following string and character literals (see [String and Character Encodings](#string-and-character-encodings)). |
| `#pragma cc45 no_zp_save`, `#pragma no_zp_save` | `-S` (standalone) output only: do not relocate the base page. Linked programs always run on `__zp_page`. |
| `#pragma cc45 set_bp <n>` | `-S` output only: set the base page to `n` (a **decimal** number; `$40` is rejected). |

Accepted but currently without effect (they do not reach the code generator): `exit_rts`, `exit_halt`, `exit_brk`, `no_bssinit`, `heap`, `stdio`, `no_0100_stack`, `unroll [N]`, `unroll_default N`. The exit behaviour is always the crt0 return described above. Pragmas inside a false `#if` block are still applied.

`_Pragma("...")` works for `once`, `weak`, `no_zp_save`, `encoding` and the `cc45` pragmas above except `signed_default`, `unsigned_default`, `max_inline_ir_size` and `max_unroll_bytes`.

## Type System

| Type | Size | Notes |
|------|------|-------|
| `char` | 1 | Unsigned unless `signed` (or `-fsigned-default`). |
| `short`, `int` | 2 | Unsigned unless `signed`. |
| `long` | 4 | Unsigned unless `signed`. |
| `long long`, `int64_t`, `uint64_t`, `__int64_t`, `__uint64_t` | 8 | `struct __int64` from `<intwide.h>` (see below). |
| `__int128`, `__int128_t`, `__uint128_t` | 16 | `struct __int128`. |
| `float`, `double`, `long double` | 5 | CBM 40-bit float. |
| `_Bool` | 1 | Any non-zero value stored becomes 1. `<stdbool.h>` provides `bool`/`true`/`false`. |
| pointers, `void *` | 2 | 16-bit addresses. |

- **`long long` / `int64_t`**: `+ - * & | ^`, comparisons and unary operators via operator overloading and the `__intN_*` runtime. Integers convert to them (zero or sign filled) in initializers, assignments, arguments and mixed operands; they narrow to `char`/`int`/`long` by assignment, return or cast. `LL` constants keep all 64 bits.
- **`__int(N)` / `__uint(N)`**: the preprocessor maps them to `struct __intN` / `struct __uintN`. `<intwide.h>` defines the 64- and 128-bit structs; another width needs its own `struct __intN` definition (e.g. `__int(32)` is an "Unknown struct" error).
- **`_Complex` / `__complex__`**: integer complex types are `struct _Complex_int`, floating ones `struct _Complex_float`, with arithmetic operators, `__real__`/`__imag__`, imaginary literals (`2.0i`) and mixed real/complex operands (`1.0 + 2.0i`).
- **Integer literals** above 16 bits become `long` (with a warning when the literal has no suffix).
- **Casts**: narrowing keeps the low bytes, widening zero- or sign-extends by the source's signedness; constant casts are folded.

### Packed Structs (Default)

Structs are **packed**: no padding between members, and the alignment of every scalar type is 1 (`_Alignof(int) == 1`).

```c
struct Packed { char a; int b; };   // b at offset 1, sizeof == 3
```

`struct __unpacked S { ... }` pads each member to its own size (`b` above would be at offset 2). Note that `sizeof` of an `__unpacked` struct currently does not include the tail padding (`sizeof(struct __unpacked {char a; int b;})` is 3, although `b` is at offset 2).

### `_Alignas` and `__attribute__((aligned))`

`_Alignas(N)` and `__attribute__((aligned(N)))` request an alignment (a power of two) for globals, local statics, statically allocated (SAC) locals, struct members and — for the attribute — struct types (`struct __attribute__((aligned(4))) S { ... }`). `aligned` without an argument means 2. An aligned member pads the struct, an aligned struct's `sizeof` is rounded up to its alignment, and `_Alignof` reports it. ln45 starts each object's data/BSS on the largest alignment it needs. Locals in stack frames are not aligned.

```c
_Alignas(16) unsigned char buffer[32];            // address % 16 == 0
struct __attribute__((aligned(4))) S { char a; }; // sizeof 4, _Alignof 4
struct M { char a; _Alignas(4) char b; };         // b at 4, sizeof 8
```

### GCC Vector Extension
`typedef T V __attribute__((vector_size(N)));` declares a vector of `N / sizeof(T)` elements of an integer or float type `T`. A vector is a value: it is initialized with `{...}` or `(V){...}`, assigned, passed and returned like a struct, and `v[i]` reads or writes an element. The operators `+ - * / % & | ^ << >>`, unary `- ~ !` and the compound assignments work element by element; a scalar operand is converted to the element type and used for every element. Comparisons give a vector of signed integers of the element's width holding -1 (true) or 0. A cast between vector types of the same size keeps the bits. `__builtin_shuffle(a, mask)` and `__builtin_shuffle(a, b, mask)` select elements by index (modulo `n`, or `2n` for two vectors). `__attribute__((mode(QI/HI/SI)))` selects an 8/16/32-bit integer.

There are no vector instructions: an operation is a loop over the elements, unrolled when the estimated code fits `-fmax-unroll-bytes=N` / `#pragma cc45 max_unroll_bytes(N)` (default 128 bytes). cc45's `int` is 16 bits, so `vector_size(16)` of `int` has 8 elements.

### String and Character Encodings

String and character literals are PETSCII by default (`.text`); in cc45's mapping `'a'` is `$41` and `'A'` is `$61`.

- **Raw ASCII**: `@"Hello"` and `@'A'` are not translated (`.ascii`, `@'A'` is `$41`).
- **Switching**: `#pragma encoding ascii` (or `petscii`, `screencode`), `#pragma encoding(ascii)`, `_Pragma("encoding ascii")` or `asm(".encoding ascii");` inside a function. The pragma applies to literals in functions and to `char` array initializers; a string literal used to initialize a global **pointer** stays PETSCII.
- **Concatenation**: `"a" "b"` is `"ab"`. When a PETSCII and an `@` literal are concatenated the result uses the first literal's encoding.

### Warnings

cc45 warns (to stderr, with a source excerpt) about unused variables and parameters, unsigned comparisons with 0 that are always false, discarded `const` in arguments, unknown or ignored attributes, oversized integer literals, recursive functions that fall back to a stack frame, and recursive `always_inline` functions. It also prints notes, e.g. when every call passes 0–255 to an `int` parameter that could be `unsigned char`. There is no warning for implicit narrowing (`char c = some_int;`).

## Object-Oriented Struct Extensions

### Methods and `this`
Functions defined inside a struct are methods, mangled `StructName__method`, with a hidden first parameter `__this` (also usable as `this`).

```c
struct Counter {
    int value;
    void init(int start) { __this->value = start; }
    void increment() { this->value = this->value + 1; }
};
struct Counter c; c.init(5); c.increment();   // c.value == 6
```

### Inheritance
`struct Dog : Animal { ... }` places the base members first, so a `Dog *` can be used as an `Animal *`.

### Virtual Methods and `final`
`virtual` methods put a vtable pointer `__vt` at offset 0 and are called through the vtable. `struct Leaf final { ... }` cannot be inherited from, and `virtual int f() final { ... }` cannot be overridden. Every object of such a struct gets its `__vt` set to its struct's vtable: locals when declared (after any initializer), globals and statics in their initial data, and also array elements and nested struct members. A derived struct shares its parent's `__vt` (`sizeof` includes the parent's members).

### Operator Overloading
An operator method `operator+` is mangled `StructName__operator_add`; `a + b` on a struct with that method becomes `StructName__operator_add(&a, b)`.

- Binary: `+` (add), `-` (sub), `*` (mul), `/` (div), `%` (mod), `==` (eq), `!=` (ne), `<` (lt), `>` (gt), `<=` (le), `>=` (ge), `<<` (shl), `>>` (shr), `&` (band), `|` (bor), `^` (bxor)
- Unary: `~` (bnot), `!` (lnot), `++` (inc), `--` (dec), `-` (neg), `+` (pos), `*` (deref), `&` (addr)
- Assignment: `+=` (add_assign), `-=` (sub_assign), `*=` (mul_assign), `/=` (div_assign), `%=` (mod_assign), `&=` (band_assign), `|=` (bor_assign), `^=` (bxor_assign), `<<=` (shl_assign), `>>=` (shr_assign)

```c
struct Vec2 {
    int x, y;
    struct Vec2 operator+(struct Vec2 o) { struct Vec2 r; r.x = this->x + o.x; r.y = this->y + o.y; return r; }
    int operator==(struct Vec2 o) { return this->x == o.x && this->y == o.y; }
};
struct Vec2 s = a + b;
```

`<complex.h>` and `<intwide.h>` are built on these.

## Storage Classes and Function Specifiers

### `static`
- **File scope**: internal linkage. A static global is not exported; a static function is emitted as `_name__<file>` so modules with equally named static functions link together.
- **Local**: static storage, initialized once, named `__<func>__local_<name>` in the assembly (`__counter__local_calls`).

### `register`
A `register` local lives in the zero-page register pool (`$30`…), named `@_l_name` in the assembly. `&` on it is an error ("Cannot take address of register variable").

### `inline`, `__forceinline`, attributes
`inline` functions, and with `-O2` (default) or `-finline-functions` any small function, are inlined at call sites in the same file when their IR is at most `-fmax-inline-ir-size` instructions (default 11). `__attribute__((always_inline))` / `__forceinline` bypasses the limit, `__attribute__((noinline))` prevents inlining (and wins over `always_inline`). A recursive `always_inline` function warns and is called normally.

### `extern`
Declares without defining; referenced externals are emitted as `.extern`.

### `__interrupt`
An interrupt service routine. It pushes A, X, Y, Z and the base page register, increments crt0's `__isr_depth`, switches to its own base page `__zp_page_isr`, and returns with `RTI` after restoring them:

```c
volatile unsigned int tick_count;
__interrupt void timer_isr(void) { tick_count++; }
```

Running on `__zp_page_isr` (allocated by ln45 only when the program has an `__interrupt` function), a handler never touches the interrupted code's ZP parameters, temporaries or frame pointer; ROM calls made in a handler return to the handler's page through `__isr_depth`. Functions called both from a handler and from the main program must not use static allocation: mark them `#pragma cc45 recurse` (ln45 reports SAC functions reachable from an interrupt handler).

### `__naked`
No prologue, epilogue or return: the body is emitted as written, and the function must return itself.

```c
__naked void fast_routine(void) {
    __asm__("lda #$42");
    __asm__("sta $0400");
    __asm__("rts");
}
```

### `__regparm`
The first parameter is passed in A (`char`) or A:X (`int`, pointer); the others use the normal convention. Declare it on the prototype as well.

```c
__regparm int add(int a, int b) { return a + b; }   // a in A:X, b at $12
```

The caller loads the register argument last, after the others are stored. Under the ZP convention its slot in the parameter block stays free (in the example `b` is at `$12`); under the stack convention it is not pushed. Works with both conventions, with and without static allocation, and across modules.

### `__fastcall__`
Makes one function use the ZP convention in a file compiled with `-fno-zpcall`. Declare it on the prototype as well.

### `__abs`, `__far`
Address-space qualifiers on globals. `__abs` is the default. `__far` is a **reserved keyword** for possible future expansion: it is accepted and currently has no effect (the variable is an ordinary 16-bit address).

### `__striped`
`__striped` is a **reserved keyword** for possible future expansion (a striped array layout for cheaper indexing; see [striped-arrays](../architecture/striped-arrays.md)). It is accepted on array declarations and currently has no effect: the array has the ordinary layout. `#pragma cc45 no_striped` is not recognised.

### Nested Functions (GCC Extension)
A function defined inside another can use the enclosing function's locals and parameters through a static chain (`__static_chain`, ZP `$06`):

```c
int outer(int x) {
    int y = 10;
    int inner(int z) { return x + y + z; }
    return inner(5);          // 16 for outer(1)
}
```

## Intrinsics and Builtins

### CPU Registers (`__cpu`)

| Expression | Type |
| :--- | :--- |
| `__cpu.A`, `.X`, `.Y`, `.Z` | `unsigned char` |
| `__cpu.AX`, `.AY`, `.AZ`, `.XY`, `.SP` | `unsigned int` |
| `__cpu.Q`, `.AXYZ` | `unsigned long` |

### Processor Flags (`__flags`)
`__flags.Carry`, `.Zero`, `.Negative`, `.Overflow` read and write the flags as `_Bool`.

```c
__cpu.A = 0x42;
__cpu.AX = 0x1234;
__flags.Carry = 1;              // SEC
if (__flags.Carry) { ... }
```

Taking the address of a register or flag is an error ("Cannot take address of CPU register").

### DMA
`__dma_copy(dst, src, len)` and `__dma_fill(dst, len, val)` run an F018B DMA job built on the stack (see also `<dma.h>`). Known issue: `__dma_fill` puts the fill value in the job's source-high byte, so it currently fills with 0.

### GCC Builtins
- Variadic: `__builtin_va_start`, `__builtin_va_arg`, `__builtin_va_end` (`__builtin_va_list` is `void *`).
- Compile time: `__builtin_constant_p`, `__builtin_expect`, `__builtin_choose_expr`, `__builtin_offsetof`, `__builtin_unreachable`, `__builtin_trap`.
- Bits: `__builtin_clz`, `ctz`, `ffs`, `popcount`, `parity` (each with `l`/`ll` forms), `__builtin_bswap16`, `__builtin_bswap32`.
- Library aliases (call the stdlib function): `__builtin_printf`, `sprintf`, `vprintf`, `puts`, `putchar`, `malloc`, `calloc`, `realloc`, `free`, `alloca`, `strlen`, `strcmp`, `strcpy`, `strncpy`, `strcat`, `strchr`, `strstr`, `memcpy`, `memset`, `memmove`, `memcmp`, `abs`, `labs`, `exit`, `abort`, `setjmp`, `longjmp`, and the math functions (`sqrt`, `sin`, `cos`, `tan`, `atan`, `atan2`, `exp`, `log`, `log10`, `log2`, `pow`, `fabs`, `floor`, `ceil`, `round`, `trunc`, `fmod`, `fmin`, `fmax`, `fdim`, `copysign`, `ldexp`, `frexp`, `modf`, `signbit`, with `f` forms).
- `__builtin_return_address`, `__builtin_shuffle`, `__builtin_conjf`.

`__has_builtin()` in the preprocessor knows only a subset of these.

## Optimizations

What the current pipeline does (checked in generated code):

- **Static allocation (SAC)**: non-recursive functions keep parameters and locals in static storage (`_func__param_x`, `_func__local_N`) instead of a stack frame; calls within a file store the arguments there directly and enter at `_func__sac`.
- **Register allocation**: temporaries and `register` variables live in the ZP pool `$30`–`$E9`.
- **Inlining** of small functions (`-O2`, `inline`, `always_inline`).
- **Constant folding** of expressions and casts, and constant-address stores: `*(volatile unsigned char *)0xD020 = c` and stores through a pointer holding a known constant address become `sta $D020`.
- **Hardware math**: 16-bit multiplication, division and modulo use the MEGA65 math unit (`$D770`–`$D77F`).
- **Lazy frames**: a frame pointer (`$FD/$FE`) is set up only for functions that need a stack frame (recursion, variadic functions, `-fno-staticalloc`).
- **IR passes** (`-O1` and up): strength reduction (`x * 8` → shift, unsigned `x % 8` → `AND`), algebraic simplification, type narrowing, branch folding, CSE, loop-invariant code motion, copy propagation, address fusion. `-Roptir` shows what they changed.
- **Assembler optimizer**: `ca45` runs its peephole optimizer on the generated code (branch inversion, `JMP`→`BRA`, redundant loads, tail calls `JSR`+`RTS` → `JMP`, …).

`BBS`/`BBR` bit tests are not currently applied to typical code.

## Calling Conventions

Selected per file: ZP (default, `-fzpcall`) or stack (`-fno-zpcall`); `__fastcall__` makes a single function ZP. Independently, non-recursive functions use static allocation (SAC, `-fno-staticalloc` to disable). ln45 checks the convention of every cross-object call and generates a bridge thunk on a mismatch, in either direction (`-Wthunk` warns, `--no-thunks` makes it an error). See [calling-conventions](../architecture/calling-conventions.md).

### ZP Convention (default)
Arguments are packed left to right into the ZP parameter block starting at `$10`: `char` 1 byte, `int`/pointer 2, `long` 4, `float` 5. The caller stores them and does `JSR`. Indirect calls (function pointers) also pass arguments in ZP (the call is a patched `JSR`). A function whose parameters exceed 32 bytes, and every variadic function, uses the stack convention instead.

```
Caller:            Callee int add(int a, int b):
  lda #<a          a at $10/$11, b at $12/$13
  sta $10          (a SAC function first copies them to
  ...               _add__param_a/_add__param_b)
  jsr _add
  ; result in A/X
```

### Stack Convention (`-fno-zpcall`)
Arguments are pushed right to left, each as at least 2 bytes (`char` is pushed as 2), and the caller removes them after the call. A SAC callee copies them into its static storage on entry; a function with a stack frame reads them through the frame pointer. Calls to a SAC function in the same file skip the stack and store directly into its static storage.

### Return Values

| Type | Location |
|------|----------|
| `char` | A |
| `int`, pointer | A (low), X (high) |
| `long` | A, X, Y, Z (Q), low byte in A |
| `struct`, `union`, `float`/`double`, `long long` | Hidden pointer passed by the caller as the first parameter (`__sret`, `$10/$11` in the ZP convention); the callee writes the result there |

The same registers are used in both conventions.

### Variadic Functions
Variadic functions always use the stack convention and a stack frame, also when the file is compiled in ZP mode. `<stdarg.h>` defines `va_list` (`unsigned int`), `va_start`, `va_arg`, `va_end` and `va_copy`. The arguments matching `...` get C's default promotions: a `char` or `_Bool` is passed as an `int` (zero-extended for `unsigned char`, sign-extended for `signed char`), so read it with `va_arg(ap, int)`.

```c
#include <stdarg.h>

int vsum(int count, va_list args) {
    int s = 0;
    while (count--) s += va_arg(args, int);
    return s;
}

int sum(int count, ...) {
    va_list args;
    va_start(args, count);
    int r = vsum(count, args);
    va_end(args);
    return r;
}
// sum(3, 0x1000, 0x200, (char)3) == 0x1203
```

### Recursion
A function on a call cycle within its file (direct or mutual recursion) automatically gets a stack frame and a warning (silenced by `#pragma cc45 recurse`). ln45 rejects SAC functions it finds on a cross-module cycle.

### Function Metadata
Each function's `endproc` is preceded by metadata that ca45 stores in the `.o45` and ln45 uses: `.func_flags` (`zp_call`/`stack_call`, `static_alloc`, `leaf`, `isr`), `.param_sizes`, `.reg_clobbers`, `.flag_clobbers` and `.frame_size`. Generated code also carries `.loc "file", line` directives and `; .debug_var` comments.

### Libraries

| Convention | Library |
|------------|---------|
| ZP (default) | `c45.lib` |
| Stack (`-fno-zpcall`) | `c45_stack.lib` |

## Known Limitations

- `__far` and `__striped` are reserved keywords with no effect yet.
- `#pragma encoding` does not affect string literals that initialize global pointers.
- `sizeof` of an `__unpacked` struct omits the tail padding.
- Inline assembly cannot name non-`register` locals; file-scope `asm` is dropped.

## Common Use Cases

### Single-File Program

```bash
cc45 game.c -o game.prg        # BASIC-startable PRG; RUN it
```

### Multi-Module Project

```c
// main.c
extern void init_graphics(void);
extern int run_game_loop(void);
int main(void) { init_graphics(); return run_game_loop(); }

// graphics.c
void init_graphics(void) { /* set up VIC-IV */ }

// game.c
int run_game_loop(void) { return 0; }
```

```bash
cc45 -c main.c -o main.o45
cc45 -c graphics.c -o graphics.o45
cc45 -c game.c -o game.o45
ln45 -basic -o game.prg main.o45 graphics.o45 game.o45 -L lib/build -l c45.lib
```

`ln45` finds `c45.lib` through `-L` or `CC45_LIB` (or give the library's path). Objects compiled with `-fno-zpcall` link with `c45_stack.lib`.

### Hardware Access

```c
void set_border(unsigned char c) {
    *(volatile unsigned char *)0xD020 = c;   // compiles to sta $D020
}

int main(void) {
    set_border(0);
    return 0;
}
```

`<mega65.h>` provides struct overlays of the VIC-IV, SID, CIA, DMA and other registers.

### A Library of Your Own

```bash
cc45 -c util.c -o util.o45
cc45 -c mathx.c -o mathx.o45
ar45 c mylib.lib util.o45 mathx.o45

cc45 -c game1.c -o game1.o45
ln45 -basic -o game1.prg game1.o45 -l mylib.lib -L lib/build -l c45.lib
```

### Makefile

```makefile
CC45   = cc45
LN45   = ln45
CFLAGS = -O2
LIBDIR = /path/to/m65compiler/lib/build

SRCS = main.c util.c graphics.c
OBJS = $(SRCS:.c=.o45)

game.prg: $(OBJS)
	$(LN45) -basic -o $@ $^ -L $(LIBDIR) -l c45.lib

%.o45: %.c
	$(CC45) $(CFLAGS) -c $< -o $@

clean:
	rm -f $(OBJS) game.prg

.PHONY: clean
```

### Inspecting the Output

```bash
cc45 -S prog.c -o prog.s45         # generated assembly
cc45 -c prog.c && nm45 prog.o45    # symbols (e.g. _main, _main__sac, _f__param_x)
objdump45 -d prog.o45              # disassembly with source lines
```
