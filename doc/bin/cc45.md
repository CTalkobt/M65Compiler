# cc45 — Mega65 C Compiler

`cc45` is a C compiler for the MEGA65 (45GS02). It compiles one C file to `ca45` assembly, and by default goes on to assemble it with `ca45` and link it with `ln45` into a BASIC-startable PRG.

Behaviour described here was checked against cc45 v1.0.4 (`cc45 --version`); examples were compiled with `./bin/cc45` and, where a result is given, run on xemu (`xemu-xmega65 -prgmode 65`), reading the exit status that crt0 leaves at `$FD/$FE`.

## Quick Start

```bash
cc45 hello.c                  # hello.prg: compile, assemble, link (10 SYS 8205)
cc45 hello.c -o hello.prg     # same, explicit output name
cc45 -c hello.c               # hello.o45 relocatable object
cc45 -S hello.c               # hello.s45 assembly
cc45 -E hello.c -o hello.i    # preprocess only
```

The one-step build links against the standard library of the selected calling convention (`c45.lib`, or `c45_stack.lib` with `-fno-zpcall`), looked up in `bin/../lib/build`, then `bin/../lib/cc45`; if neither exists it passes `-l <name>` to `ln45`, which searches `CC45_LIB`. The library's `crt0` member is the startup code.

## Command-Line Usage

```bash
cc45 [options] <input_file.c>
```

Exactly one input file is compiled (the last non-option argument). An unrecognised option starting with `-` (for example `-Wall`) gives *"cc45: warning: unknown option '-Wall' ignored"*.

### Options

| Option | Description |
|--------|-------------|
| `-E` | Preprocess only. The output goes to the `-o` file, or to `<input>.prg` when no `-o` is given (there is no stdout output). |
| `-S` | Stop after code generation. Writes the standalone assembly form (a small startup stub at `* = $2000`, or the `--prg-base` address), meant for inspection. |
| `-c` | Compile and assemble to a relocatable `.o45` object. |
| `-g` | In a one-step build (`-o prog.prg`), also write `prog.dbg`, the program's debug information (ln45 `-g`; ln45.md, Debug File). Objects carry their debug records with or without it. |
| `-Wl,<a>,<b>`, `-Xlinker <a>` | In a one-step build, pass `<a>` and `<b>` to ln45 (`-Wl,` splits at the commas): `-Wl,--section,SCREEN=0x800`, `-Wl,-m` (its map on the output; with `-Wl` options ln45's output is shown), `-Wl,-M,prog.map`. |
| `-o <file>` | Output file. Its extension selects the stage: `.s`/`.s45` assembly (as `-S`), `.o45` object (as `-c`), anything else a program. Defaults: `<input>.prg`, `<input>.o45` with `-c`, `<input>.s45` with `-S`. |
| `--prg-base <hex>` | Link a plain PRG loaded at that address (hex digits, e.g. `3000` or `0x3000`; no `$`) instead of the BASIC-startable PRG. Start it with `SYS`. |
| `-O<n>` | Optimization level, a digit `0`–`9` (default `2`). See [Optimization Levels](#optimization-levels). `-Os` / `-Osize` is `-O2` with `-fmul-call` and `-fno-rotate-loops` (size over speed), `-Ospeed` is `-O3` (which also turns `-fzp-args` off: the parameters copied inline on entry, about 300 cycles a call faster, #359); any other suffix is `-O0`. |
| `-I<path>`, `-I <path>` | Add an include directory (searched after the default directory; see [Include Search](#include-search)). |
| `-D<name>[=<val>]` | Define a preprocessor macro (`-DNAME` defines it as `1`). |
| `-v` | Log to stderr, each line `[cc45:INFO] …`: the stages (`Compiling x.c (O2)...`, `Parsing...`), informational notes (`SAC thunk generated for ...`, `note: devirtualized N virtual call(s)`); ca45 and ln45 run with the same flag (`[ca45:INFO] …`, `[ln45:INFO] …`) and their summaries are shown (`Object file: ...`, `Linked ...`). Without it cc45 prints only warnings and errors. |
| `-vv`, `-vvv`, `-vvvv`, `-v0` | More detail: `-vv` (DEBUG) the sub-steps and IR passes, the ca45/ln45 command lines; `-vvv` (DEEP) internals (ln45's relocations); `-vvvv` (TRACE) every token. Cumulative (`-v -v` = `-vv`), at most 4; `-v0` off. The level never changes the program built. Format and levels: `include/Logger.hpp`, the same in ca45 and ln45. |
| `-fzpcall` | ZP calling convention (default). Defines `__CC45_ZPCALL__`. |
| `-fno-zpcall` | Stack calling convention; links `c45_stack.lib`. Defines `__CC45_STACK__`. |
| `-fstaticalloc` / `-fno-staticalloc` | Static allocation (SAC) of locals of non-recursive functions (default on). Also defines `__CC45_STATIC_ALLOC__`. |
| `-fzp-locals` / `-fno-zp-locals` | The most used variables of static-allocation functions that make calls in a base-page block of their own (`$80`–`$E9`, placed by ln45; default on). When a program's call chains need more than that area, ln45 warns (`base-page storage: ...`) and calls the functions that share bytes through save/restore wrappers; `-fno-zp-locals` avoids that. |
| `-floop-idioms` / `-fno-loop-idioms` | Copy and fill loops of arrays as calls of `memmove` / `memset` (off by default, at every `-O` level). A `for` loop with a local integer variable stepped by `++` / `--` against a bound known before it runs, whose body only copies elements (`t[i + c] = s[i + d]`, the same type) or fills them with a constant `memset` can store, between arrays (not pointers, not `volatile`); an inner loop over whole rows is a row element; a shift within one array only in the direction `memmove` gives the loop's result. Only loops of two arrays or more, a row loop, or elements of 3 bytes or more are changed, and the loop variable gets the value the loop leaves. In pfest the calls' setup cost about what the loops did (#323), so it is not on by default. |
| `-fmul-call` / `-fno-mul-call` | Multiplications as calls of the library's `__mul16` / `__mul32` (`stdlib_asm/divmod.s45`: 3–11 bytes a use, 5 with a byte constant factor (`__mul16y`, the factor in Y), instead of the hardware-multiplier sequence's 22 / 50, but a `jsr`/`rts` slower). By default a multiply outside loops (also an element address's index times its size) is a call and one inside a loop is inline (a constant factor outside loops is shifts and adds only when they are no bigger than the call); `-fmul-call` (and `-Os`) makes every one a call, `-fno-mul-call` none. |
| `-fzp-locals-max=N` | Bytes of such a block (default 16, the library 8; 0 = none). Larger blocks hold more variables in ZP but fit less often along deep call chains. |
| `-fzp-plan=FILE` | The blocks' variables as ln45 chose them for the whole program (`ln45 --zp-plan-out=FILE` on a first build; [The program-wide plan](ln45.md#the-program-wide-base-page-plan)): a function the plan lists takes exactly its variables, with no cap and even with `-fno-zp-locals`; a function it does not list keeps the rule above. Compile every file of the program with the same plan: blocks that no longer fit (a stale plan, a file built without it) fall back to ln45's save/restore wrappers, which cost bytes and cycles. |
| `-fstack16` / `-fno-stack16` | 16-bit CPU stack topped at `$BFFF` (default) / the ROM's 8-bit page-1 stack. See [CPU Stack](#cpu-stack). |
| `-fstack-top=<addr>` | Top byte of the 16-bit CPU stack (`0x9FFF`, `$9FFF` or decimal). |
| `-ffunction-sections` | With `-c`: a section per function, global or static variable, string literal and static-allocation block (`.split`; ca45 `-ffunction-sections`), so ln45 drops what a library member's users do not reach — code, data and BSS. In a one-step build (`cc45 x.c -o x.prg`) ln45 also trims the program itself (`--gc-inputs`): unreached functions and their data go. A block holding aligned locals stays with the object. `-fno-function-sections` turns it off. |
| `-fstack-size=<n>` | The CPU stack's share below its top (default 4096; `$400`, `0x400` or decimal): `malloc`'s automatic heap ends `n` bytes below the stack top. Set by the module containing `main` (`__stack_size`); ln45 `--stack-size=` does the same at link time. A large program that reaches past `$B000` gets a heap with a smaller share. |
| `-foverlay=<name>` | The unit's code goes in the code overlay `<name>` (as `#pragma cc45 overlay(name)`): ln45 links it to run in the overlay region (copied) or window (mapped) and makes it visible when a call needs it. See [Code Overlays](#code-overlays). |
| `-fbss-fill=<byte>` | The byte crt0 fills BSS with at startup (default `$00`; `0xFF`, `$FF` or decimal). Set by the module containing `main` (`__bss_fill`); a non-zero value breaks C's zero initialization on purpose, to find code that relies on it. ln45 `--bss-fill=` does the same at link time. |
| `-finline-functions` | Inline small functions (also enabled by `-O2` and up). |
| `-f<optimization>` / `-fno-<optimization>` | Turn one optimization on or off, e.g. `-fno-cse`, `-floop-invariant-code-motion`, `-fno-tail-call-optimization`. See [optimizations.md](../architecture/optimizations.md#optimization-switches) for the names. |
| `--future` | Warn when an optimization that is not implemented yet is requested (`-fprocedure-inlining`, `#pragma cc45 optimize(cross-function-inlining)`, …); without it such requests are ignored silently. |
| `-Roptir` | Report what the IR optimization passes change, on stderr. |
| `-Rcodegen` | Annotate the assembly (`-S`, `--save-temps`) with why each instruction is there: the IR operation, its virtual register and where it lives, the value (`lda #2  ; [CONST → v2(I8,ZP:$22) val=2]`, `ldy $34  ; [the index ((p),y: no address built)]`). The code is the same as without it. With `CC45_OPMARK=1` (a `; @op` line before each IR instruction's code) and `CC45_DUMP_IR=1`, the tools for finding where code size goes. |
| `-fmax-inline-ir-size=<N>` | Largest function (in IR instructions) that is inlined; default 11. |
| `-fmax-unroll-bytes=<N>` | Largest estimated code size of an unrolled vector operation or (with `-floop-unrolling`) loop; default 128. |
| `-fsigned-default` / `-fno-signed-default` | Plain `char`/`short`/`int`/`long` are signed (standard C) / unsigned (default). |
| `-funsigned-char` / `-fsigned-char` | With `-fsigned-default`, keep plain `char` unsigned / make it signed. |
| `-fimplicit-function-declaration` / `-fno-…` | Allow calls to undeclared functions with a warning (default: error). |
| `-V`, `--version` | Print the version and exit. |
| `-?`, `--help` | Print a short help and exit. |

`--save-temps` keeps the intermediate assembly `temp_<pid>.s45` (written in the current directory; cc45 prints its name), the input it gives ca45. The following options are accepted but currently have **no effect**: `--pragma <text>` and `--emit-ir`. To see the optimized IR, set `CC45_DUMP_IR=1` (printed to stderr).

### Optimization Levels

| Level | Effect |
|-------|--------|
| `-O0` | AST constant folding and the always-on code generation and assembler optimizations; only `inline` functions (and `-finline-functions`) are inlined. |
| `-O1` | Adds the IR passes: strength reduction, algebraic simplification, type narrowing, branch folding, CSE, loop-invariant code motion, copy propagation, address fusion. |
| `-O2` (default), `-O3` | Additionally inlines small functions automatically (up to `-fmax-inline-ir-size`). `-O3` currently produces the same code as `-O2`. |
| `-O4` and up | Adds loop interchange (`-floop-interchange`) and loop unrolling (`-floop-unrolling`). `-O5`…`-O9` currently produce the same code as `-O4`. |

`-f<name>` / `-fno-<name>` switch single optimizations on top of the level, and `#pragma cc45 optimize(...)` switches IR passes per function; see [optimizations.md](../architecture/optimizations.md).

### Exit Codes

| Code | Stage |
|------|-------|
| 0 | Success |
| 1 | Preprocessor error (e.g. `#include` not found, `#error`) |
| 43 | Parse error |
| 85 | AST optimization failure |
| 127 | Code generation / semantic error (undeclared identifier, invalid construct) |
| exit status of `ca45` / `ln45` (normally 1) | Assembler or linker error |
| 253 | Internal/pipeline error (e.g. input file cannot be opened) |

### Configuration File

Options are read from `~/.config/m65/cc45.conf` (`cp45.conf` when run as `cp45`) before the command line, one or more per line; `#` starts a comment line. Later options override earlier ones, so command-line flags win. See [CONFIGURATION.md](CONFIGURATION.md).

```
-O2
-finline-functions
```

### Environment Variables

| Variable | Description |
|----------|-------------|
| `CC45_INCLUDE` | Colon-separated include directories, searched before the standard headers (`bin/../lib/include`, or `bin/../include/cc45` in an installed tree) and the `-I` directories. |
| `CC45_LIB` | Colon-separated library directories used by `ln45` (for the one-step build only when the library is not found next to `bin/`). |
| `CC45_DUMP_IR` | Non-zero: print the optimized IR to stderr. |
| `CC45_OPMARK` | Set: before each IR instruction's code, a comment `; @op <op> <type> <operands>`, for `src/test/opsize.py` (code bytes by IR operation, through `ca45 --source-map`). |
| `CA45_OPTIMIZE`, `CA45_WARNINGS` | Read by `ca45` when cc45 runs it. |

### Include Search

`#include "f"` and `#include <f>` search the same list, in order: the directory of the including file, `CC45_INCLUDE`, the standard headers, then the `-I` directories; a file under `-I` therefore cannot override a standard header of the same name. The standard headers are the first of `bin/../lib/include` (the build tree) and `bin/../include/cc45` (an installed tree: `make install` puts `bin/` in `PREFIX/bin` and the headers in `PREFIX/include/cc45`) that has a `stdio.h`, so both a build tree and an installed toolchain work without `CC45_INCLUDE`.

## Compilation Pipeline

1. **Preprocess** (`cp45`, integrated): macros, includes, conditionals; `#pragma cc45 …` lines become `__asm__(".directive")` statements. A unit that uses `long long`, `int64_t`, `__int64`, `__int128`, `__int(N)` or `__uint(N)` gets `<intwide.h>` included automatically.
2. **Parse** to an AST, then AST constant folding and function analysis.
3. **IR generation and optimization** (IRBuilder): inlining, static allocation, register allocation, IR passes.
4. **Code generation** (IRCodeGen) to `ca45` assembly with `proc`/`endproc` blocks, `.loc` source-line directives and per-function metadata.
5. **Assemble** with `ca45 -c` and **link** with `ln45 -basic` (or `-prg -t <base>`).

## Features

[examples/c/ext_tour](../../examples/c/ext_tour/main.c) (its screen: [doc/examples](../examples/README.md#ext_tour)) shows the extensions to C in one program, a short function each with its check: struct methods and operators, `break N`, `continue <value>`, `repeat`, `__likely`/`__unlikely`, `__pure`, `__zp`, `__cpu`/`__flags`, `__bit`/`__bits`, `__jsr`, `__fastcall__`, `#pragma encoding`, `optimize(off)`, `__noescape`, GCC vectors, `long long`/`__int(N)`, `_Complex`, `__builtin_*`, `#pragma weak` and `push_macro`/`pop_macro`. Its comment names the examples that show the rest (nested functions, computed goto, `__interrupt`, overlays, `__far`, …).

- **Types**: `char`, `short`, `int`, `long`, `long long`, `float`, `double`, `long double`, `_Bool` (a value stored in it is 0 or 1), `__bit` (booleans packed 8 to a byte, see [Packed booleans](#packed-booleans-__bit)), `__fixed(I, F)`, `__fixed8_8`, `__fixed16_16` (see [Fixed point](#fixed-point-__fixedi-f)), `signed`/`unsigned` variants, pointers, arrays (multi-dimensional), `struct`, `union` (including anonymous members), `enum`, bitfields (`char` up to 8 bits, `short`/`int` 16, `long` 32; a wider one is an error, as is a `long long` bitfield), function pointers, `void *`, `_Complex`, GCC vectors, `__int(N)`.
- **Signedness**: plain `char`/`short`/`int`/`long` are **unsigned** unless declared `signed`; `-fsigned-default` or `#pragma cc45 signed_default` selects standard C (`#pragma cc45 unsigned_default` switches back). `x < 0` on an unsigned value warns. A variable of a plain integer type (no `signed`/`unsigned` written, not a typedef) that is unsigned by this default warns when a negative constant is stored in it or compared with it, and on `x < 0` / `x >= 0`, before constant folding can remove the code: `int r; for (r = -1; r <= 1; r++)` gives `'r' is unsigned (plain int is unsigned in cc45): -1 becomes 65535; declare it 'signed' (or use -fsigned-default)`. An explicit `unsigned` (`unsigned x = -1`, all ones) does not warn.
- **Declarations**: `typedef`, `static`, `extern`, `register`, `auto`, `volatile`, `const`, `restrict`, qualifiers in any order, implicit `int` (`static max;`).
- **`restrict`** (also `__restrict`, `__restrict__`): on a pointer parameter (`char *restrict d`, `int a[restrict]`), the optimizer takes the C meaning: what it points to is reached only through it (and pointers made from it) while the function runs. Loads through it are reused across stores into globals and through other `restrict` parameters (CSE) and hoisted out of loops that do not write that object (LICM): `out[i] = in[i] * *k` reads `*k` once. A program that breaks the promise (passes overlapping arrays) gets the wrong values, as in C. Not used on locals, globals or struct members; a parameter the function assigns or takes the address of, or one inlined into its caller, is treated as an ordinary pointer. See [optimizations.md](../architecture/optimizations.md#ir-passes).
- **Initializers**: scalar, aggregate, designated (`{.x = 1}`, `{[2] = 3}`), flexible array members, string-literal concatenation, compound literals (`(int[]){1, 2}[1]`, `(struct point){.x = 7}`), a file's bytes with `#embed "f.bin"` or `#include binary [char|word|long] "f.bin"` (see [cp45](cp45.md#embed-and-include-binary)).
- **Operators**: all C operators, `sizeof`, `_Alignof`, `_Generic`, comma, casts, GCC Elvis `a ?: b`, `typeof`/`__typeof__`, statement expressions `({ ... })`, `&&label` and `goto *p`, `__real__`/`__imag__`.
- **Statements**: `if`/`else`, `switch` with GCC case ranges (`case 'A' ... 'Z':`), `while`, `do`, `for` with declarations, `break`, `continue`, `goto`, labels, `return`, `repeat(N)` unrolling, `asm`/`__asm__`, `_Static_assert`.
- **Functions**: prototypes, variadic functions (`<stdarg.h>`), `inline`, `_Noreturn`, GCC nested functions, `__interrupt`, `__naked`, `__regparm`, `__fastcall__`.
- **Floating point**: `float`, `double` and `long double` are all the CBM 40-bit format (5 bytes), computed by the BASIC 65 ROM routines; see [stdlib](../architecture/stdlib.md).
- **Struct extensions**: methods, single inheritance, `virtual`, `final`, operator overloading (see [Object-Oriented Struct Extensions](#object-oriented-struct-extensions)).
- **Weak symbols**: `#pragma weak` / `#pragma cc45 weak` before a definition. A weak function is a default the link may replace, so cc45 assumes nothing of its body at the calls in its own file: it is never inlined, and those calls go through its plain entry as a call from another file would (not its `__sac` entry or static storage). (A struct method's weak copies are all alike: they are inlined.)
- **MEGA65 extensions**: `__cpu`/`__flags` register access, `__bit`/`__bits` (bits of a variable, see [below](#bits-of-a-variable-__bit-__bits)), `__jsr`/`__jmp` (a routine called with registers, see [below](#calling-an-address-__jsr-__jsr_raw-__jmp)), `__dma_copy`/`__dma_fill`, string encodings (`@"..."`, `p"..."`, `s"..."`, `a"..."`, `#pragma encoding`), `__far` functions (kept in far memory, see [Code Overlays](#code-overlays)), far and near pointers (`T __far *p`, `T __near *p`, see [Far pointers](#far-pointers)); `__far` on a non-pointer variable and `__striped` are reserved for future expansion.

## Language Syntax (BNF)

A simplified grammar of the statements and expressions cc45 accepts.

### Statements

```bnf
<statement> ::= <compound-statement>
              | <expression-statement>
              | <selection-statement>
              | <iteration-statement>
              | <jump-statement>
              | <labelled-statement>
              | <declaration>
              | <static-assert>

<compound-statement>   ::= "{" <statement>* "}"
<expression-statement> ::= <expression>? ";"
<labelled-statement>   ::= <identifier> ":" <statement>

<selection-statement> ::= "if" "(" <expression> ")" <statement> ( "else" <statement> )?
                        | "switch" "(" <expression> ")" <statement>
                        | "case" <constant> ( "..." <constant> )? ":" <statement>?
                        | "default" ":" <statement>?

<iteration-statement> ::= "while" "(" <expression> ")" <statement>
                        | "do" <statement> "while" "(" <expression> ")" ";"
                        | "for" "(" ( <expression-statement> | <declaration> ) <expression>? ";" <expression>? ")" <statement>
                        | "repeat" "(" <integer-constant> ")" <statement>
                        | "repeat" "(" <type-name> <identifier> "," <integer-constant> ")" <statement>

<jump-statement> ::= "return" <expression>? ";"
                   | "break" <integer-constant>? ";"
                   | "continue" ";"
                   | "continue" ( <constant> | "default" ) ";"
                   | "goto" <identifier> ";"
                   | "goto" "*" <expression> ";"
                   | ( "asm" | "__asm__" ) "volatile"? "(" <string-literal> ")" ";"

<static-assert> ::= "_Static_assert" "(" <constant-expression> "," <string-literal> ")" ";"
```

### Expressions

```bnf
<expression>     ::= <assignment> ( "," <assignment> )*
<assignment>     ::= <unary> <assignment-op> <assignment> | <conditional>
<assignment-op>  ::= "=" | "+=" | "-=" | "*=" | "/=" | "%=" | "&=" | "|=" | "^=" | "<<=" | ">>="
<conditional>    ::= <logical-or> ( "?" <expression>? ":" <conditional> )?
<logical-or>     ::= <logical-and> ( "||" <logical-and> )*
<logical-and>    ::= <bitwise-or> ( "&&" <bitwise-or> )*
<bitwise-or>     ::= <bitwise-xor> ( "|" <bitwise-xor> )*
<bitwise-xor>    ::= <bitwise-and> ( "^" <bitwise-and> )*
<bitwise-and>    ::= <equality> ( "&" <equality> )*
<equality>       ::= <relational> ( ("==" | "!=") <relational> )*
<relational>     ::= <shift> ( ("<" | ">" | "<=" | ">=") <shift> )*
<shift>          ::= <additive> ( ("<<" | ">>") <additive> )*
<additive>       ::= <multiplicative> ( ("+" | "-") <multiplicative> )*
<multiplicative> ::= <unary> ( ("*" | "/" | "%") <unary> )*
<unary>          ::= ( "!" | "~" | "-" | "+" | "*" | "&" | "++" | "--" | "__real__" | "__imag__" ) <unary>
                   | "&&" <identifier>
                   | "sizeof" <unary> | "sizeof" "(" <type-name> ")"
                   | ( "_Alignof" | "__alignof__" ) "(" <type-name> ")"
                   | "(" <type-name> ")" <unary>
                   | <postfix>
<postfix>        ::= <primary> ( "[" <expression> "]" | "(" <argument-list>? ")" | "." <identifier>
                                | "->" <identifier> | "++" | "--" )*
<primary>        ::= <identifier> | <constant> | <string-literal>+
                   | "(" <expression> ")"
                   | "(" "{" <statement>* "}" ")"
                   | "(" <type-name> ")" "{" <initializer-list> "}"
                   | ( "typeof" | "__typeof__" ) "(" ( <expression> | <type-name> ) ")"
                   | "_Generic" "(" <assignment> "," <generic-association> ( "," <generic-association> )* ")"
                   | "__builtin_va_start" "(" <expression> "," <identifier> ")"
                   | "__builtin_va_arg" "(" <expression> "," <type-name> ")"
                   | "__builtin_offsetof" "(" <type-name> "," <identifier> ")"
<generic-association> ::= ( <type-name> | "default" ) ":" <assignment>
<argument-list>  ::= <assignment> ( "," <assignment> )*
```

## Statement Descriptions

### Selection Statements (`if`, `else`, `switch`)
- **`if` / `else`**: standard C.
- **`__likely(x)` / `__unlikely(x)`**: (extension) the value of `x`, expected true / false. On the condition of an `if` (also under `!`), the branch not expected to run is placed after the function's return (`-freorder-blocks`, from `-O1`), so the expected path falls through the conditional branches (a taken branch costs a cycle more) and into the `rts`; the unexpected one branches back. `__builtin_expect(x, c)` with an integer constant `c` is the same: `__likely(x)` when `c` is non-zero, `__unlikely(x)` when it is 0 (with any other `c` there is no hint). Elsewhere (in `&&`/`||`, a loop condition, `?:`) a hint has no effect.
  ```c
  if (__unlikely(err)) {          // after the rts: the common path is
      report(err);                // a not-taken bne and the code after it
      return;
  }
  ```
- **`switch`**: transfers control to the matching `case` label; control falls through to the next case unless a `break` intervenes.
    - **`case <min> ... <max>`**: (GCC extension) an inclusive range, for `char`, `int` and `long`. Ranges and single cases mix freely.
    - **`continue <value>` / `continue default`** (extension): `continue <value>` jumps to the `case` of the innermost `switch` that `<value>` selects, as if the `switch` ran again with that value (any expression, so a computed state works too; ranges and `default` apply as usual). `continue default` jumps to `default`, or past the `switch` if it has none. A plain `continue;` still belongs to the enclosing loop.
      ```c
      switch (state) {
      case START: init();  continue RUN;
      case RUN:   if (step()) continue RUN; continue STOP;
      case STOP:  finish(); break;
      }
      ```

### Iteration Statements (`while`, `do`, `for`, `repeat`)
- **`while`**, **`do`**, **`for`**: standard C, including `for (int i = 0; ...)`. `break` leaves the innermost loop or `switch`; `continue` goes to the condition (`while`, `do`) or the increment (`for`) of the innermost loop.
- **`break N`**: (extension) leaves the N innermost loops and `switch`es (a `switch` counts as a level, `repeat` does not: it is not a loop). N is an integer literal from 1 to 255; `break 1` is `break`. More levels than enclose the `break` (within its function) is an error. One jump, instead of a `goto` or a flag tested by every loop; the VLAs of the loops it leaves are released.
  ```c
  for (y = 0; y < 25; y++)
      for (x = 0; x < 40; x++)
          if (screen[y * 40 + x] == target)
              break 2;                    // x, y where it was found
  ```
- **`repeat`**: (extension) compile-time unrolling. The body is copied N times with no counter or branch. N must be an integer constant.
    - `repeat(N) { body }`
    - `repeat(type var, N) { body }`: `var` is a constant 1, 2, …, N in the successive copies.

```c
repeat(8) { *dst++ = *src++; }                  // 8 copies, no loop
repeat(unsigned char x, 4) { buf[x - 1] = x; }  // buf = {1, 2, 3, 4}
```

### Jump Statements
- **`return`**: see [Return Values](#return-values) for the registers used.
- **`goto <label>`**, **`goto *expr`** with **`&&label`** (computed goto). Labels are function-scoped.
- **`asm` / `__asm__`**: see [Inline Assembly](#inline-assembly).

## Inline Assembly

`asm("...")` / `__asm__("...")` (optionally `__asm__ volatile (...)`) copies the string into the function's assembly. `\n` in the string separates lines; adjacent string literals are concatenated (`asm("lda #1\n" "rts")`), and there is no GCC operand syntax (`: "r"(x)`).

At file scope, `asm("...")` is module-level assembly: cc45 emits it after the module's `.extern` list, before the functions, and switches back to the code segment after it. It can define data (`.segment "data"`), equates and whole functions in assembly; a symbol it defines (`sym:` or `sym =`) gets no `.extern` from a C declaration of it (`test_file_asm_xemu.c`):

```c
asm("    .segment \"data\"\n"
    "    .global _tbl\n"
    "_tbl: .byte 7, 9, 11\n");
asm(".global _asm_seven\n_asm_seven:\n lda #7\n ldx #0\n rts");
extern unsigned char tbl[3];
int asm_seven(void);
```

```c
int main(void) {
    asm("lda #$34\n ldx #$12");
    return __cpu.AX;            // 0x1234
}
```

After an `asm` statement the compiler assumes nothing about the registers. Local labels in inline assembly use the `@name` form (they are scoped to the function's `proc`).

### Reaching C Variables

| C object | Assembly name | Notes |
|----------|---------------|-------|
| Global `total` | `_total` | Absolute address. |
| `static` global | `_total` | Not exported from the object. |
| `static` local `calls` in `counter` | `__counter__local_calls` | |
| Function `main` | `_main` | A `static` function is `_name__<file>` (e.g. `_helper__util` in `util.c`). |
| Parameter `val` (ZP convention) | `@_p_val` | The parameter's ZP slot (`$10`…). Valid until the function makes a call. |
| Parameter `val` of a SAC function | `_func__param_val` | The function's static copy (both conventions). |
| `register` local `i` | `@_l_i` | Its zero-page address (`$30`…). |

Other locals and stack-frame parameters have no stable symbolic name for inline assembly (SAC locals are numbered, `_func__local_N`; frame offsets change). Pass such values through a global or a `register` variable.

```c
volatile int g_value;

void store_to_global(int val) {
    __asm__("lda @_p_val");       // ZP slot of val ($10/$11)
    __asm__("ldx @_p_val+1");
    __asm__("sta _g_value");
    __asm__("stx _g_value+1");
}
```

Do not use the old `ldax _p_val, sp` / `lda.sp` stack-relative forms: parameters are no longer on the stack in the default modes and the result is wrong. Hand-written code must not address the CPU stack as `$0100,x` either (see [CPU Stack](#cpu-stack)).

## Zero Page Layout

The program runs on a private base page (`__zp_page`, see [Memory Layout](#memory-layout-and-startup)), so these addresses are offsets within that page, not the ROM's page 0:

| Address | Use |
|---------|-----|
| `$06`–`$07` | `__static_chain` (nested functions) |
| `$08`–`$0F` | `__zp_scratch` … `__zp_scratch4` (compiler and runtime scratch) |
| `$10`–`$2F` | ZP calling-convention parameter block (32 bytes) |
| `$30`–`$7F` | Register allocator pool: temporaries and `register` variables |
| `$80`–`$F1` | Base-page blocks: the most used variables of static-allocation functions that make calls, one block per function, placed by ln45 (`-fno-zp-locals` turns them off), and `__zp` variables at the top. The area starts lower, at the end of the part of the pool the program uses (ca45's `cc45.bptop`): `$46` in a program whose functions need the pool up to `$45` |
| `$F2`–`$F5` | 32-bit temporary |
| `$F6`–`$FC` | Library temporaries (float code `$F6`–`$FA`; `puts` and frames over 255 bytes `$FB`/`$FC`) |
| `$FD`–`$FE` | Frame pointer of functions that use a stack frame |

`-D cc45.zeroPageStart=…` and `-D cc45.zeroPageAvail=…` only define preprocessor macros; the layout above is fixed.

## Memory Layout and Startup

### Startup (crt0)

`ln45` takes the startup code from the library's `crt0` member. Before `main` it:

1. saves the caller's stack pointer and flags, and enables the MEGA65 I/O registers (`$47`, `$53` to `$D02F`);
2. sets the exit status at ROM page-0 `$FD/$FE` to `$FFFF` ("never reached exit");
3. moves the base page to `__zp_page` (`lda #>__zp_page / tab`);
4. switches to the 16-bit CPU stack at `__stack_top` (unless `-fno-stack16`), restoring the caller's I flag;
5. fills BSS (`__bss_start` to `__bss_end`, which includes the private base page) with `__bss_fill` (0 unless `-fbss-fill=` / ln45 `--bss-fill=`), using a DMA fill job;
6. calls `_init_features` (a weak `rts`; define your own `init_features()` to add initialization);
7. calls `main` with `argc`/`argv` from the BASIC line that ran the program (see below), or `argc = 0`, `argv = NULL` when `main` takes no parameters.

**Command-line arguments.** When `main` is defined with parameters (`int main(int argc, char **argv)`), cc45 links the library's `__mainargs` (about 300 bytes; programs with `main(void)` don't get it). It reads the line typed at BASIC's `READY.` prompt, which BASIC 65 keeps in its input buffer at `$0200`:

```
RUN : P1, P2                     argc 3: "", "P1", "P2"
RUN "MYPROG" : P1, "A, B"        argc 3: "MYPROG", "P1", "A, B"
RUN "MYPROG" :REM TOTAL, STOP    argc 3: "MYPROG", "TOTAL", "STOP"
```

- `argv[0]` is the name in `RUN "NAME"`, or `""`; `argc` is at least 1, and `argv[argc]` is `NULL`.
- The arguments follow the first `:` outside quotes; a `REM` right after it is skipped. They are separated by commas and trimmed of spaces; quotes group text (commas, colons) and are removed. They end at the end of the line or at a `:` outside quotes; at most 16.
- **Use `:REM` when an argument contains a BASIC keyword**: BASIC tokenizes the line when RETURN is pressed, and only text after `REM` (or inside quotes) is left as typed. Without it, `TOTAL` arrives as the `TO` token (`$A4`) followed by `TAL`, and `ONE` as the `ON` token followed by `E`.
- The text is PETSCII as BASIC stored it (letters typed in the default mode are `$41`-`$5A`, which cc45 string literals write as lowercase: `strcmp(argv[1], "p1")`). It is copied before `main` runs, since the next line of keyboard input overwrites `$0200`.
- A program started some other way (`SYS`) gets `argc` 1 and `argv[0]` `""`.

When `main` returns, or `exit()` is called, `__exit` sets the base page back to 0, stores the exit status (`main`'s return value, `exit()`'s argument, `$FFFE` after `abort()`) at `$FD/$FE`, restores the caller's 8-bit stack and flags and returns with `rts`. A BASIC caller reads it with `PEEK(253)+256*PEEK(254)`.

crt0 clears BSS (step 5), so globals without an initializer start at 0 on real hardware too, whatever was in memory. Uninitialized `static` locals are in BSS as well (and get `-fbss-fill`'s byte like globals); a variable with an explicit initializer, `= 0` included, is in the initialized data.

### Default Memory Map (one-step build / `ln45 -basic`)

```
$2001  BASIC line 10 SYS 8205
$200D  crt0, code, data
       BSS (__bss_start .. __bss_end)
       __zp_page        private base page (page-aligned, last page of BSS)
       __zp_page_isr    handlers' base page (only if the program has an __interrupt function)
       heap             __bss_end .. $B000 (malloc)
$B000  4 KB reserved for the stack
$BFFF  __stack_top: the 16-bit CPU stack grows down from here
$C000  ROM in C65 mode (not usable as RAM)
$D000  I/O
```

`ln45` stops with an error if the program ends above `__stack_top`, and warns when less than 512 bytes are left for the stack.

### Linker Symbols

| Symbol | Default | Description |
|--------|---------|-------------|
| `__bss_start`, `__bss_end` | set by ln45 | Bounds of the BSS segment. |
| `__stack_size` | `4096` (ln45; `--stack-size=`) | The CPU stack's share below `__stack_top`; the automatic heap ends there. Defined by the module containing `main` for `-fstack-size=` and `#pragma cc45 stack_size`. |
| `__bss_fill` | `0` (ln45; `--bss-fill=`) | The byte crt0 fills BSS with. Defined by the module containing `main` for `-fbss-fill=`. |
| `__zp_page`, `__zp_page_isr` | set by ln45 | Private base pages. |
| `__stack_top` | `$BFFF` (weak, crt0) | Top of the 16-bit stack; `0` = 8-bit page-1 stack. Defined by the module containing `main` when `-fno-stack16`, `-fstack-top` or the pragmas are used. |
| `__heap_start`, `__heap_end` | `0` (library member `__heap_bounds`) | `0` means automatic: start at `__bss_end`; end 4 KB below `__stack_top`'s page (`$B000`), or `$C000` with the 8-bit stack. |

### Heap

`malloc`/`calloc`/`realloc`/`free` are always available from the library; the heap is initialized by the first `malloc`. To place it explicitly, link an object that defines both bounds, which then replaces the library default:

```asm
; heap.s45 — assemble with: ca45 -c heap.s45 -o heap.o45
.global __heap_start
.global __heap_end
__heap_start = $8000
__heap_end   = $A000
```

```bash
ln45 -basic -o prog.prg prog.o45 heap.o45 -L lib/build -l c45.lib
```

## Code Overlays

A program whose code does not fit in bank 0 can put parts of it in **code
overlays**: code that is kept in far memory (bank 5) and brought into view
when it is called. The 45GS02's program counter is 16 bits, so far code
has to become visible in the CPU's 64 KB before it can run. There are two
ways to do that, chosen at link time.

**Marking the code.** A whole file goes in an overlay: `#pragma cc45
overlay(name)` at its top, or `-foverlay=name` on its command line. Files
with the same name share an overlay. Nothing else changes in the source:
calls, function pointers and both calling conventions work as usual, and
cc45 output is the same for both methods.

```c
/* tool.c */
#pragma cc45 overlay(tool)
int tool_run(int x) { return x * 3; }      /* called from main.c as usual */
```

```bash
cc45 -O2 -c main.c -o main.o45
cc45 -O2 -c tool.c -o tool.o45
ln45 -basic -o prog.prg main.o45 tool.o45 c45.lib                  # copied
ln45 -basic --overlay-map -o prog.prg main.o45 tool.o45 c45.lib    # mapped
disk45 add prog.d81 prog.prg PROG && disk45 add prog.d81 prog.ov1 PROG.OV1
```

ln45 writes the overlays' code to `prog.ov1` (and their description, for
nm45 and objdump45, to `prog.ovd`). Put `prog.ov1` on the program's disk
as `PROG.OV1`: the startup code loads it into bank 5 from
the drive the program came from, and stops with `?OVERLAY FILE` if it is
missing. A call into an overlay from outside it goes through a small
resident stub (6 bytes; 21 with ln45 `--overlay-fast-stubs`), which makes the overlay visible and returns
through the runtime, so the caller's code is visible again when the call
returns. A call within the same overlay is direct.

| | Copied (default) | Mapped (`ln45 --overlay-map`) |
|---|---|---|
| How | DMA copies the overlay into one region of bank 0 | `MAP` points a window of the CPU's address space at the overlay in bank 5; no copying |
| Where it runs | a region just below the stack's share (the heap ends there) | `$6000`–`$7FFF`, or `$4000`–`$7FFF` for an overlay over 8 KB |
| Cost of a switch | about 0.1 ms per KB of the overlay | a few instructions, whatever the size |
| Largest overlay | the room between the program's end and the stack's share | 16 KB |
| Program's own size | must end below the region | must end below the window (`$6000` or `$4000`); the heap moves above it (`$8000`) |
| Code that writes itself | writes the copy (lost at the next switch) | writes bank 5 (kept) |

Choose **mapped** when overlays call each other often or are large, and
the resident program fits below `$4000`/`$6000`. Choose **copied** when
the resident program is larger, or when overlays are switched rarely.

**In both methods:**
- An overlay's variables (data and BSS) stay resident: they keep their
  values while other overlays run. Only code is swapped, and the constants
  kept with it (see [Constants kept with the code](#constants-kept-with-the-code-__noescape)).
  The starting value of a local array or struct (`char buf[] = "text";`),
  which only that function copies from, is always kept with its code.
- An `__interrupt` handler cannot be in an overlay, nor reach one through
  its calls (link errors).
- Calls through overlays nest 32 deep.
- `setjmp`/`longjmp` work across overlay calls: `longjmp` drops the
  overlay calls it leaves and brings back the overlay `setjmp` was called
  from (`jmp_buf` is 8 bytes).
- ROM calls and disk I/O work from inside an overlay.

`<overlay.h>` declares `__ovl_current` (which overlay is visible: 1, 2, …;
0 before the first call) and `__ovl_region` (where overlays run).

### Constants kept with the code (`__noescape`)

An overlay's string literals and `const` data are resident by default:
their addresses may be passed anywhere, and a pointer into an overlay is
valid only while that overlay is in the region. When the address of a
constant never leaves the code of its file, it can be kept with that code
instead, in the overlay (copied or mapped), or in the far chunk of the
`__far` functions that use it, which saves bank 0 memory:

```c
#pragma cc45 overlay(set)
#pragma cc45 noescape_strings          /* the literals that follow */

static const char __noescape names[] = "autoindent\0ai\0expandtab";
static const char *const __noescape table[] = { "one", "two" };  /* the strings too */

message("no such option", 1);          /* resident message() copies it at once */
msgf(1, __escape "not found: %s", s);  /* stays resident: msgf calls into another overlay */
```

- **`__noescape`** (or `__attribute__((noescape))`) on a read-only
  object (`const`, or `* const` for a pointer) promises that its address is
  used only by the code of its file, while that code runs: never stored,
  returned, or passed to code that runs another overlay meanwhile.
  `__noescape` on a writable object is an error (a copied overlay is copied
  in again from its store, so a write would be lost). On a function
  parameter (Clang's `noescape`) the attribute is accepted and has no
  effect.
- **`#pragma cc45 noescape_strings`** makes the string literals in
  functions that follow `__noescape` (until `#pragma cc45 escape_strings`);
  **`__escape "…"`** keeps one of them resident. A literal whose address
  initializes static storage (`static const char *p = "x";`, a table of
  `char *`) stays resident: its address is stored.
- **Placement**: an object or literal goes where the code using it goes:
  the overlay (an overlay file), or the far chunk when only `__far`
  functions use it. One used by resident code, by code in two places, or
  from a resident initializer stays resident; so does everything in a
  program without overlays. The same source builds anywhere.
- **Checks**: ln45 refuses a reference to an overlay's `__noescape` data
  from outside that overlay (another file, resident code). It warns when
  the code passes such an address to a function that can call into another
  overlay, directly or through its calls (calls through pointers can reach
  every function whose address is taken), with the call's line and the
  chain:

  ```
  ln45: warning: search.o45, line 292: '_search_motion' (code overlay search) passes the
  address of __noescape data to '_msgf', which can call into code overlay fmt
  (_msgf -> _vfmt): the data is not in the region while that runs (__escape keeps a literal resident)
  ```

  While the other overlay runs, the data's bytes are that overlay's code. The
  call may not reach it, or not while the pointer is still used; `__escape`
  on the literal (or no `__noescape`) removes the warning. cc45 follows the
  address through copies, offsets, a pointer read from a kept table and a
  local it is stored in; one stored elsewhere (a global, a structure behind a
  pointer) is not followed.
- In vim2 (25 overlays), the pragma in every overlay file moves about 2 KB
  of message strings and tables out of bank 0 (the region grows by the
  largest overlay's share).

### `__far` functions

A single function can be far without a file of its own: declare it
`__far` (anywhere among its specifiers: `__far int f(void)`,
`static __far int g(int)`, `int __far h(void)`).

```c
__far int checksum(const char *p, int n) {   /* kept in bank 5 */
    int s = 0;
    while (n--) s += *p++;
    return s;
}
```

cc45 puts each `__far` function's code in the text sub-segment `far`; the
rest of the file stays resident. ln45 packs the far code of each file into
**automatic mapped overlays** (`far1`, `far2`, …) of 8 KB (16 KB when one
file has more). Files whose far code calls each other go into the same
overlay when they fit. Calls go through stubs as for any overlay:

- No pragma, no `--overlay-map`: `__far` code is always mapped (and when a
  program has both, its `#pragma cc45 overlay` files are mapped too).
- A file's far functions are in the same overlay: calls among them are
  direct. Calls between overlays, from resident code and through function
  pointers go through the stubs; a call from far code to resident code is
  direct.
- A prototype does not need `__far`: only the definition decides where the
  code goes.
- `__far` functions are not inlined (their code stays in far memory).
- An `__interrupt` handler cannot be `__far` (a link error), and one file's
  far code must fit in 16 KB.
- The program still needs the overlay file on its disk (`<PROG>.OV1`).
- In standalone `-S` output (no linker) `__far` has no effect.
- Only code moves: a far function's string literals, `static` and `const`
  data and static storage stay resident, except the constants kept with
  the code (`__noescape`, `#pragma cc45 noescape_strings`: below).
- Grouping is by file: ln45 puts files whose far code calls each other in
  one overlay when they fit (it counts call sites, not how often they run).
  Far functions that call each other often belong in the same file, or in
  files that fit in one 8 KB window together. Otherwise each call between
  them changes the map.
- An interrupt handler must not reach far (or overlay) code: the overlay
  runtime is not reentrant. ln45 follows the calls from every `__interrupt`
  handler (through resident functions and function pointers too) and
  rejects any that reaches an overlay, naming the chain of calls.

`__far` on a pointer makes a far pointer (next section); on another
variable it is still a reserved qualifier with no effect.

### Far pointers

`T __far *p` (or `__far T *p`) is a pointer to memory anywhere in the
MEGA65's 28-bit address space: chip RAM banks 0-5, attic RAM
(`$8000000`), the I/O area. It holds the address in 4 bytes (a `long`'s
size and calling convention), and what it points to is read and written
with the 45GS02's 32-bit indirect addressing (`lda [bp],z`, `ldq [bp],z`):
no MAP, no bank switching, no library call.

```c
struct Cell { char ch; int count; };
char __far *screen = (char __far *)0x40000;      /* bank 4 */
struct Cell __far *cells = (struct Cell __far *)0x50000;

void fill(char c) {
    int i;
    for (i = 0; i < 1000; i++) screen[i] = c;
    cells[3].count += 2;
    cells->ch = 'x';
}
```

- **Access**: `*p`, `p[i]`, `p->m`, `(*p).m`, members of members and
  elements of array members (`p->name[2]`), with `=`, `op=`, `++`/`--`.
  The objects are integers, enums, `_Bool`, fixed-point values and
  pointers (near or far). A whole struct or union is not copied through a
  far pointer (`s = *p` is an error: copy its members, or use
  `dma_copy_far`); floats and bit-fields through one are errors too.
- **Arithmetic**: `p + n`, `p - n`, `p += n`, `p++` move by elements;
  `p - q` (two far pointers) is the number of elements between them, a
  `long`; comparisons and `if (p)` are those of the 4-byte value.
  `&p[i]` and `&p->m` are far pointers.
- **Arrays of arrays** (#347): a far pointer to an array, `T (__far *p)[N]`
  or with a typedef'd row (`typedef unsigned int pair[2]; pair __far *p`),
  is indexed `p[k][v]` (`p + 1` moves by a row); so is a far
  multi-dimensional array (`__bank(4) T t[R][C]`, any number of
  dimensions: `t[k]` is a far pointer to its row). Casts to them work:
  `(pair __far *)0x40000UL`, `(T (__far *)[N])addr`, also indexed
  directly. (A cast to a *normal* pointer to an array, `(T (*)[N])` or
  `(pair *)`, is a `void *`: assign it to a `T (*q)[N]` to index it;
  indexing a `void *` is an error.)
- **Conversions**: a normal (near) pointer converts to a far one without
  a cast (`char __far *f = buf;`: the address in bank 0); a far pointer
  converts to a near one by a cast, which keeps the low 16 bits
  (`(char *)f`). An integer converts with a cast:
  `(long __far *)0x8000000L`.
- **Where**: locals, globals (initialized with a constant, an address or
  `array + n`), `static`s, parameters, return values (`char __far
  *find(void)`), struct members, arrays of them, typedefs
  (`typedef char __far *fstr;`), `sizeof`. `T __far **pp` is a near
  pointer to a far pointer.
- **Spelling**: on a function, `__far` before the return type (or after a
  non-pointer one, `int __far h(void)`) still makes a [`__far`
  function](#__far-functions); `char __far *f(void)` returns a far pointer.
- What a far pointer points to is not `const`-checked (`const char __far
  *p` is accepted; writes through it are not errors).

The far address lives in four base-page bytes (its register's, or
`$F2`-`$F5` while one access runs); `z` indexes the bytes of an `int` or a
`long`. Test: `src/test-resources/test_far_ptr_xemu.c` (both conventions);
`test_compiler.sh` checks the code and the errors. The library's `far_ptr.h`
(`far_ptr_t`, `far_read_*`) and `dma_copy_far` remain for code that wants
them.

### Near pointers

`T __near *p` (or `__near T *p`) is a 1-byte pointer into the program's
base page (its [`__zp` variables](#__zp), or any base-page offset): what it
points to is read and written base-page indexed (`ldx p` / `lda $00,x`).

```c
struct Pos { char x, y; };
__zp char regs[8];
__zp struct Pos pos;

void clear(char __near *r, char n) { while (n--) *r++ = 0; }
void move(struct Pos __near *p) { p->x += 1; }
/* clear(regs, 8); move(&pos); */
```

- Access, arithmetic, `sizeof`, where they can be declared and the errors
  are those of far pointers (above); the address arithmetic is 8-bit, so
  it stays in the page.
- **Conversions**: a normal pointer (`&zpvar`, a `__zp` array) converts to
  a near one by its low byte, without a cast. A near pointer converts to a
  normal or far one by adding the base page (`tba`: the base-page
  register): with a cast, and in assignments, initializations, arguments
  and returns. Two near pointers compare as offsets; compare a near
  pointer with a normal one after a cast (`(char *)np == q`).
- A static initializer is an address's low byte
  (`char __near *g = &zpvar;`: `.byte <(_zpvar)`).
- An `__interrupt` handler runs on its own base page: a near pointer
  dereferenced there reaches the handler's page, not the program's.

Test: `src/test-resources/test_near_ptr_xemu.c` (both conventions).

### `__bank(n)`

`__bank(n)` keeps a file-scope variable, or a function, in the 64 KB bank
`n` of far memory: chip RAM banks 4 and 5, or attic RAM banks `$800`-`$87F`
(`$8000000`-`$87FFFFF`, variables only).

```c
__bank(4) const char tileset[4096] = { /* ... */ };   /* kept in bank 4 */
__bank(5) int score;                                   /* zero at start */
extern __bank(4) const char tileset[];                 /* in another file */
__bank(5) void level_loader(void) { /* ... */ }       /* code in bank 5 */
```

- **Variables** are kept in their bank, with their initial values (zeros
  without one): ln45 writes them into the program's overlay files, which
  the program loads at start (the disk needs them, as for [`__far`
  functions](#__far-functions): `<PROG>.OV1`, …, one per bank). In C a
  banked variable is a far object: `tileset[i]`, `score += 2`, `rec.m`,
  `&score` (a far pointer, `int __far *`) work as through a [far
  pointer](#far-pointers), and `sizeof` is the object's. Each file reaches
  them through a hidden 4-byte address (`.dword _tileset`).
- **Functions** are [`__far` functions](#__far-functions) whose overlay is
  kept in bank `n` (4 or 5): called through their stubs and the mapped
  window. The bank is the definition's (a prototype may say it too).
- A banked array converts to a far pointer to its first element (a
  `T t[R][C]`: to its first row, `T (__far *)[C]`); to a normal pointer only
  with a cast (its low 16 bits, a warning without one).
- Not on locals, members or types (errors). With `-S` (no linker) the
  variables and functions stay resident.
- ln45: [`__bank(n)` variables and functions](ln45.md#__bankn-variables-and-functions).

Test: `src/test-resources/bank/` (two files, banks 4, 5 and attic RAM,
both conventions; a 16-bit reference to a banked variable from assembly is a
link error).

**Inspecting.** The linker map (`ln45 -M`) shows where the overlays run,
where each is kept in bank 5, and their symbols and source lines per
overlay. `nm45 prog.ovd` and `objdump45 -d prog.ov1` list and disassemble
the overlays at their run addresses.

**More:** [ln45: Code Overlays](ln45.md#code-overlays) covers the layout,
the file format and the runtime. The examples are `examples/c/overlays`
(three tools in one region; `make OVERLAY_MAP=1` for mapped) and
`examples/c/mapped_overlays`, which shows that mapped code runs from bank 5,
with no copy. Overlays (whole files, or `__far` functions) are how cc45
runs code outside bank 0.

## CPU Stack

Programs run on a 16-bit CPU stack by default. crt0 clears the 45GS02 E flag
(`CLE`) and sets SP to `__stack_top` — `$BFFF`, the last byte below `$C000`
(in C65 mode bank 0 `$C000`-`$CFFF` reads as ROM, so it can't hold a stack).
The stack grows down towards the program's BSS and private base page, so deep
recursion, large stack frames and `alloca` are not capped at 256 bytes.
On exit crt0 sets E again and restores the caller's page-1 SP and flags.
The ROM IRQ handler, the BASIC float routines and the screen/keyboard
KERNAL calls (`putchar`, `getchar`) run unchanged on the relocated stack. The
KERNAL's disk code does not: the `<cbm.h>` wrappers (and so `fopen` and the
CBM file functions) call the KERNAL through `__rom_call` (`stdlib_asm/rom_call.s45`; cc45 declares it only in modules whose asm names it), which moves
to the ROM's page-1 stack for the call.

- `-fno-stack16` / `#pragma cc45 no_stack16`: keep the ROM's 8-bit stack on
  page 1. The choice belongs to the module that defines `main`, which then
  defines `__stack_top = 0` (overriding crt0's weak `$BFFF`).
- `-fstack-top=<addr>` / `#pragma cc45 stack_top(<addr>)`: move the top of
  the 16-bit stack (for example below a buffer kept at `$A000`), at most
  `$BFFF` (ln45 rejects a higher one: `$C000` up reads as ROM and I/O). A
  pragma in the source wins over the command-line flag. With either stack
  the program must end below `$C000`; `-fno-stack16` does not make more
  room.
- Hand-written assembly must not address the stack as `$0100,x` (or
  `__sp_base,x`). Read it through a pointer instead:
  `tsx; tsy; stx $08; sty $09; ldy #1; lda ($08),y` (SP+1). When changing SP
  with interrupts enabled, write SPH first when lowering SP and SPL first when
  raising it, so an interrupt between the two writes pushes below live data.

## Pragmas

`#pragma` lines are handled by the preprocessor. Unknown pragmas are ignored silently.

| Pragma | Effect |
|--------|--------|
| `#pragma once` | Include the file only once. |
| `#pragma push_macro("N")` / `pop_macro("N")` | Save / restore a macro definition. |
| `#pragma weak`, `#pragma cc45 weak` | The next function or global is a weak definition. |
| `#pragma cc45 recurse` | The next function uses a stack frame instead of static allocation (needed for functions called both from an `__interrupt` handler and from mainline code; also silences the warning on recursive functions). |
| `#pragma cc45 signed_default` / `unsigned_default` | Plain integer types signed / unsigned from here on. |
| `#pragma cc45 no_stack16` | As `-fno-stack16`. |
| `#pragma cc45 stack_top(<addr>)` (or `stack_top <addr>`) | As `-fstack-top=<addr>`. |
| `#pragma cc45 stack_size(<n>)` (or `stack_size <n>`) | As `-fstack-size=<n>`. |
| `#pragma section("<name>", <addr>)`, `#pragma section("<name>")`, `#pragma cc45 section(...)` | Declares a section for `__section("<name>")` variables and functions, at `<addr>` (or where another file or `ln45 --section` puts it): see [Sections](#sections-pragma-section-__section). |
| `#pragma cc45 overlay(<name>)` (or `overlay <name>`) | As `-foverlay=<name>`: this file's code is in the code overlay `<name>` ([Code Overlays](#code-overlays); `<overlay.h>`). |
| `#pragma cc45 max_inline_ir_size(<N>)` | As `-fmax-inline-ir-size=N`. |
| `#pragma cc45 max_unroll_bytes(<N>)` | As `-fmax-unroll-bytes=N`. |
| `#pragma cc45 optimize(<name>, no-<name>, …)` | Switch IR optimization passes for the functions that follow (e.g. `optimize(no-licm)`); see [optimizations.md](../architecture/optimizations.md#optimization-switches). |
| `#pragma cc45 optimize(off)` / `optimize(on)` | `#pragma cc45 optimize(off)` … `optimize(on)`: the functions defined between them compiled as written, to read their code before and after optimizing or to step through it: no IR pass (nor dead-temporary removal, loop interchange), no inlining of them into callers or of calls inside them, and ca45's passes (redundant loads, branch inversion, tail calls, tail merging, sequence extraction, …) leave their code alone (cc45 puts it between `.noopt_start` and `.noopt_end`). Inside a function body, for that function only. What code generation always does (constant folding of the source, its choice of instructions) stays; the other functions are optimized as usual (`test_noopt_xemu.c`). |
| `#pragma encoding <ascii\|petscii\|screencode>`, `#pragma encoding(<…>)` | Encoding of the string and character literals that follow (a `p`/`s`/`a`/`@` prefix overrides it) (see [String and Character Encodings](#string-and-character-encodings)). |
| `#pragma cc45 no_zp_save`, `#pragma no_zp_save` | `-S` (standalone) output only: do not relocate the base page. Linked programs always run on `__zp_page`. |
| `#pragma cc45 set_bp <n>` | `-S` output only: set the base page to `n` (a **decimal** number; `$40` is rejected). |

Accepted but currently without effect (they do not reach the code generator): `exit_rts`, `exit_halt`, `exit_brk`, `no_bssinit`, `heap`, `stdio`, `no_0100_stack`, `unroll [N]`, `unroll_default N`. The exit behaviour is always the crt0 return described above. Pragmas inside a false `#if` block are still applied.

`_Pragma("...")` takes every pragma `#pragma` does (`_Pragma("cc45 signed_default")`, `_Pragma("encoding ascii")`, …), also from a macro's expansion.

## Type System

| Type | Size | Notes |
|------|------|-------|
| `char` | 1 | Unsigned unless `signed` (or `-fsigned-default`). |
| `short`, `int` | 2 | Unsigned unless `signed`. |
| `long` | 4 | Unsigned unless `signed`. |
| `long long`, `int64_t`, `uint64_t`, `__int64_t`, `__uint64_t` | 8 | `struct __int64` from `<intwide.h>` (see below). |
| `__int128`, `__int128_t`, `__uint128_t` | 16 | `struct __int128`. |
| `float`, `double`, `long double` | 5 | CBM 40-bit float. |
| `_Bool` | 1 | Any non-zero value stored becomes 1. `<stdbool.h>` provides `bool`/`true`/`false`. |
| pointers, `void *` | 2 | 16-bit addresses. |

- **`long long` / `int64_t`**: `+ - * / % & | ^ << >>`, the compound assignments, comparisons and unary operators via operator overloading and the `__intN_*` runtime. The structs have no signedness (`unsigned long long` is the same one): comparisons, `>>` (arithmetic), `/` and `%` (truncating toward zero) are signed; a shift count is an `int`. A unit emits only the struct methods it calls (each a weak copy), so `a + b` links one operator, not all of them. Integers convert to them (zero or sign filled) in initializers, assignments, arguments and mixed operands; they narrow to `char`/`int`/`long` by assignment, return or cast. `LL` constants keep all 64 bits.
- **`__int(N)` / `__uint(N)`**: the preprocessor maps them to `struct __intN` / `struct __uintN`. `<intwide.h>` defines the 64- and 128-bit structs; another width needs its own `struct __intN` definition. `__int(8)`, `__int(16)` and `__int(32)` (and `__uint`) are the native `signed`/`unsigned` `char`, `int` and `long` instead: `__int(32)` is `signed long`, with no struct and no `<intwide.h>`.
- **`_Complex` / `__complex__`**: integer complex types are `struct _Complex_int`, floating ones `struct _Complex_float`, with arithmetic operators (`+ - * /`, `==`, `!=`, unary `-` and `~` conjugate; integer division truncates), `__real__`/`__imag__`, imaginary literals (`2.0i`) and mixed real/complex operands (`1.0 + 2.0i`).
- **Integer literals** above 16 bits become `long` (with a warning when the literal has no suffix).
- **Casts**: narrowing keeps the low bytes, widening zero- or sign-extends by the source's signedness; constant casts are folded.
- **Mixed signedness**: an operation (comparison, `/`, `%`, `*`, also `/=` …) on a signed and an unsigned operand is unsigned, unless the signed type is wider than the unsigned one and so holds all its values: a `signed int` against an `unsigned char`, a `signed long` against an `unsigned int`, is signed (`-3 < (unsigned char)245`). A signed operand against a non-negative literal up to 32767 is signed too. A `signed char` and an `unsigned char` both promote to `int`: compared, divided or taken modulo (also `/=`, `%=`) they are computed in 16 bits, signed (`(signed char)-1 < (unsigned char)255`). The right side of a compound assignment widens to the left side's type by its own signedness (`l += (signed char)-1` subtracts 1).

### Packed Structs (Default)

Structs are **packed**: no padding between members, and the alignment of every scalar type is 1 (`_Alignof(int) == 1`).

```c
struct Packed { char a; int b; };   // b at offset 1, sizeof == 3
```

`struct __unpacked S { ... }` aligns each member to its natural alignment (`b` above would be at offset 2): a 2- or 4-byte scalar or pointer to its size, an array like its element, a struct member to that struct's natural alignment (an `__unpacked` struct's largest member alignment, 1 for a packed struct); `float` and `char` are not aligned. Bitfield units align like their type. The struct's size is padded to a multiple of its largest member alignment, so `sizeof(struct __unpacked {char a; int b;})` is 4 and `struct __unpacked {char a; long l; char c;}` is 12. Once defined, the struct can be named with or without the keyword (`struct __unpacked S v;` and `struct S v;` are the same). A flexible array member (`char d[];`) adds nothing to `sizeof`.

### Fixed point (`__fixed(I, F)`)
Signed fixed-point numbers, for the arithmetic of games, graphics and signals without the BASIC ROM's floats. `__fixed(I, F)` has I integer bits (the sign among them) and F fraction bits, I + F = 16 or 32, both at least 1:

| Type | Size | Range | Step |
|------|------|-------|------|
| `__fixed8_8` = `__fixed(8, 8)` | 2 bytes | -128 to 127.996 | 1/256 |
| `__fixed(1, 15)` | 2 bytes | -1 to 0.99997 | 2^-15 (audio) |
| `__fixed16_16` = `__fixed(16, 16)` | 4 bytes | -32768 to 32767.99998 | 1/65536 |
| `__fixed(8, 24)` | 4 bytes | -128 to 127.99999994 | 2^-24 |
| `__fixed(4, 28)` | 4 bytes | -8 to 7.999999996 | 2^-28 (the Mandelbrot example) |

```c
typedef __fixed(4, 28) coord;
__fixed8_8 y = 0, vy = 3;          /* constants scaled when compiled: 3 is $0300 */
vy -= 0.25;                        /* sub, no float code */
y += vy;
if (y > 100) ...                   /* a compare of the integers */
coord left = cx + (col - 160) * step;   /* int * fixed: the integer times step's */
__fixed16_16 area = w * h;         /* the hardware multiplier */
printf("%f\n", toFloat8_8(y));     /* printf: as a float */
```

- The value is an integer scaled by 2^F. Constants (`1.5`, `-0.25`, `3`) are scaled when compiled, rounded to the nearest step: in initializers of globals, statics, arrays and structs, and in expressions; one out of the type's range warns ("does not fit `__fixed(1, 15)`") and wraps.
- `+`, `-`, unary `-`, comparisons, `!`, `&&`, `||` and `?:` are the integers' code (as fast as `int` / `long`). `*` and `/` of two fixed values scale: 16-bit types inline (a 32-bit product shifted F bits down; `(a << F) / b`), 32-bit ones through `__fx32_mul` / `__fx32_div` (`<fixed.h>`, `stdlib_asm/fixed.s45`: the MEGA65's 32×32 multiplier and 32.32 divider). A fixed value `*` an integer, or `/` an integer, is the integer times (over) the fixed value's integer: exact, and the integer need not fit the fixed type (`(col - 160) * step` with `step` in `__fixed(4, 28)`). Results are truncated toward 0 and wrap when they do not fit. `%`, `&`, `|`, `^`, `~` are errors; `<<` / `>>` shift the integer.
- Mixed operands: an `int` or `float` with a fixed value (but for `*` / `/` above) becomes that fixed type; two fixed types of different sizes the wider (`__fixed8_8` with `__fixed(4, 28)`: `__fixed(4, 28)`); two different ones of one size are an error ("cast one to the other": no silent loss of range or precision). Assignments, initializers, arguments, return values and casts convert to and from `int`, `long`, `float` and other fixed types: to an integer drops the fraction toward 0 (`(int)-1.25` is -1), to a float is exact up to its 32-bit mantissa. `x op= y` is `x = x op y` (x a simple lvalue).
- `<fixed.h>` (included automatically when a file names a fixed type) has `fixedToFloat(v)` and `fixedToInt(v)` for any fixed value, `toFloat8_8(v)`, `toFloat16_16(v)`, `toInt8_8(v)` and `toInt16_16(v)`. There is no `printf` conversion of their own: `printf("%f", fixedToFloat(x))`.
- In xemu (40 MHz), against `float`: an 8.8 multiply about 6 times faster, a 16.16 multiply or divide 4, an addition 18.
- Inside cc45 (messages show `__fixed(I, F)`) the type is named `__fixedI_F`.

Tests: `src/test-resources/test_fixed_xemu.c` (8.8, 16.16), `test_fixed_any_xemu.c` (4.28, 8.24, 1.15, 4.12, mixed); `examples/c/mandelbrot` (`make check`).

### `_Alignas` and `__attribute__((aligned))`

`_Alignas(N)` and `__attribute__((aligned(N)))` request an alignment (a power of two) for globals, local statics, statically allocated (SAC) locals, struct members and — for the attribute — struct types (`struct __attribute__((aligned(4))) S { ... }`). `aligned` without an argument means 2. An aligned member pads the struct, an aligned struct's `sizeof` is rounded up to its alignment, and `_Alignof` reports it. ln45 starts each object's data/BSS on the largest alignment it needs. Locals in stack frames are not aligned. As in C11, `_Alignas` may stand anywhere among the declaration specifiers (`_Alignas(8) static int x;`, `static int _Alignas(8) x;`).

```c
_Alignas(16) unsigned char buffer[32];            // address % 16 == 0
struct __attribute__((aligned(4))) S { char a; }; // sizeof 4, _Alignof 4
struct M { char a; _Alignas(4) char b; };         // b at 4, sizeof 8
```

### GCC Vector Extension
`typedef T V __attribute__((vector_size(N)));` declares a vector of `N / sizeof(T)` elements of an integer or float type `T`. A vector is a value: it is initialized with `{...}` or `(V){...}`, assigned, passed and returned like a struct, and `v[i]` reads or writes an element. The operators `+ - * / % & | ^ << >>`, unary `- ~ !` and the compound assignments work element by element; a scalar operand is converted to the element type and used for every element. Comparisons give a vector of signed integers of the element's width holding -1 (true) or 0. A cast between vector types of the same size keeps the bits. `__builtin_shuffle(a, mask)` and `__builtin_shuffle(a, b, mask)` select elements by index (modulo `n`, or `2n` for two vectors). `__attribute__((mode(QI/HI/SI)))` selects an 8/16/32-bit integer.

There are no vector instructions: an operation is a loop over the elements, unrolled when the estimated code fits `-fmax-unroll-bytes=N` / `#pragma cc45 max_unroll_bytes(N)` (default 128 bytes). cc45's `int` is 16 bits, so `vector_size(16)` of `int` has 8 elements.

### String and Character Encodings

String and character literals are PETSCII by default (`.text`); in cc45's mapping `'a'` is `$41` and `'A'` is `$C1`, as BASIC's `ASC("A")` (193) and disk45's `-p`. The letters swap case; everything else keeps its ASCII byte, which the MEGA65's ASCII fonts (`FONT A`/`B`) show as itself (`\ ^ _ { | } ~`). A character constant is its byte read as a `char`: with the default unsigned `char`, `'S'` is 211 (`$D3`); when plain `char` is signed (`-fsigned-default` without `-funsigned-char`), it is -45, and `'\xff'` is -1, as in GCC, so `c == 'S'` holds for a `char c` holding that byte.

- **Prefixes** (as in ca45 and basic45): a lower-case letter touching the opening quote chooses the encoding of that one literal, whatever `#pragma encoding` says:

  | Prefix | Encoding | Mapping | `"Hi@"` / `'a'` |
  |--------|----------|---------|-----------------|
  | none | PETSCII, or the `#pragma encoding` in effect | as `p` | `$C8 $49 $40` / `$41` |
  | `p"…"`, `p'x'` | PETSCII, mixed case (`.text`) | `a`-`z` → `$41`-`$5A`, `A`-`Z` → `$C1`-`$DA`, the rest unchanged | `$C8 $49 $40` / `$41` |
  | `s"…"`, `s'x'` | screen codes (ca45's `.screencode` / `s"…"`) | `@` → 0, `A`-`Z` and `a`-`z` → 1-26, `[ \ ] ^ _` → 27-31, the rest unchanged | `$08 $09 $00` / `$01` |
  | `a"…"`, `a'x'`, `@"…"`, `@'x'` | raw ASCII (`.ascii`) | as typed | `$48 $69 $40` / `$61` |

  With a space (`p "x"`) the letter is an ordinary identifier, so variables and functions named `p`, `s` or `a` are unaffected (`p(s)`, `int s = 1;`); in standard C a letter touching a quote is a syntax error anyway. The preprocessor keeps the prefix with its literal (a macro named `p`, `s` or `a` is not expanded in front of a quote, as for `L"…"`).
- **Escapes** in a prefixed literal are those of its encoding: `\n` is `$0D` and `\r` `$0A` in PETSCII and screen codes (as ca45's `.screencode`), `$0A`/`$0D` in ASCII; `\xHH`, octal and the other escapes give the exact byte (`s"\x41"` is `$41`, not translated).
- **Static initializers** (globals and `static` locals) are evaluated at compile time: constant expressions (every operator, `&&` / `||` / `?:` evaluating only the operand that counts, casts, `sizeof` and `_Alignof` of a type or of any variable, an `extern` array with its size included, `sizeof a / sizeof a[0]`, floats), addresses (`&x`, `buf + 2`, `&a[3]`, functions) and `offsetof`. A value has its type: `(signed char)200` is -56, `(unsigned)-1` stored in a `long` is 65535, `7 / 2` is 3 even for a `float`. An initializer that is none of these (`int x = f();`, `int y = a;`) is an error: `initializer of 'x' is not a compile-time constant` (`initializer element of ...` for one inside braces).
- **Array sizes, enum values, bit-field widths, `_Alignas` and `_Static_assert`** take integer constant expressions evaluated the same way, with `sizeof` of the variables declared so far: `char a[(unsigned char)300]` has 44 elements, `enum { E = sizeof x * 3 }`, `unsigned b : 1 + 2;`, `_Static_assert(sizeof x == 2, "...")`. A bit-field width that is not a constant is an error.
- **Case labels** are integer constant expressions evaluated the same way (`case sizeof x:`, `case (signed char)200:`, `case 3 ... sizeof(long):`); one that is not (`case x:`) is an error: `case label is not an integer constant expression`.
- **Character constants** with a prefix are integer constants: they work in constant expressions, `enum` values, `case` labels and static initializers (`case s'A':` is `case 1:`).
- **Switching**: `#pragma encoding ascii` (or `petscii`, `screencode`), `#pragma encoding(ascii)`, `_Pragma("encoding ascii")` or `asm(".encoding ascii");` inside a function. The pragma applies from where it appears (literals before the first one are PETSCII) to the string and character literals that follow — in functions, `char` array initializers, global pointer initializers and constant expressions (`case 'A':`, enumerators): under `#pragma encoding ascii`, `'A'` is `$41` and `'\n'` `$0A`; under `screencode`, `'A'` is 1.
- **Concatenation**: `"a" "b"` is `"ab"`. The result uses the **first** literal's encoding (its prefix, or the pragma when it has none); the prefixes of the following pieces are ignored: `s"A" "B"` is `$01 $02`, `"A" s"B"` is `$C1 $C2`.
- `u8"…"`, `u"…"` and `U"…"` are not supported (a syntax error); `L"…"` is an array of 16-bit `wchar_t`.

### Warnings

cc45 warns (to stderr, with a source excerpt) about unused variables and parameters (`unused variable 'x'`; `variable 'x' set but not used` when it is only assigned, as with `while ((c = getc(f)) != EOF)`), unsigned comparisons with 0 that are always false, discarded `const` in arguments, unknown or ignored attributes, oversized integer literals, recursive functions that fall back to a stack frame, and recursive `always_inline` functions. It also prints notes, e.g. when every call passes 0–255 to an `int` parameter that could be `unsigned char` (from `-O1`, the `param-narrowing` pass passes such a parameter of a `static` function as a byte when that costs the function nothing; see `doc/architecture/optimizations.md`). There is no warning for implicit narrowing (`char c = some_int;`).

## Object-Oriented Struct Extensions

### Methods and `this`
Functions defined inside a struct are methods, mangled `StructName__method`, with a hidden first parameter `__this` (also usable as `this`).

```c
struct Counter {
    int value;
    void init(int start) { __this->value = start; }
    void increment() { this->value = this->value + 1; }
};
struct Counter c; c.init(5); c.increment();   // c.value == 6
```

### Inheritance
`struct Dog : Animal { ... }` places the base members first, so a `Dog *` can be used as an `Animal *`.

### Virtual Methods and `final`
`virtual` methods put a vtable pointer `__vt` at offset 0 and are called through the vtable. `struct Leaf final { ... }` cannot be inherited from, and `virtual int f() final { ... }` cannot be overridden. Every object of such a struct gets its `__vt` set to its struct's vtable: locals when declared (after any initializer), globals and statics in their initial data, and also array elements and nested struct members. A derived struct shares its parent's `__vt` (`sizeof` includes the parent's members).

### Operator Overloading

An operator applied to a struct or union with no such operator method is an error (`invalid operands to binary / ('struct S' has no operator/)`), as in C. The result of an operator on a small struct (4 bytes or less, returned in registers) can itself be an operand: `(a + b) == s`, `__real__ (a + b)`.
An operator method `operator+` is mangled `StructName__operator_add`; `a + b` on a struct with that method becomes `StructName__operator_add(&a, b)`.

- Binary: `+` (add), `-` (sub), `*` (mul), `/` (div), `%` (mod), `==` (eq), `!=` (ne), `<` (lt), `>` (gt), `<=` (le), `>=` (ge), `<<` (shl), `>>` (shr), `&` (band), `|` (bor), `^` (bxor)
- Unary: `~` (bnot), `!` (lnot), `++` (inc), `--` (dec), `-` (neg), `+` (pos), `*` (deref), `&` (addr)
- Assignment: `+=` (add_assign), `-=` (sub_assign), `*=` (mul_assign), `/=` (div_assign), `%=` (mod_assign), `&=` (band_assign), `|=` (bor_assign), `^=` (bxor_assign), `<<=` (shl_assign), `>>=` (shr_assign)

```c
struct Vec2 {
    int x, y;
    struct Vec2 operator+(struct Vec2 o) { struct Vec2 r; r.x = this->x + o.x; r.y = this->y + o.y; return r; }
    int operator==(struct Vec2 o) { return this->x == o.x && this->y == o.y; }
};
struct Vec2 s = a + b;
```

`<complex.h>` and `<intwide.h>` are built on these.

## Storage Classes and Function Specifiers

### `static`
- **File scope**: internal linkage. A static global is not exported; a static function is emitted as `_name__<file>` so modules with equally named static functions link together.
- **Local**: static storage, initialized once, named `__<func>__local_<name>` in the assembly (`__counter__local_calls`).

### `register`
A `register` local lives in the zero-page register pool (`$30`…), named `@_l_name` in the assembly. `&` on it is an error ("Cannot take address of register variable").

In a leaf function (one that makes no calls and has no inline `asm`) the compiler treats pointer locals as `register` variables without the keyword, and copies a pointer parameter used twice or more into one at the start of the body, so dereferences use `($zp),y` in place (see `doc/architecture/optimizations.md`, "Pointers in zero page"). A pointer whose address is taken stays in memory. `CC45_NO_ZP_POINTERS=1` in the environment turns this off.

A static-allocation function that does make calls keeps its most used variables in a base-page block of its own in `$80`–`$E9`: pointers first, then `char`/`int`/`long` variables by their number of uses (those in loops counted 4 times), up to 16 bytes (`-fzp-locals-max=N`; the library is built with 8); in the ZP convention its parameters are candidates too (copied there at the entry). Variables whose address is used, floats, arrays and structs stay in storage. ln45 places the blocks so that functions active at the same time never share bytes: the variables survive the calls, pointers are dereferenced in place and every access is a base-page one. When the blocks of functions active together need more than the 106 bytes, ln45 warns and calls the functions that share bytes through wrappers that save and restore them (correct, slower calls); `-fno-zp-locals` turns blocks off. Recursive, `__interrupt` and `alloca` functions (stack frames) and standalone `-S` output have no blocks.

### `inline`, `__forceinline`, attributes
`inline` functions, and with `-O2` (default) or `-finline-functions` any small function, are inlined at call sites in the same file when their IR is at most `-fmax-inline-ir-size` instructions (default 11). `__attribute__((always_inline))` / `__forceinline` bypasses the limit, `__attribute__((noinline))` prevents inlining (and wins over `always_inline`). A recursive `always_inline` function warns and is called normally.

### `extern`
Declares without defining; referenced externals are emitted as `.extern`.

### `__interrupt`
An interrupt service routine. It pushes A, X, Y, Z and the base page register, increments crt0's `__isr_depth`, switches to its own base page `__zp_page_isr`, and returns with `RTI` after restoring them:

```c
volatile unsigned int tick_count;
__interrupt void timer_isr(void) { tick_count++; }
```

Running on `__zp_page_isr` (allocated by ln45 only when the program has an `__interrupt` function), a handler never touches the interrupted code's ZP parameters, temporaries or frame pointer; ROM calls made in a handler return to the handler's page through `__isr_depth`. After the switch it calls `__jsr_isr_save` and `__rc_isr_save`, before returning their `_restore`s: the library's `cbm_args.s45` and `rom_call.s45` keep the interrupted code's [`__jsr`](#calling-an-address-__jsr-__jsr_raw-__jmp) bytes and `__rom_call`'s saved stack pointer when the program links them (crt0's defaults are a plain `rts`). Functions called both from a handler and from the main program must not use static allocation: mark them `#pragma cc45 recurse` (ln45 reports SAC functions reachable from an interrupt handler).

### `__naked`
No prologue, epilogue or return: the body is emitted as written, and the function must return itself. A `__naked` function may return a value: its asm leaves it where the convention expects (A, A/X, ...); the closing brace adds nothing. The specifiers `static`, `extern`, `inline`, `_Noreturn`, `__interrupt`, `__naked`, `__regparm` and `__fastcall__` may come in any order (`__naked static` is static).

```c
__naked void fast_routine(void) {
    __asm__("lda #$42");
    __asm__("sta $0400");
    __asm__("rts");
}

/* the address of a byte after its own rts, in A/X */
__naked static unsigned char *here(void) {
    __asm__("lda #<mark");
    __asm__("ldx #>mark");
    __asm__("rts");
    __asm__("mark: .byte 0");
}
```

### `__regparm`
The first parameter is passed in A (`char`) or A:X (`int`, pointer); the others use the normal convention. Declare it on the prototype as well.

```c
__regparm int add(int a, int b) { return a + b; }   // a in A:X, b at $12
```

The caller loads the register argument last, after the others are stored. Under the ZP convention its slot in the parameter block stays free (in the example `b` is at `$12`); under the stack convention it is not pushed. Works with both conventions, with and without static allocation, and across modules.

### `__fastcall__`
Makes one function use the ZP convention in a file compiled with `-fno-zpcall`. Declare it on the prototype as well (it comes first: `__fastcall__ int f(int x);`). The library's headers declare its assembly functions (`memcpy`, `strlen`, `putchar`, `malloc`, `exit`, …) this way, so stack-convention programs call them directly instead of through a linker thunk; cc45's own `memcpy`/`memset`/`alloca` calls (struct copies, VLAs) do the same. So does a call to one of those assembly functions that has no declaration in the file (an implicit declaration, or `__builtin_alloca`, `__builtin_setjmp`, `__builtin_longjmp`, `__builtin_abs`, …), unless the file declares or defines that name itself. Declaring a function `__fastcall__` after a stack-convention call to it is an error (the linker could not bridge that call).

### `__zp`
Puts a global (or a `static` local) in the program's base page, where every access is a 2-byte base-page instruction instead of a 3-byte absolute one:

```c
__zp unsigned char *screen = (unsigned char *)0x0800;
__zp int counter;
static __zp unsigned char tab[8] = { 1, 2, 3 };
extern __zp int shared;          /* defined in another file, also __zp */
```

ln45 places the variables at the top of the base-page blocks' area (from the end of the register pool the program uses to `$F1`) of the private base page (`__zp_page`); the functions' base-page blocks share what is left (114 bytes or more in all, a link error beyond; one file can define 98 with the default 16-byte blocks). Every file that uses a `__zp` variable must declare it `__zp` (an `extern __zp` array needs its length); one file defines it. Initial values are copied into the base page at startup (crt0 calls `__zp_init`, which ln45 generates); without one the variable is filled like BSS. Its address (`&counter`) is its full address in the base page's 256-byte block, so pointers to it work everywhere.

- Code an `__interrupt` handler reaches may not use a `__zp` variable: the handler runs with its own base page (`__zp_page_isr`), and ln45 rejects it (`... is reachable from interrupt handler ...`). Share data with handlers in plain globals.
- On a local that is not `static`, `__zp` has no effect (a warning): use `register` for a local in a register.
- In `-S` output (no linker) a `__zp` variable is a plain global.

How it is assembled: each file gives its `__zp` variables placeholder base-page addresses (above the largest `.zar` block, up to `$FC`) and declares them with ca45 `.zpsym`; the defining file exports `cc45.zpvar.<sym>` (its size) and, with an initial value, `cc45.zpinit.<sym>` (the value, in data). A `static __zp` variable's symbol is `<name>__<file>`.

### Sections (`#pragma section`, `__section`)
Puts globals, `static` variables and functions at an address of your choosing: screen RAM, a character set or sprite data where the VIC reads it, a table at a fixed place another program knows, code that must run at a fixed address.

```c
#pragma section("SCREEN", 0x0800)       /* the 80-column screen */
#pragma section("TABLES", $0C00)

__section("SCREEN") char screen[2000];   /* screen[0] is $0800 */
__section("TABLES") const unsigned char sine[64] = { 0, 6, 12, /* ... */ };
static __section("TABLES") unsigned char hits = 0;
char spare[8] __attribute__((section("TABLES")));   /* GCC's form */

#pragma section("FAST", 0x1600)
__section("FAST") void blit(void) { /* ... */ }      /* runs at $1600 */
```

- `#pragma section("NAME", address)` (or `#pragma cc45 section(...)`) declares a section in the file: a name (letters, digits, `_`) and an address in bank 0 (`0x0800`, `$0800`, `2048`; at most `$FFFF`). Without the address (`#pragma section("NAME")`) the address comes from another file of the program or from `ln45 --section NAME=address`, which overrides the pragmas.
- `__section("NAME")` puts a global or a `static` (local or file scope) in a section the file declared before it; an undeclared one is an error, as `__section` on a member, a type or a local that is not `static`.
- **Functions**: `__section("NAME")` on a function (its prototype or its definition; two different sections are an error) puts its code in the section: ln45 links it to run there and copies it into place at startup (its copy stays in the program). The code of a section comes first, then its variables. Calls and pointers to it are ordinary; it is never inlined (its code runs there). Not with `__far` or on a nested function. GCC's `__attribute__((section("NAME")))` does the same when NAME is declared, and is ignored otherwise (as before).
- The variables of a section follow each other in the order of their declarations, file after file in the order ln45 links them; the code reaches them with ordinary 16-bit addresses (`extern char screen[];` in another file is the same array).
- An **initial value** (`= 0` too) is copied into place at startup: by a DMA job per variable in `__zp_init`, which crt0 calls after the BSS fill; the value also stays in the program's data. A variable **without** one is not touched: section memory is not cleared (it is the screen's, the hardware's, or another program's). ln45 keeps the initial values even of variables the program never names (data for the hardware).
- ln45 checks the sections: one past `$FFFF`, two that overlap, one over the program (text, data, BSS, its base page), over the CPU stack's share or the code overlays' region are errors; one in malloc's heap a warning. The `-m` map lists each section (`SECT`).
- Not with `__zp`, `__noescape` or `_Alignas`. In `-S` output (not linked) a section variable is an equate at the address of the file's `#pragma section` (one is needed), initial values are not copied and a section function stays with the other code (warnings).
- `ln45 --section` in a one-step build: `cc45 x.c -o x.prg -Wl,--section,NAME=0x0C00`.

Test: `src/test-resources/test_section_xemu.c` (both conventions); `test_compiler.sh` links two files' parts of a section. How it is assembled: [ln45](ln45.md#__section-variables).

### `__abs`, `__far`
Address-space qualifiers on globals. `__abs` is the default. On a pointer, `__far` makes a far pointer (`char __far *p`: see [Far pointers](#far-pointers)). On another variable `__far` is a **reserved keyword** for possible future expansion: it is accepted and has no effect (the variable is an ordinary 16-bit address). On a function, `__far` keeps its code in far memory: see [`__far` functions](#__far-functions).

### `__striped`
`__striped` is a **reserved keyword** for possible future expansion (a striped array layout for cheaper indexing; see [striped-arrays](../architecture/striped-arrays.md)). It is accepted on array declarations and currently has no effect: the array has the ordinary layout. `#pragma cc45 no_striped` is not recognised.

### Nested Functions (GCC Extension)
A function defined inside another can use the enclosing function's locals and parameters through a static chain (`__static_chain`, ZP `$06`):

```c
int outer(int x) {
    int y = 10;
    int inner(int z) { return x + y + z; }
    return inner(5);          // 16 for outer(1)
}
```

## Pure and const functions

`__pure` (`__attribute__((pure))`) promises that a function has no side
effects: it returns a value computed from its arguments and from memory it
only reads. `__attribute__((const))` promises more: the value depends on
the arguments alone (no memory read, not even through a pointer argument).
(`__const` itself is GCC's spelling of the `const` qualifier, as in GCC.)
The optimizer (from `-O1`) then:

- reuses the result of an earlier call with the same arguments (`sq(a) +
  sq(a)` calls `sq` once): for a pure function only while nothing writes
  memory in between (a store through a pointer, to a global or to a local
  whose address is taken, another call);
- drops a call whose result is not used;
- hoists a call out of a loop when its arguments do not change in the loop:
  a const function's, or a pure function's in a loop that writes no
  memory; only a call in the loop's header (its condition, or a `do`
  loop's body), which runs whenever the loop is entered.

```c
int sq(int x) __attribute__((const));
__pure unsigned int count(const char *s);
for (i = 0; i < sq(n); i++) ...            /* sq(n) once, before the loop */
```

**Inferred** (`-fipa-pure-const`, from `-O1`; `-fno-ipa-pure-const` turns it
off): a function of the same file is const when it reads nothing but its
parameters and its own variables, writes nothing but its own variables,
always returns (no loops, no recursion) and calls only const functions;
pure when it also calls pure ones (`unsigned len2(const char *s) { return
strlen(s) + 1; }`). Such a function never reads memory itself: the compiler
does not know which loads are `volatile`, and a function reading a
hardware register (`*(volatile char *)0xD012`) must keep its calls. One
reading globals or through pointers needs `__pure`. Functions of other files
need the attribute on their declaration.

Only a function whose value comes back in registers (an integer, a pointer,
or none) is treated so: one returning a struct, union, `_Complex`, float or
`long long` writes the value through its hidden `__sret` pointer, and the
attribute has no effect on it.

The library's `strlen`, `strcmp`, `strncmp`, `strchr`, `strrchr`,
`strstr`, `strpbrk`, `strspn`, `strcspn`, `strnlen` and `memcmp` are
`__pure`, `abs` and `labs` const (`<string.h>`, `<stdlib.h>`). A function
that breaks its promise (writes memory, does I/O) may be called fewer times
than the source says. Test: `test_pure_xemu.c`.

## Intrinsics and Builtins

### CPU Registers (`__cpu`)

| Expression | Type |
| :--- | :--- |
| `__cpu.A`, `.X`, `.Y`, `.Z` | `unsigned char` |
| `__cpu.AX`, `.AY`, `.AZ`, `.XY`, `.SP` | `unsigned int` |
| `__cpu.Q`, `.AXYZ` | `unsigned long` |

### Processor Flags (`__flags`)
`__flags.Carry`, `.Zero`, `.Negative`, `.Overflow` read and write the flags as `_Bool`.

```c
__cpu.A = 0x42;
__cpu.AX = 0x1234;
__flags.Carry = 1;              // SEC
if (__flags.Carry) { ... }
```

Taking the address of a register or flag is an error ("Cannot take address of CPU register").

### Bits of a variable (`__bit`, `__bits`)
`__bit(v, n)` is bit `n` of the integer lvalue `v`; `__bits(v, lo, hi)` bits `lo` to `hi` (both included, bit 0 the lowest), shifted down to bit 0. Both read and write:

```c
if (__bit(status, 5)) ...           /* bbs5: no shifts */
x = __bits(CIA_ICR, 0, 2);          /* CIA_ICR & 7 */
__bit(flags, 5) = 1;                /* flags |= $20: lda / ora #$20 / sta */
__bits(VIC_CTRL, 5, 7) = 3;         /* VIC_CTRL = (VIC_CTRL & $1F) | $60 */
__bits(r, 4, 7) += 1;               /* the field wraps in its 4 bits */
n = __bits(r, 0, 3)++;              /* the old field; ++/-- before it: the new one */
```

- `v` is any integer lvalue: `char`, `int` or `long`, signed or not, a variable, a struct member, `p->m`, `a[i]`, `*p`, a `volatile` hardware register (`*(volatile unsigned char *)0xD011`). It is evaluated once (`__bits(a[i++], 2, 3) = 1` increments `i` once), and a write reads it once and stores it once (a `volatile` register: one load, one store; a write of every bit does not read it).
- `n`, `lo`, `hi` are constant expressions; a bit outside the operand (`__bit(c, 8)` of a `char`), `lo > hi` and a position that is not constant are errors, as are an operand that is not an integer (a pointer, a float, a struct) and taking the address (`&__bit(...)`).
- The value is unsigned whatever `v` is: `unsigned char` for a field of up to 8 bits, `unsigned int` up to 16, `unsigned long` above. A value written is cut to the field's width (`__bits(x, 1, 3) = 0x1F` writes 7); the value of the assignment is the field as stored.
- Writes: `=`, `+=`, `-=`, `*=`, `/=`, `%=`, `&=`, `|=`, `^=`, `<<=`, `>>=`, `++`, `--`.
- In a condition (`if`, `while`, `for`, `!`, `&&`, `||`) a field is tested as `v & mask`, without shifts; a single bit is usually tested with `BBS`/`BBR`.

For registers with named fields the bit-field structs of `<mega65.h>` read better; `__bit`/`__bits` need no declaration. The processor status bits are `__flags`. Test: `src/test-resources/test_bits_xemu.c`.

### Calling an address (`__jsr`, `__jsr_raw`, `__jmp`)
`__jsr(target, ...)` calls a machine-code routine with values in the CPU's registers and gives back the registers it returns:

```c
__jsr(0xFFD2, .A = 'A');                          /* KERNAL CHROUT */
__jsr(0xFFBA, .A = 1, .X = 8, .Y = 15);           /* SETLFS */
c = __jsr(0xFFCF).A;                              /* CHRIN: A after the call */
if (__jsr(0xFFC0).Carry) ...                      /* OPEN failed */
__jsr(0xFFF0, .Carry = 1, .X -> row, .Y -> col);  /* PLOT: X and Y into variables */
w = __jsr_raw(my_routine, .AX = 0x1234).AX;       /* the program's own routine */
__jmp(0xE000, .A = 1);                            /* no return */
```

- **The target** is a constant address (`0xFFD2`, `KERNAL_CHROUT`, `0xFF00 + 0xE4`) or the name of a function declared `extern` and not defined in the file: an assembly routine of another file, or of the file's top-level `asm()` (a C function of the same file is called as a function; a call through `jsr` is not in cc45's call graph).
- **Values** `.R = expression` for the registers `A X Y Z` and the pairs `AX AY AZ XY` (low byte in the first) and `Q` (`AXYZ`, 32 bits), and `.Carry` (set when the value is not 0). Every value is computed before any register is loaded, so nothing in between can change one; a constant becomes an immediate load (`lda #$41`), any other value goes through a byte of the library (`stdlib_asm/cbm_args.s45`) — but when only one 8-bit register (`A`, `X`, `Y` or `Z`) is computed (and `.Carry` is not), it is loaded straight into that register before the call (`.A = c`: `lda c`, no byte). A register given twice is an error.
- **Results**: `.R -> lvalue` stores a register after the call (`.X -> row`), and `__jsr(...).R` is one as the call's value: a register (`unsigned char`, `unsigned int` for a pair, `unsigned long` for `Q`) or a flag (`.Carry`, `.Zero`, `.Overflow`, `.Negative`: 0 or 1). Only the registers asked for are saved.
- **ROM addresses** (`$C000` and up) are called through `__rom_calli` (`stdlib_asm/rom_call.s45`: `jsr __rom_calli` / `.word target`, 5 bytes): the routine runs on the ROM's base page 0 and page-1 stack, as the KERNAL needs (the program's base page is moved, and its stack is 16-bit), and the registers and flags go in and come back as for a direct `JSR`. `__jsr_raw` calls any address directly (`jsr target`): for the program's own routines, or ROM code that needs neither.
- **`__jmp(target, .R = ...)`** jumps (`jmp target`): the routine's `rts` returns to the caller of the function that jumped, so use it as a function's last statement, in a function without a stack frame; to a ROM address it switches to base page 0 first. It has no results.
- The values and results go through bytes of the library, which an `__interrupt` handler saves at its start and restores at its end (one level: a handler interrupted by another shares the save area), so a `__jsr` in a handler does not change those of a `__jsr` the program is in the middle of. Test: `src/test-resources/test_isr_jsr_xemu.c`.

The `<cbm.h>` wrappers are `__jsr` calls ([stdcbm.md](../architecture/stdcbm.md)). Tests: `src/test-resources/test_jsr_xemu.c`, `test_cbm_xemu.c`.

### Packed booleans (`__bit`)
`__bit` is a boolean type (a `_Bool`: a value stored in it is 0 or 1) whose variables at file scope are packed eight to a byte:

```c
__bit visible = 1, dirty, paused;     /* 3 bits of one byte */
__zp __bit ready;                     /* a bit of a byte in the base page */
struct Sprite { __bit shown; __bit flipped; unsigned char x; };  /* 2 bytes */

dirty = 1;                /* lda #2 / tsb byte */
ready = 0;                /* rmb0 (__zp) */
if (ready) ...            /* bbs0 (__zp) */
visible = count > 3;      /* any value: 0 or 1 */
```

- **At file scope** (`static` or not) each `__bit` is a bit of a hidden byte of the file (`__bitvarsN`), in the order declared, with its initial value (a constant). Writes are `TSB`/`TRB` of the byte, tests `AND #mask`. With `__zp` the bytes are in the program's base page and writes are `SMB`/`RMB`, tests `BBS`/`BBR`; like any `__zp` variable they cannot be used from an `__interrupt` handler (ln45 refuses), plain `__bit` ones can.
- **Struct members** are 1-bit fields: consecutive `__bit` members share a byte (`struct Sprite` above is 2 bytes); a value stored is 0 or 1.
- **Locals, parameters, return values, array elements and pointed-to values** are `_Bool`s (a byte each): `__bit` there is just the boolean type.
- A file-scope `__bit` belongs to its file: `extern __bit` is an error (share an `unsigned char` and [`__bit(v, n)`](#bits-of-a-variable-__bit-__bits) between files). It has no address (`&flag` is an error) and `++`/`--` are errors (write `flag = 1`, `flag = !flag`); `=`, `|=`, `&=`, `^=` and the other compound assignments work, the result converted to 0 or 1.
- `sizeof` a `__bit` is 1 (a `_Bool`'s). `__bit(` followed by `(` is the builtin `__bit(v, n)`; the type is `__bit name`.

Test: `src/test-resources/test_bit_type_xemu.c`.

### DMA
`__dma_copy(dst, src, len)` and `__dma_fill(dst, len, val)` run an F018B DMA job built on the stack (see also `<dma.h>`). The addresses are 16-bit, in bank 0: colour RAM beyond `$D800`–`$DBFF` and memory above 64 KB are out of reach; for those, `<dma.h>`'s library functions `dma_copy_far(dst, src, len)` / `dma_fill_far(dst, len, val)` take 28-bit linear addresses (`dma_fill_far(0xFF80000UL, 2000, 5)` colours the whole 80x25 screen).

## Optimizations

What the current pipeline does (checked in generated code):

- **Static allocation (SAC)**: non-recursive functions keep parameters and locals in static storage (`_func__param_x`, `_func__local_N`) instead of a stack frame; calls within a file store the arguments there directly and enter at `_func__sac`.
- **Register allocation**: temporaries and `register` variables live in the ZP pool `$30`–`$7F`; the most used variables of static-allocation functions that make calls live in the function's base-page block in `$80`–`$E9`.
- **Inlining** of small functions (`-O2`, `inline`, `always_inline`).
- **Constant folding** of expressions and casts, and constant-address stores: `*(volatile unsigned char *)0xD020 = c` and stores through a pointer holding a known constant address become `sta $D020`.
- **Hardware math**: 16-bit multiplication, division and modulo use the MEGA65 math unit (`$D770`–`$D77F`).
- **Lazy frames**: a frame pointer (`$FD/$FE`) is set up only for functions that need a stack frame (recursion, `alloca`, `-fno-staticalloc`; variadic functions use static allocation like others, `va_start` reading the address of the `...` arguments that their entry thunk keeps). A frame of 8 bytes or more is pushed in a `phw #0` loop and dropped by setting SP from the frame pointer, not byte by byte (`test_frame_large_xemu.c`).
- **IR passes** (`-O1` and up): strength reduction (`x * 8` → shift, unsigned `x % 8` → `AND`), algebraic simplification, type narrowing, branch folding, CSE, loop-invariant code motion, copy propagation, address fusion. `-Roptir` shows what they changed.
- **Assembler optimizer**: `ca45` runs its peephole optimizer on the generated code (branch inversion, `JMP`→`BRA`, redundant loads, tail calls `JSR`+`RTS` → `JMP`, …).

`BBS`/`BBR` bit tests are not currently applied to typical code.

## Calling Conventions

Selected per file: ZP (default, `-fzpcall`) or stack (`-fno-zpcall`), which code can test as `__CC45_ZPCALL__` / `__CC45_STACK__`; `__fastcall__` makes a single function ZP. Independently, non-recursive functions use static allocation (SAC, `-fno-staticalloc` to disable). ln45 checks the convention of every cross-object call and generates a bridge thunk on a mismatch, in either direction (with a warning; `--no-thunks` makes it an error). See [calling-conventions](../architecture/calling-conventions.md).

### ZP Convention (default)
Arguments are packed left to right into the ZP parameter block starting at `$10`: `char` 1 byte, `int`/pointer 2, `long` 4, `float` 5. The caller stores them and does `JSR`. Indirect calls (function pointers) also pass arguments in ZP (the call is a patched `JSR`). A function whose parameters exceed 32 bytes, and every variadic function, uses the stack convention instead — so does a call through a pointer of a variadic type (`int (*p)(char *, ...)`, also a struct member or a typedef), whose `...` arguments get the default promotions (`char` → `int`).

```
Caller:            Callee int add(int a, int b):
  lda #<a          a at $10/$11, b at $12/$13
  sta $10          (a SAC function first copies them to
  ...               _add__param_a/_add__param_b)
  jsr _add
  ; result in A/X
```

### Stack Convention (`-fno-zpcall`)
Arguments are pushed right to left, each as at least 2 bytes (`char` is pushed as 2), and the caller removes them after the call. A SAC callee copies them into its static storage on entry; a function with a stack frame reads them through the frame pointer. Calls to a SAC function in the same file skip the stack and store directly into its static storage.

### Return Values

| Type | Location |
|------|----------|
| `char` | A |
| `int`, pointer | A (low), X (high) |
| `long` | A, X, Y, Z (Q), low byte in A |
| `struct`, `union`, `float`/`double`, `long long` | Hidden pointer passed by the caller as the first parameter (`__sret`, `$10/$11` in the ZP convention); the callee writes the result there |

The same registers are used in both conventions.

### Variadic Functions
Variadic functions always use the stack convention and a stack frame, also when the file is compiled in ZP mode. `<stdarg.h>` defines `va_list` (`unsigned int`), `va_start`, `va_arg`, `va_end` and `va_copy`. The arguments matching `...` get C's default promotions: a `char` or `_Bool` is passed as an `int` (zero-extended for `unsigned char`, sign-extended for `signed char`), so read it with `va_arg(ap, int)`.

```c
#include <stdarg.h>

int vsum(int count, va_list args) {
    int s = 0;
    while (count--) s += va_arg(args, int);
    return s;
}

int sum(int count, ...) {
    va_list args;
    va_start(args, count);
    int r = vsum(count, args);
    va_end(args);
    return r;
}
// sum(3, 0x1000, 0x200, (char)3) == 0x1203
```

### Recursion
A function on a call cycle within its file (direct or mutual recursion) automatically gets a stack frame and a warning (silenced by `#pragma cc45 recurse`). ln45 rejects SAC functions it finds on a cross-module cycle.

### Function Metadata
Each function's `endproc` is preceded by metadata that ca45 stores in the `.o45` and ln45 uses: `.func_flags` (`zp_call`/`stack_call`, `static_alloc`, `leaf`, `isr`), `.param_sizes`, `.reg_clobbers`, `.flag_clobbers` and `.frame_size`. Generated code also carries `.loc "file", line` directives and, for a debugger, `.dbg_var` / `.dbg_type` directives (written after each `endproc`, and the module's after its data): each global, static, local and parameter with its C type and where its value lives (its static storage, base-page block byte, ZP register, frame offset or register; `none` when optimised away), and the layouts of the structs and unions they use. They become the object's `OPT_DEBUG_VARS` / `OPT_DEBUG_TYPES` records (`objdump45 -g`; lib45.md 1.12) and never change the code.

### Libraries

| Convention | Library |
|------------|---------|
| ZP (default) | `c45.lib` |
| Stack (`-fno-zpcall`) | `c45_stack.lib` |

## Known Limitations

- `__far` on non-pointer variables and `__striped` are reserved keywords with no effect yet.
- Inline assembly cannot name non-`register` locals.

## Common Use Cases

### Single-File Program

```bash
cc45 game.c -o game.prg        # BASIC-startable PRG; RUN it
```

### Multi-Module Project

```c
// main.c
extern void init_graphics(void);
extern int run_game_loop(void);
int main(void) { init_graphics(); return run_game_loop(); }

// graphics.c
void init_graphics(void) { /* set up VIC-IV */ }

// game.c
int run_game_loop(void) { return 0; }
```

```bash
cc45 -c main.c -o main.o45
cc45 -c graphics.c -o graphics.o45
cc45 -c game.c -o game.o45
ln45 -basic -o game.prg main.o45 graphics.o45 game.o45 -L lib/build -l c45.lib
```

`ln45` finds `c45.lib` through `-L` or `CC45_LIB` (or give the library's path). Objects compiled with `-fno-zpcall` link with `c45_stack.lib`.

### Hardware Access

```c
void set_border(unsigned char c) {
    *(volatile unsigned char *)0xD020 = c;   // compiles to sta $D020
}

int main(void) {
    set_border(0);
    return 0;
}
```

`<mega65.h>` provides struct overlays of the VIC-IV, SID, CIA, DMA and other registers.

### A Library of Your Own

```bash
cc45 -c util.c -o util.o45
cc45 -c mathx.c -o mathx.o45
ar45 c mylib.lib util.o45 mathx.o45

cc45 -c game1.c -o game1.o45
ln45 -basic -o game1.prg game1.o45 -l mylib.lib -L lib/build -l c45.lib
```

### Makefile

```makefile
CC45   = cc45
LN45   = ln45
CFLAGS = -O2
LIBDIR = /path/to/m65compiler/lib/build

SRCS = main.c util.c graphics.c
OBJS = $(SRCS:.c=.o45)

game.prg: $(OBJS)
	$(LN45) -basic -o $@ $^ -L $(LIBDIR) -l c45.lib

%.o45: %.c
	$(CC45) $(CFLAGS) -c $< -o $@

clean:
	rm -f $(OBJS) game.prg

.PHONY: clean
```

### Inspecting the Output

```bash
cc45 -S prog.c -o prog.s45         # generated assembly
cc45 -c prog.c && nm45 prog.o45    # symbols (e.g. _main, _main__sac, _f__param_x)
objdump45 -d prog.o45              # disassembly with source lines
```
