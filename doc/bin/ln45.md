# ln45 — Linker for .o45 Object Files

`ln45` links `.o45` relocatable object files and `.lib` archives into a flat binary or a PRG executable. It pulls the library members it needs, lays out and merges the segments, resolves symbols, bridges calling-convention mismatches with thunks, checks static-allocation (SAC) safety, and applies relocations.

`cc45 file.c` (without `-c`/`-S`) runs `ln45` for you: `ln45 -basic -o <out> <obj> <extra libs> <c45.lib | c45_stack.lib>` (or `-prg -t <base>` with `cc45 --prg-base`).

## Usage

```bash
ln45 [options] <file1.o45> [file2.o45 ...] [-l lib.lib ...]
```

Any argument ending in `.lib` is taken as a library (same as `-l`); every other non-option argument is an object file. Options and files may be mixed in any order. `ln45` reads no configuration file.

## Options

| Flag | Description |
|------|-------------|
| `-o <file>` | Output filename (default: `a.out`, or `a.prg` for a PRG) |
| `-prg` | Write a PRG: 2-byte load address (the text base) + image. Also selected when the `-o` name ends in `.prg` |
| `-basic` | Write a PRG that loads at `$2001` and starts with a `10 SYS <addr>` BASIC line; the code follows it at `$200D`. Implies `-prg` |
| `-t <addr>` | Text segment base address, hex (`2000` or `0x2000`). Default `$2000` (`$200D` with `-basic`). Do not combine with `-basic`: the code is still stored right after the stub at `$200D` but linked for `<addr>`, and the stub calls `<addr>` |
| `-d <addr>` | Data segment base, hex (default: right after text). Must not be below the end of text — the data image is always written after the text |
| `-b <addr>` | BSS segment base, hex (default: right after data) |
| `-z <addr>` | Base for `.zp` segment symbols, hex (default: `02`) |
| `-L <dir>` | Add a library search directory |
| `-l <lib>` | Link a `.lib` archive (selective linking). The name is used as given (`-l c45.lib`, not `-l c45`) |
| `-m` | Print the symbol map (`  %08x name`, sorted by name) to stdout after linking |
| `-M <file>` | Write a detailed map file (see [Map File Format](#map-file-format)) |
| `--no-thunks` | Make every calling-convention mismatch a link error instead of generating a thunk |
| `-v`, `-vv` | `-v`: also print the cross-module analysis summaries and informational warnings (unused global symbols, SAC overlay); `-vv`: also trace every relocation. Default: errors, warnings and the summary only |
| `--bss-fill=V` | The byte crt0 fills BSS with at startup: defines `__bss_fill` (default `0`; `$FF`, `0xFF` or decimal) unless an object defines it (cc45 `-fbss-fill=`) |
| `-Wthunk` | Warn on mismatches and generate thunks — the default behaviour, so the flag changes nothing |
| `-V` / `--version` | Display version and exit |
| `-?` / `--help` | Display help |

## Environment Variables

| Variable | Description |
|----------|-------------|
| `CC45_LIB` | Colon-separated library directories. A library that is not found at the path given is looked up in each `CC45_LIB` directory, then in each `-L` directory. |

## Linking Process

### 1. Library resolution
Undefined imports of the input objects are looked up in the symbol index of each library, in command-line order. The defining member is added to the link; its own imports are added to the undefined set, and the scan repeats until nothing new is pulled. A symbol already defined by an object (even weakly) does not pull a member. Pulled members are named `lib(member.o45)` in diagnostics and the map.

The startup code is a library member (`crt0_zp.o45` in `c45.lib`, `crt0.o45` in `c45_stack.lib`), pulled in by the references every cc45 object makes to it (`__bp_rom`/`__bp_prog`), so a C program links with just its objects and the standard library. Its `init` sub-segment is placed first, at the text base.

### 2. Layout
- **Text**: object text bodies are grouped by sub-segment (`OPT_SEGATTR` records, see [lib45](../architecture/lib45.md#16-sub-segment-attributes-opt_segattr)): all `init` chunks first (crt0 startup), then `code`, then other names in alphabetical order. Objects without sub-segment records are one `code` chunk. Within a group, objects keep command-line order (pulled library members follow the input objects).
- **Data / BSS / ZP**: concatenated in object order.
- **Alignment**: an object exporting `cc45.align.text`, `cc45.align.data` or `cc45.align.bss` (emitted by cc45 for `_Alignas`/`aligned(N)`) is placed so its aligned items land on that boundary; the data and BSS bases are rounded up to the largest such alignment.
- Data starts after text and BSS after data unless `-d`/`-b` are given.

### 3. Symbol resolution
- Exports are collected into a global map: `segment base + object offset + symbol offset` (absolute exports keep their value).
- A strong definition overrides a weak one; two strong definitions are an error; of two weak ones the first wins.
- Every import must resolve (an import `X__ar_N` resolves through `X__ar` plus offset `N`).
- Linker-defined symbols (unless an object defines them):

| Symbol | Value |
|--------|-------|
| `__bss_start` | BSS base |
| `__bss_end` | End of BSS, including the base page(s) below |
| `__bss_fill` | The byte crt0 fills BSS with: `--bss-fill=V`, default `0` |
| `__zp_page` | Only if some object imports it (crt0 does): a page-aligned 256-byte block after BSS, used as the program's relocated base page |
| `__zp_page_isr` | With `__zp_page`: the page after it when any object has an `__interrupt` function (`FUNC_FLAG_ISR`), else equal to `__zp_page` |

`__stack_top` is not linker-defined: `c45.lib`/`c45_stack.lib` provide `$BFFF` (`asm___stack_top.o45`); cc45 defines it in the main object for `-fstack-top=` and as `0` for `-fno-stack16`.

### 4. Function metadata checks
From function attribute records and JSR relocations ln45 builds a call graph, computes transitive clobber sets (shown in the map), and then:
- **Calling conventions** — see [Thunks](#calling-convention-thunks).
- **SAC safety** — a function using static allocation (`FUNC_FLAG_STATIC_ALLOC`) that can reach itself through the call graph (recursion across modules), or that is reachable from an `__interrupt` handler, is a link error. Mark such functions `#pragma cc45 recurse`.

### 5. Thunks, relocation, output
Thunks are appended to the text segment (data/BSS move up if they were placed automatically), relocations are applied, and the image is written: text, then data (a gap between text end and a higher `-d` address is zero-filled). BSS is never written; crt0 zeroes it.

### 6. Stack room check
If `__stack_top` is non-zero, ln45 fails when the program end (`__bss_end`, or the end of `__zp_page`) is above it, and warns when fewer than 512 bytes are left for the 16-bit CPU stack.

## Relocation Types

| Type | Patch | Description |
|------|-------|-------------|
| `R_WORD` | 2 bytes | 16-bit address |
| `R_LOW` | 1 byte | Low byte of an address |
| `R_HIGH` | 1 byte | High byte of an address (the record carries the low byte for the addend) |
| `R_LINEAR24` | 3 bytes | 24-bit linear address |
| `R_LINEAR32` | 4 bytes | 32-bit linear address |
| `R_SEGADR` | 3 bytes | 24-bit address (written like `R_LINEAR24`) |
| `R_IMM8` / `R_IMM16` | 1 / 2 bytes | Immediate operands (self-modifying-code parameters) |

For an external reference the bytes already at the patch site are the addend (`sym+4`); for an internal one they hold the assembly-time address, from which the object's segment base is subtracted before adding the final segment address.

## Output Format

- **Flat binary** (default): text + data, no header.
- **`-prg`**: 2-byte little-endian load address (the text base), then the image.
- **`-basic`**: load address `$2001`, then a 12-byte BASIC program `10 SYS 8205` (next-line link, line number 10, `$9E` SYS token, the decimal address, `$00`, end-of-program `$00 $00`), then the image at `$200D`.

## Examples

All examples were run with the current toolchain (`c45.lib` from `lib/build`, put on `CC45_LIB` or given with a path).

### Separate compilation

```bash
cc45 -c main.c -o main.o45
cc45 -c math.c -o math.o45

# Auto-running PRG: LOAD and RUN on the MEGA65
ln45 -basic -o program.prg main.o45 math.o45 -l c45.lib

# Plain PRG at $2000 (start with SYS 8192 / BANK 0)
ln45 -prg -o program.prg main.o45 math.o45 -l c45.lib
```

### Assembly objects

```bash
ca45 -c main.s45 -o main.o45
ca45 -c utils.s45 -o utils.o45
ln45 -t 0800 -m -o program.bin main.o45 utils.o45
```

```
Linked 2 objects to program.bin (27 bytes)

Symbol map:
  0000081b __bss_end
  0000081b __bss_start
  00000807 print
  00000800 start
```

### Libraries

```bash
ar45 c mylib.lib util.o45 math.o45
ln45 -basic -o program.prg main.o45 mylib.lib -l c45.lib     # or -l mylib.lib
ln45 -basic -o program.prg main.o45 -L ./libs -l mylib.lib -l c45.lib
```

Only the members that define symbols the program needs are linked. Put your own libraries before `c45.lib` only for readability — resolution repeats over all libraries until nothing changes, so order does not matter for dependencies; it matters only when two libraries define the same symbol (the first one listed is searched first).

### Custom layout

```bash
# Text at $0800, data at $4000 (the file is zero-filled up to $4000), BSS at $6000
ln45 -t 0800 -d 4000 -b 6000 -o image.bin boot.o45 kernel.o45
```

## Calling-Convention Thunks

A cc45 object exports a marker, `cc45.mode_zp` (ZP convention, the default) or `cc45.mode_stack` (`-fno-zpcall`); each function's attribute record has `FUNC_FLAG_ZP_CONV` when it takes ZP parameters. For each JSR from a caller to a callee with an attribute record:

- caller and callee from objects with the same marker: no check (the caller already used the callee's convention);
- otherwise the caller's convention is its object's marker (or, for hand-written code without a marker, its own `FUNC_FLAG_ZP_CONV`), and a mismatch with the callee's convention — **in either direction** — needs a thunk.

Callees without an attribute record (e.g. hand-written routines without `.func_flags`/clobber directives) are never checked.

By default each mismatch is reported and bridged:

```
ln45: warning: calling convention mismatch: '_main' calls '_add' (zp_call -> stack_call) (generating thunk)
```

The call is redirected to `__thunk_z2s_<callee>` (ZP caller → stack callee) or `__thunk_s2z_<callee>` (stack caller → ZP callee), one per callee, appended to the text segment. Their code (ZP parameter block at `$10`, `paramSize` from the callee's attribute record):

```asm
__thunk_z2s_foo:            ; ZP caller -> stack callee
    lda $10+n-1 / pha ...   ; push the ZP parameters, highest byte first
    lda $10 / pha
    jsr foo
    sta $0e                 ; (only if n > 0) keep A
    pla ...                 ; drop n bytes (works with the 16-bit stack)
    lda $0e
    rts

__thunk_s2z_foo:            ; stack caller -> ZP callee
    tsx / tsy / stx $08 / sty $09     ; pointer to the stack
    ldy #3 / lda ($08),y / sta $10    ; copy each argument byte, past the return address
    ...
    jmp foo                 ; foo's RTS returns to the original caller
```

With `--no-thunks` every mismatch is an error:

```
ln45: link error: calling convention mismatch: '_main' calls '_add' (zp_call -> stack_call)
```

Linking `c45_stack.lib` currently reports two mismatches inside the library itself (`___vformat_con_put` → `_putchar`, `_printf_float` → `_itoa`); they are bridged by thunks and the programs run correctly, but `--no-thunks` rejects any stack-convention program that uses `printf`.

## Error Messages

| Message | Cause |
|---------|-------|
| `ln45: no input files` | No object file on the command line |
| `ln45: cannot open X` / `cannot find library X` | Missing object, or library not found as given, in `CC45_LIB` or `-L` |
| `undefined symbol '_foo' (referenced in X)` | An import with no definition |
| `duplicate symbol '_foo' (defined in X and Y)` | Two strong definitions |
| `calling convention mismatch: ...` | A mismatch with `--no-thunks` |
| `error: '_f' uses static allocation but is recursive (...)` | A SAC function on a call cycle (possibly across modules) |
| `error: '_f' uses static allocation but is reachable from ISR handler (...)` | A SAC function called (directly or indirectly) from an `__interrupt` function |
| `relocation offset N out of range in X` / `relocation patch overflows segment in X` | A relocation points past its segment |
| `invalid symbol index N in X` | An external relocation names a non-existent import |
| `ln45: error: program ends at $XXXX, above the CPU stack top $BFFF (...)` | The program (BSS + base page) overlaps the 16-bit stack |

Link errors are printed as `ln45: link error: <message>`; several convention/SAC errors are printed together.

## Diagnostics

| Warning | Meaning |
|---------|---------|
| `ln45: warning: calling convention mismatch: ... (generating thunk)` | See above |
| `ln45: warning: unused global symbol 'X' (defined in FILE)` | Only with `-v`. An exported symbol no object imports. `_main`, names starting with `__` and linker symbols are not reported; compiler-generated exports such as `_f__sac`, `_f__param_x` and `cc45.*` markers are, so expect many of these with cc45 objects |
| `warning: symbols 'X' and 'Y' overlap at $NNNN (different segments)` | Two symbols of different segments got the same address. cc45 objects export weak absolute constants (`cc45.mode_zp` = 1, `__zp_scratch` = 8, ...), so these can appear harmlessly |
| `ln45: warning: only N bytes left for the CPU stack ...` | Less than 512 bytes between the program end and `__stack_top` |

By default `ln45` prints only errors, the warnings above and the `Linked ...` summary. `-v` adds the cross-module analysis summaries (`[Phase 91.4] ...`, `INFO: ...`, dispatcher notes) and informational warnings (`unused global symbol` — mostly library internals and globals used only in their own object — and `SAC function '...' has no __ar symbol`); `-vv` also traces every relocation (`DEBUG [External Reloc]: ...`, `=== DEBUG: DATA relocation ...`).

## Function Metadata

Each function export can carry a 19-byte attribute record (see [lib45 §4.3](../architecture/lib45.md#43-function-attribute-record-optional)) written by ca45 from `.func_flags`, `.zp_uses`, `.zp_clobbers`, `.zp_release`, `.reg_clobbers` and `.flag_clobbers` inside a `proc`. cc45 emits these for every function. The linker uses the convention, SAC and ISR flags, the parameter size (thunks) and the clobber masks (transitive clobbers in the map).

## Map File Format

`-M <file>` writes:

```
Linker Map
==========

Memory Layout
-------------
  TEXT   $200D - $4917  (10507 bytes)
  DATA   $4918 - $495E  (71 bytes)
  BSS    $495F - $4BFF  (673 bytes)

Object Files
------------
  main.o45
    TEXT  $2086 - $2143  (190 bytes)
    DATA  $4918 - $491D  (6 bytes)
    BSS   $495F - $496A  (12 bytes)
  math.o45
    TEXT  $2144 - $21B2  (111 bytes)
    BSS   $496B - $4976  (12 bytes)
  c45.lib(crt0_zp.o45)
    TEXT  $200D - $2085  (121 bytes)
  ...

Symbols (by address)
--------------------
  $0001  cc45.mode_zp                   main.o45 [weak]
  $200D  __init                         c45.lib(crt0_zp.o45)
  $2067  _init_features                 c45.lib(crt0_zp.o45) [weak]
  $2086  _main                          main.o45  [uses:- clob:- rel:- regs:AXYZ]
  $4460  _putchar                       c45.lib(asm_putchar.o45)  [uses:10-11 clob:10-11 rel:10-11 regs:AXYZ]
  $4B00  __zp_page                      <linker>
  ...

Call Graph
----------
  ___vformat_con_put -> _putchar
  ...

Source Lines
------------
  $2086  main.c:6
  ...
```

- **Memory Layout**: each non-empty segment. BSS includes the `__zp_page` (and `__zp_page_isr`) pages. A ZP line appears only if objects have `.zp` segments.
- **Object Files**: every input object and pulled library member with its share of each segment (an object's text line spans its first chunk's position; sub-segment reordering can place parts elsewhere).
- **Symbols**: all global symbols with address, defining file (`<linker>` for linker symbols, empty for thunks) and `[weak]`. Functions with attribute records show `[uses: clob: rel: regs:]` (ZP masks printed as `$03`-based slot ranges) and, if calls add to them, `(trans: clob: regs:)`.
- **Call Graph**: caller → callees found through JSR relocations.
- **Source Lines**: first address of each `file:line` from the objects' line info.

`objdump45 -d program.prg` picks up `program.map` automatically for symbolic disassembly.

## Limitations

- The `.o45` format has four segments. ca45 maps `code`, `text`, `init` and any other named segment to TEXT (named sub-segments are kept as `OPT_SEGATTR` records and ordered as described above); only `data`, `bss` and `zp` map to DATA, BSS and ZP.
- `-basic` cannot be combined with `-t`, and `-d` below the end of text produces a wrong image (see Options).
