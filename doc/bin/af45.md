# af45 — MEGA65 assembly formatter

`af45` lays out ca45 assembly the way [al45's style rules](al45.md#style-rules)
describe (#611). It is the same program as `ca45` (`bin/af45` is a link to
`ca45`) started under another name. It reads the source text alone (no
assembly), and it changes whitespace only: labels need their colon in ca45,
so indentation never changes what a file assembles. Its test assembles a
file before and after and compares the bytes; the library's 159 files give
the same objects.

It is idempotent (a second run changes nothing), and al45 with the style
rules on reports nothing in what it writes.

## Usage

```
af45 [options] <file.s45>...
```

| Option | What |
|--------|------|
| (none) | The one file, formatted, on standard output |
| `-w`, `--write` | Rewrite the files in place (an unchanged file is not written) |
| `--check` | Change nothing; print the name of each file that would change, exit status 1 if any |
| `-o FILE` | Write the one file's result to `FILE` |
| `--config=FILE` | This configuration, not `~/.config/m65/cc45-lint.yml` and `.cc45-lint.yml` |
| `--option=ID=VALUE` | A rule option over the configuration's (`--option=mega65-style-comment-column=24`) |
| `-v` … `-vvvv` | Log to stderr (the configuration files read, the files written) |
| `-?`, `-h`, `--help` | The usage |
| `-V`, `--version` | The version |

Several files need `-w` or `--check`. Exit status: 0, 1 (`--check`: a file
would change), 2 (an error: a file, an option, the configuration).

```bash
af45 sprite.s45                     # to standard output
af45 -w src/*.s45                   # rewritten
af45 --check lib/stdlib_asm/*.s45   # in a CI step: fails when one is not formatted
```

## What it does

- **Whitespace**: tabs outside string and character literals expanded (8-column stops), spaces at the end
  of a line removed, a newline after the last line. Line endings become `\n`.
- **Labels and constants** (`name:`, `@name:`, `NAME = value`) at column 1. What follows a label on its
  line keeps its distance from it (at least one space): `vf_ctx:    .res 2` stays as it is.
- **Instructions** (and macros used as one) after `mega65-style-instruction-column` spaces (4); a directive,
  `proc` or `endproc` at column 1 if it was there, else at the instruction column, or where it lines up
  under the directive of the latest label line (a table).
- **Operands**: one space after the mnemonic, or at `mega65-style-operand-column`. Directives' operands,
  and an operand's own spacing (`lda ( $10 ),y`), are left alone.
- **Trailing comments** at `mega65-style-comment-column` (28: column 29), or, after code that reaches
  past it, their spacing kept (two spaces at least). A comment alone on the next line that started where
  the trailing comment did moves with it. A `//` comment becomes `;`. Comments on a line of their own
  stay where they are.
- **Left as they are**: lines in or touching a `/* */` comment (but for spaces at their end). A line it
  cannot classify (`*= $2000`) keeps its indentation.

## Options

From the configuration (`~/.config/m65/cc45-lint.yml`, then the first `.cc45-lint.yml` from the file's
directory upward, or `--config=FILE`), then `--option`:

```yaml
options:
  mega65-style-instruction-column: 4
  mega65-style-operand-column: 0
  mega65-style-comment-column: 28
```

The naming options (`mega65-style-label-name`, …) are al45's alone: af45 renames nothing.
