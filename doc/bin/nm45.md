# nm45 — Symbol Lister for .o45 Object Files

`nm45` lists the symbols (imports and exports) of `.o45` relocatable object files, in the style of Unix `nm`, and can also show the header, relocations, segment sizes, a hex dump and function attributes.

It reads the files produced by `ca45 -c` and `cc45 -c`. `.lib` archives are not read (nm45 points you to `ar45 t`); extract members with `ar45 x` first. It also reads the code overlay files ln45 writes (`<program>.ovd`, `<program>.ov1`, see [Code overlay files](#code-overlay-files)).

## Usage

```bash
nm45 [options] <file.o45> [...]
```

## Output Format

```
OFFSET TYPE NAME
```

- **OFFSET**: 8-digit hex value — segment-relative offset for exports (the value itself for absolute ones), blank for imports.
- **TYPE**: one letter (below).
- **NAME**: the symbol name as stored in the object.

| Letter | Meaning |
|--------|---------|
| `U` | Undefined — imported symbol (`.extern`) |
| `T` | Text segment export |
| `D` | Data segment export |
| `B` | BSS segment export |
| `Z` | Zero-page segment export |
| `A` | Absolute export (a constant) |
| `W` | Weak export (any segment) — can be overridden by a strong definition |

By default the list is sorted by name, imports and exports together.

## Options

### Symbol display
| Flag | Description |
|------|-------------|
| `-u` | Only undefined (imported) symbols |
| `-g` | Only exported symbols |
| `-n` | Sort by offset (exports first, then imports) |
| `-R` | Reverse the sort order |
| `-p` | No sorting — imports, then exports, in file order |
| `-A`, `-o` | Prepend the file name to each line (`file.o45:offset T name`) |
| `-f` | Append function attributes to functions that have them |

### Object inspection
| Flag | Description |
|------|-------------|
| `-h` | File header: format, CPU, mode flags, segment bases/lengths, options |
| `-x` | Hex dump of the text and data bodies |
| `-r` | Decoded relocation entries |
| `-S` | The section table and section references of a sectioned object (`OPT_SECTIONS`/`OPT_SECTREF`, [lib45](../architecture/lib45.md)); "No sections" otherwise. Part of `-a` |
| `-s` | Segment sizes, one line per file (like `size`) |
| `-a` | All: header, section table, hex dump, relocations, sizes, symbols with function attributes |
| `-v` … `-vvvv`, `-v0` | Log on stderr as `[nm45:LEVEL] …` (the toolchain's format, `include/Logger.hpp`); cumulative, at most `-vvvv`; `-v0` off: each file's kind, segment sizes and record counts (`-v`), its size in bytes (`-vv`) |
| `-V` / `--version` | Display version and exit |
| `-?` / `--help` | Display help |

`-h`, `-x`, `-r`, `-S` and `-s` replace the symbol listing (unless `-a` is given). With several files and without `-A`, each file's output is preceded by a blank line and `file:`. Unrecognized options are taken as file names.

## Examples

### List symbols

```
$ nm45 amain.o45 autil.o45

amain.o45:
00000030 W cc45.bptop
         U print
00000000 T start

autil.o45:
00000030 W cc45.bptop
00000000 T print
```

(`cc45.bptop` is in every object ca45 writes: how far into the register pool `$30`–`$7F` its instructions reach, for ln45's [base-page blocks](ln45.md#base-page-blocks).)

A cc45 object also exports compiler-generated symbols: `_f__sac` (body entry of a SAC function), `_f__ar` (its static storage, size `cc45.sacsize._f`), `_f__param_x` (its static parameter slots), and weak absolute constants (`cc45.mode_zp`/`cc45.mode_stack`, `cc45.zeroPageStart`, `cc45.bptop`, `cc45.icallinfo`, each function's `cc45.fsig.<f>.<sig>`, `__zp_scratch`..., `__sp_base`, `__static_chain`; see [lib45](../architecture/lib45.md#8-symbol-naming-c-linkage)):

```
$ nm45 math.o45
         U __bp_prog
         U __bp_rom
00000101 W __sp_base
00000006 W __static_chain
00000008 W __zp_scratch
0000000a W __zp_scratch2
0000000c W __zp_scratch3
0000000e W __zp_scratch4
00000000 T _add
00000000 B _add__ar
00000000 B _add__param_a
00000002 B _add__param_b
00000000 T _add__sac
0000000f T _mul2
00000005 B _mul2__ar
00000005 B _mul2__param_a
0000000f T _mul2__sac
00000031 W cc45.bptop
00000001 W cc45.fsig._add.s2_2
00000001 W cc45.fsig._mul2.s2
00000001 W cc45.icallinfo
00000001 W cc45.mode_zp
00000005 A cc45.sacsize._add
00000003 A cc45.sacsize._mul2
00000008 W cc45.zeroPageStart
```

### Search across objects

```
$ nm45 -A amain.o45 autil.o45 | grep print
amain.o45:         U print
autil.o45:00000000 T print
```

### Function attributes

```
$ nm45 -f math.o45 | grep ' T _add$\| T _add '
00000000 T _add  [zp_call leaf static_alloc uses:- clobbers:- releases:- regs:AX flags:CNZV]
```

The bracket shows the convention (`zp_call`/`stack_call`), the `leaf`, `reentrant`, `static_alloc`, `zeroalloc` and `isr` flags, the base-page bytes the function uses, clobbers and releases as their addresses in hex ranges (`uses:10-11`, `-` for none; #360), and the clobbered registers and flags. The parameter and frame sizes of the record are not shown (`objdump45 --tree` shows them).

### Header

```
$ nm45 -h amain.o45
File:    amain.o45
Format:  .o45 (32-bit)
CPU:     45GS02 ($45)
Mode:    $8800 (SIZE32 CPUEXT)
Text:    base=$0000  len=7
Data:    base=$0000  len=3
BSS:     base=$0000  len=0
ZP:      base=$0000  len=0
Options:
  type=$02 OS [05]
  type=$03 ASM "ca45"
```

Options other than FNAME/OS/ASM/AUTHOR/CREATED are labelled `USER` (e.g. `$10` sub-segment, `$11` line info, `$12` debug symbols) and shown as text or hex bytes.

### Relocations

```
$ nm45 -r amain.o45
Text relocations (3):
  0001  R_LOWX      DATA    extra=$00
  0003  R_HIGH      DATA    extra=$00
  0005  R_WORD      EXTERN  print
```

### Sections

An object compiled with `cc45 -ffunction-sections` (or assembled with ca45's `.function_sections`):

```
$ nm45 -S m.o45
Sections (6):
   idx  seg     offset    length  align  name
     0  TEXT  00000000        15      1  _used
     1  TEXT  0000000F         9      1  _unused
     2  TEXT  00000018        37      1  _main
     3  DATA  00000001         2      1  cc45.sectinit._hv
     4  BSS   00000000         4      1  _used__ar
     5  BSS   00000004         4      1  _unused__ar
```

A section ln45 always keeps is marked `[keep]`; `Section references (N):` follows when the object has `OPT_SECTREF` entries.

### Segment sizes

```
$ nm45 -s amain.o45 autil.o45 math.o45
    text     data      bss       zp    total  filename
       7        3        0        0       10  amain.o45
      17        0        0        0       17  autil.o45
      26        0        8        0       34  math.o45
```

### Full dump

`nm45 -a amain.o45` prints the header, the section table (`No sections (the object is kept or dropped as a whole)` for an unsectioned object), `Text body`/`Data body` hex dumps, the relocations, a `Sizes:` line and the symbols.

## Workflows

```bash
# Who defines / references a symbol
nm45 -A *.o45 | grep _malloc

# All unresolved references
nm45 -u -A *.o45 | awk '{print $NF}' | sort -u

# Exported but never imported by these objects
comm -23 <(nm45 -g -A *.o45 | awk '{print $NF}' | sort -u) \
         <(nm45 -u -A *.o45 | awk '{print $NF}' | sort -u)

# Duplicate strong text exports (a link error)
nm45 -g -A *.o45 | awk '$2=="T" {print $3}' | sort | uniq -d

# Symbols of a library
mkdir tmp && cd tmp && ar45 x ../mylib.lib && nm45 -g *.o45
```

## Supported Formats

Only `.o45` (magic `$01 $00 "o45"`) is accepted. The reader also contains the 16-bit `.o65` code path (selected when the `SIZE32` mode bit is clear) and the `CPU_EXT` handling, but files with the standard `.o65` magic (`"o65"`) are rejected with `invalid magic`. cc65 objects are detected and rejected with a specific message.

## Code overlay files

ln45 describes the overlays and their symbols in `<program>.ovd`, next to their code in `<program>.ov1` (see [ln45 Code Overlays](ln45.md#code-overlays)). nm45 reads either file (from a `.ov1` it reads the `.ovd` next to it) and lists each symbol at the address it runs at, as `T`, with the overlay it is in:

```
$ nm45 ovldemo.ovd
0000af1f T _hanoi_moves  [overlay hanoi]
0000ae87 T _is_prime  [overlay primes]
0000ad00 T _primes_count  [overlay primes]
```

`-h` (or `-S`/`-s`) prints the overlays: where each one is kept in far memory and where it runs.

```
$ nm45 -h ovldemo.ovd
code overlays (copied), run at $AD00, 3 overlays, file loaded at $50000
  1 primes           kept $50000-$501EA  runs $AD00-$AEEA  491 bytes
  2 hanoi            kept $501EB-$5046B  runs $AD00-$AF80  641 bytes
  3 words            kept $5046C-$505AC  runs $AD00-$AE40  321 bytes
```

`-p` (unsorted), `-n` (by overlay and address), `-R` and `-A` apply; `-u` lists nothing (the overlays' references are resolved). Packed overlay files (`ln45 --pack-overlays`) are read as well. The description holds 24 bits of each overlay's far address: overlays kept in attic RAM (`$8000000`+) are shown as kept at `$00000`…, and the file as loaded at `$00000`.
