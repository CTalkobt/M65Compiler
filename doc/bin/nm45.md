# nm45 — Symbol Lister for .o45 / .o65 Object Files

`nm45` lists the symbols (imports and exports) in `.o45` and `.o65` relocatable object files. It follows the conventions of the standard Unix `nm` tool.

Both 32-bit `.o45` files (produced by `ca45 -c` or `cc45 -c`) and standard 16-bit `.o65` files (from other 6502 toolchains) are supported.

## Usage

```bash
nm45 [options] <file.o45|file.o65> [...]
```

## Output Format

Each line displays one symbol:

```
OFFSET TYPE NAME
```

- **OFFSET**: 8-digit hex address (segment-relative offset for exports, blank for imports).
- **TYPE**: Single letter indicating the symbol's segment and linkage.
- **NAME**: The symbol name as stored in the object file.

### Type Letters

| Letter | Meaning                              |
|--------|--------------------------------------|
| `U`    | Undefined — imported symbol (`.extern`) |
| `T`    | Text segment — code (`.global` in `.code`) |
| `D`    | Data segment — initialized data (`.global` in `.data`) |
| `B`    | BSS segment — uninitialized data (`.global` in `.bss`) |
| `Z`    | Zero Page / Direct Page segment (`.global` in `.zp`) |
| `W`    | Weak export — can be overridden by a strong definition |
| `A`    | Absolute — not relative to any segment |

## Options

### Symbol display
| Flag      | Description                                                |
|-----------|------------------------------------------------------------|
| `-u`      | Display only undefined (imported) symbols                  |
| `-g`      | Display only global (exported) symbols                     |
| `-n`      | Sort by address instead of name (defined symbols first)    |
| `-R`      | Reverse the sort order                                     |
| `-p`      | No sorting — display in file order                         |
| `-A`, `-o`| Prepend filename to each line (`file.o45:offset T name`)   |

### Object file inspection
| Flag      | Description                                                |
|-----------|------------------------------------------------------------|
| `-h`      | Display file header (format, CPU, mode flags, segment bases/lengths, options) |
| `-x`      | Hex dump of segment bodies                                 |
| `-r`      | Display decoded relocation table entries                   |
| `-s`      | Display segment sizes summary (one line per file)          |
| `-f`      | Display function attributes (ZP calling convention metadata)|
| `-a`      | Display all: header + relocations + sizes + symbols + func attrs |
| `-V` / `--version` | Display version and exit                        |
| `-?`      | Display help message                                       |

## Examples

### List all symbols

```
$ nm45 main.o45
         U _printf
00000000 T _main
00000000 D _counter
```

### Show only undefined (imported) symbols

```
$ nm45 -u main.o45
         U _printf
```

### Sort by address

```
$ nm45 -n program.o45
00000000 T _init
00000000 D _buffer
0000002c T _main
00000050 T _cleanup
```

### Reverse alphabetical order

```
$ nm45 -r main.o45
00000000 D _result
00000000 T _main
         U _add
```

### Search across multiple object files

Use `-A` to prepend filenames, making the output `grep`-friendly:

```
$ nm45 -A *.o45 | grep _main
main.o45:00000000 T _main
math.o45:         U _main
```

This shows that `main.o45` defines `_main` and `math.o45` references it.

### Find undefined symbols (missing functions)

```bash
$ nm45 -u -A *.o45 | sort | uniq
main.o45:         U _printf
math.o45:         U _malloc
util.o45:         U _strlen
```

These are symbols that must be provided by a library or other object file during linking.

### Check calling convention metadata

For objects compiled with ZP calling convention (`-fzpcall`):

```bash
$ nm45 -f main.o45
```

Shows `.zp_uses`, `.zp_clobbers`, `.reg_clobbers` directives in function attributes section.

### Multi-file listing (without -A)

Without `-A`, multiple files get headers:

```
$ nm45 main.o45 math.o45

main.o45:
         U _add
00000000 T _main
00000000 D _result

math.o45:
00000000 T _add
```

### Inspect file header

```
$ nm45 -h main.o45
File:    main.o45
Format:  .o45 (32-bit)
CPU:     45GS02 ($45)
Mode:    $8800 (SIZE32 CPUEXT)
Text:    base=$0000  len=28
Data:    base=$001C  len=11
BSS:     base=$0000  len=0
ZP:      base=$0000  len=0
Options:
  type=$02 OS [05]
  type=$03 ASM "ca45"
```

### Display relocation entries

```
$ nm45 -r main.o45
Text relocations (3):
  0006  R_LOW       DATA
  0008  R_HIGH      DATA    extra=$1C
  000C  R_WORD      EXTERN  _puts
```

### Segment sizes (like `size`)

```
$ nm45 -s *.o45
    text     data      bss       zp    total  filename
      28       11        0        0       39  main.o45
       7        0        0        0        7  crt0.o45
      41        0        0        0       41  puts.o45
```

### Full dump

```
$ nm45 -a main.o45
```

Displays header, relocations, sizes, and symbols in one output.

## Supported Formats

| Format | Extension | Width | Description |
|--------|-----------|-------|-------------|
| `.o45` | `.o45`    | 32-bit | MEGA65 relocatable objects (produced by `ca45 -c` or `cc45 -c`) |
| `.o65` | `.o65`    | 16-bit | Standard Andre Fachat 6502 relocatable objects (from xa65, cc65, etc.) |

Both formats share the same magic bytes (`$01 $00 "o65"`), option structure, relocation encoding, and symbol table layout. The reader auto-detects the width from the `SIZE32` mode bit. 16-bit values are widened to 32-bit internally.

The `CPU_EXT` mode bit is also handled: when set, an extended CPU ID byte is read after the segment fields (e.g., `$45` for 45GS02, `$03` for 65CE02).

## Relation to the Toolchain

`nm45` reads object files produced by:
- `ca45 -c input.s -o output.o45` — assembler in relocatable mode
- `cc45 -c input.c -o output.o45` — C compiler in relocatable mode
- Any `.o65`-compatible toolchain (xa65, cc65, etc.)

It is the primary diagnostic tool for inspecting symbol tables before linking with `ln45`.

## Debugging Workflows

### Verify symbol exports before linking

Before linking, check that all required symbols are exported:

```bash
# List all exported symbols
$ nm45 -g *.o45

# Check if specific symbol exists
$ nm45 -g -A *.o45 | grep _malloc
```

### Find unresolved references

```bash
# Get all undefined symbols
$ nm45 -u *.o45

# Check which object files reference a symbol
$ nm45 -u -A *.o45 | grep _printf
main.o45:         U _printf
puts.o45:         U _printf

# Find symbols defined but not used (dead code)
$ comm -23 <(nm45 -g *.o45 | cut -d' ' -f3 | sort) \
           <(nm45 -u *.o45 | cut -d' ' -f3 | sort)
```

### Analyze library contents

Before linking a library, inspect what symbols it exports:

```bash
# Extract library and list symbols
$ ar45 -x mylib.lib
$ nm45 -g *.o45
$ rm *.o45

# Or use nm45 directly on individual library members (if available)
```

### Check segment sizes

```bash
$ nm45 -s *.o45

# Total code size
$ nm45 -s *.o45 | awk '{sum += $1} END {print sum " bytes"}'

# Find largest module
$ nm45 -s *.o45 | sort -k1 -rn | head -5
```

### Validate object file consistency

```bash
# Check that all symbols are consistently defined
$ nm45 -g -A main.o45 > main_exports.txt
$ nm45 -g -A math.o45 > math_exports.txt

# Look for duplicate exports (error during linking)
$ cat main_exports.txt math_exports.txt | cut -d' ' -f3 | sort | uniq -d
```
