# ar45 — Archiver for .o45 Object Files

`ar45` creates and manages `.lib` static library archives of `.o45` relocatable object files. Libraries enable selective linking — `ln45` only pulls in the members needed to resolve undefined symbols.

## Usage

```bash
ar45 <command> <archive.lib> [files...]
ar45 -V | --version
ar45 -? | --help
```

The command is a single letter without a dash (`ar45 c`, not `ar45 -c`). `ar45` reads no configuration file.

`-v` … `-vvvv` anywhere among the arguments log on stderr as `[ar45:LEVEL] …` (the toolchain's format, `include/Logger.hpp`); cumulative, at most `-vvvv`; `-v0` off: the archive read and the members added, replaced and removed (`-v`), each member's exported symbol count (`-vv`) and its symbols (`-vvv`).

## Commands

| Command | Description |
|---------|-------------|
| `c` | Create (or overwrite) an archive from the given `.o45` files |
| `t` | List archive members (name and size) |
| `x` | Extract all members into the current directory (existing files are overwritten) |
| `s` | Print the global symbol index (`symbol [member]`) |
| `a` | Add files to an existing archive; a member with the same file name is replaced |
| `d` | Delete the named members (`ar45: NAME: not found in archive` for unknown names) |

Members are stored under their base file name (`obj/math.o45` becomes `math.o45`); `d` takes that name. After `c`, `a` and `d` the symbol index is rebuilt from the export tables of all members (a file that is not a valid `.o45` is stored but contributes no symbols).

## Archive Format (`.lib`)

```
magic         4 bytes     "a45\0"
version       1 byte      $01
member_count  4 bytes LE
symbol_count  4 bytes LE
[symbol index: symbol_count entries]
  name        NUL-terminated
  member_idx  4 bytes LE   (index into the member list)
[members: member_count entries]
  name_len    2 bytes LE
  name        name_len bytes (base file name, no NUL)
  data_len    4 bytes LE
  data        data_len bytes (.o45 file content)
```

The index lists every export of every member, weak ones included, in member order; the same name can appear for several members (cc45 objects all export weak constants such as `__zp_scratch` and `cc45.mode_zp`). `ln45` pulls the first member whose index entry matches an undefined symbol.

## Examples

### Create and inspect a library

```bash
cc45 -c addm.c -o addm.o45
cc45 -c mulm.c -o mulm.o45
cc45 -c slen.c -o slen.o45
ar45 c my.lib addm.o45 mulm.o45 slen.o45
```

```
Created my.lib (3 members, 34 symbols, 2122 bytes)
```

```
$ ar45 t my.lib
addm.o45 (527 bytes)
mulm.o45 (492 bytes)
slen.o45 (469 bytes)

$ ar45 s my.lib | grep '^_add'
_add [addm.o45]
_add__param_a [addm.o45]
_add__param_b [addm.o45]
_add__sac [addm.o45]
```

### Link with a library

```bash
ln45 -basic -o program.prg main.o45 my.lib -l c45.lib
# or
ln45 -basic -o program.prg main.o45 -l my.lib -l c45.lib
```

If `main.o45` imports only `_add`, only `addm.o45` is linked (it shows up as `my.lib(addm.o45)` in an `ln45 -M` map). Dependencies between members, and between libraries, are resolved iteratively: if `addm.o45` imported `_slen`, `slen.o45` would be pulled in as well.

### Update, remove, extract

```bash
cc45 -c mulm.c -o mulm.o45
ar45 a my.lib mulm.o45        # Updated my.lib (3 members, 34 symbols)
ar45 d my.lib slen.o45        # Updated my.lib (2 members)
mkdir out && cd out && ar45 x ../my.lib
# x addm.o45 (527 bytes)
# x mulm.o45 (492 bytes)
```

### One library per project area

```bash
ar45 c libs/graphics.lib obj/sprite.o45 obj/palette.o45
ar45 c libs/physics.lib  obj/collision.o45 obj/velocity.o45
ln45 -basic -o game.prg game.o45 -l libs/graphics.lib -l libs/physics.lib -l c45.lib
```

Keep one function (or a small group of related functions) per member: linking is per member, so everything in a pulled member ends up in the program.

Objects in a library must follow the calling convention of the program or rely on ln45's thunks (see [ln45](ln45.md#calling-convention-thunks)); build ZP-convention libraries with the default `cc45` and stack-convention ones with `-fno-zpcall`.
