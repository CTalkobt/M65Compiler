# al45 — MEGA65 assembly linter

`al45` checks ca45 assembly for MEGA65-specific mistakes and reports them by
rule (#64, #199). It is the same program as `ca45` (`bin/al45` is a link to
`ca45`) started under another name: it parses exactly what ca45 assembles
(the preprocessor, `#include`, macros, ca45's addressing modes), runs no
optimizer and writes no output file. The design and the planned rules are in
`doc/architecture/lint.md`.

Hand-written assembly is the primary target: no rule needs cc45's
`proc`/`.func_flags` scaffolding, and common idioms (falling through between
routines, data after a `jsr`, `bit` to skip a byte, self-modified operands,
a jump through the stack, a routine that pulls its return address) are not
reported.

## Usage

```bash
al45 [options] file.s45
al45 -c -Ilib/stdlib_asm file.s45     # a relocatable object: the cc45 profile
al45 --format=sarif file.s45 > out.sarif
al45 --list-rules
al45 --explain=mega65-rom-call-bp
```

| Option | Description |
|--------|-------------|
| `-c` | Lint as a relocatable object (what `ca45 -c` assembles): the default profile is `cc45`. |
| `-I<path>`, `-D<name>[=<val>]`, `--cpu 6502` | As for ca45. |
| `--checks=LIST` | Rule globs, applied in order: `mega65-*`, `-mega65-unused-label`. |
| `--disable=ID[,ID]` | Turn rules off (as `--checks=-ID`). |
| `--severity=ID=LEVEL` | A rule's level: `off`, `info`, `warning`, `error`. |
| `--profile=cc45` / `standalone` | The profile (see below). |
| `--config=FILE` | Read this configuration instead of the default files. |
| `--format=text` / `json` / `sarif` | Output format (default text). |
| `--list-rules` | The rules, their level in force and their profile. The profile here is the configuration's or `--profile`'s, else `standalone` (`-c` is not looked at): `al45 --profile=cc45 --list-rules` shows the cc45 rules' levels instead of `off`. |
| `--explain=ID` | A rule's description. |
| `--suggest-clobbers` | Also print, for each named `proc`, the `.reg_clobbers` and `.flag_clobbers` al45 works out from its code (and whether it is a leaf), one line per proc before the findings. |
| `-v` … `-vvvv` | Diagnostics of al45 itself on stderr (the configuration files read); the findings do not change. |
| `-V`, `--version`; `-?`, `-h`, `--help` | The version (`al45 v…`); the options above. |

Findings go to stdout. Text lines are
`file:line:col: warning: message [mega65-rule-id]`. JSON is an array of
`{file, line, column, severity, rule, message}`; SARIF is version 2.1.0, for
GitHub Code Scanning and the VS Code SARIF viewer. The exit status is 1 when
a finding has the level `error` (or the source does not assemble), else 0.
ca45's own warnings (e.g. `-Woverflow`) still go to stderr.

## Profiles

- **`cc45`**: code linked with crt0 and c45.lib (ln45): rules about cc45's
  conventions apply (the relocated base page, the 16-bit stack). The default
  for `-c`.
- **`standalone`**: a flat binary (demos, a program not linked with
  c45.lib): CPU and hardware rules only. The default without `-c`.

## Rules

| Rule | Default | Profile | What |
|---|---|---|---|
| `mega65-unreachable` | warning | all | Code after `jmp`/`bra`/`lbra`/`rts`/`rti`/`rtn` with no label in between. Data (`.byte`, …) is not code. |
| `mega65-unused-label` | info | all | A local label (`@name`) nothing refers to. Global labels are not reported, nor cc45's block labels (`@entry`, `@for_inc3`, … in a proc with `.var cc45.fp`). |
| `mega65-no-bp-mode` | warning | all | `ldz $xx`, `lda`/`sta $xx,y`, `jmp ($xx)`, `phw $00xx`: no base-page form, assembled as absolute `$00xx` (ignores B). ca45 warns about these when assembling. |
| `mega65-page1-stack` | warning | all | A page-1 stack access (`lda $0101,x`) in the cc45 profile or a file that selects the 16-bit stack (`cle`). |
| `mega65-dma-trigger-order` | warning | all | `$D701`/`$D702`/`$D704` (the DMA list address) written after `$D700`/`$D705` (the trigger) in the same straight-line code, with no later trigger (which would make them the next job's). |
| `mega65-io-personality` | info | standalone | A VIC-III/IV register (`$D030`-`$D07F`) written in a file that never writes the `$47 $53` knock to `$D02F`. |
| `mega65-rom-call-bp` | warning | cc45 | `jsr` to the ROM (`$E000` and up) not between `jsr __bp_rom` and `jsr __bp_prog` (or `__rom_call`). A routine that sets B itself (`tab`) and a call whose address a store patches (`sta label+1`) are not reported. |
| `mega65-unnamed-proc-attrs` | warning | all | `.func_flags` in an unnamed `proc` (ignored: name it `proc <name>`). ca45 warns about it when assembling. |
| `mega65-flag-stale` | warning | all | A comparison (`cmp`, `cpx`, `cpy`, `cpz`, `cmpq`) whose flags something sets again before a branch reads them: `cmp #5 / ldx #0 / beq` branches on X. Reported at the branch, or at the comparison when all its flags are set again unread (a call sets them: `cpx #3 / jsr f / bne`). `php` / `plp` around the load, or a later reader of the carry (`cmp / lda / beq / bcs`), make it used. |
| `mega65-stack-balance` | warning | all | `rts` / `rti` reached with bytes still pushed, on some path from a routine's entry (a `proc`, a `jsr`'s target, an exported label, a global label nothing runs into). Two bytes before `rts` are a jump through the stack and are not reported. |
| `mega65-clobber-mismatch` | warning | all | A `proc` that changes a register its `.reg_clobbers` does not list, or a flag its `.flag_clobbers` does not; a proc declared `leaf` that calls. A register pushed and pulled again is not changed. Calls of procs in the file count with what they declare. |
| `mega65-zp-param-block` | warning | cc45 | A byte of the parameter block (`$10`-`$2F`) read after `jsr _name` (a C function) with no store to it since: the call may have changed it. |
| `mega65-lib-temps` | warning | cc45 | The same for the library's temporaries (`$F6`-`$FC`). |
| `mega65-dead-reg-write` | info | all | A load or transfer whose register is written again on every path before anything reads it, and whose N and Z nothing tests. |
| `mega65-redundant-load` | info | all | A register loaded with the constant or the byte it already holds (straight-line code; `sta $20 / lda $20`). |
| `mega65-dead-store` | info | all | A base-page byte stored twice with nothing reading it between (straight-line code). |

### The rules on data flow

The last eight follow what each instruction reads and writes (A, X, Y, Z,
the flags N Z C V, the stack) through the file's branches and jumps. They
err towards silence:

- A call, a return, a jump out of the file, a simulated operation
  (`mul.32`, `ldax.fp`, …), an instruction whose operand a store patches and
  a write to the hypervisor's trap registers (`$D640`-`$D67F`) read every
  register: a value is "unused" only when every path overwrites it first.
- "Straight-line" rules forget what they know at a label, a call and a
  branch.
- I/O registers (`$D000`-`$DFFF`) are never the same twice and a read of one
  is never wasted.
- What a macro repeats (several instructions from one source line) and what
  cc45 generates (a proc with `.var cc45.fp`: left for ca45's optimizer) is
  not reported as wasted work.
- `mega65-zp-param-block` / `mega65-lib-temps` take `jsr _name` (not
  `__name`) for a C function. A callee in the same file that declares
  `.zp_clobbers` is believed; after a call of anything else al45 knows
  nothing and says nothing.
- `mega65-stack-balance` gives up on a routine that sets the stack pointer
  (`txs`), pulls more than it pushed, uses `rtn`, or reaches one place with
  two different depths (a loop that pushes).

Operands that name a relocatable symbol (a label of a segment, BSS, an
`.extern`) have no address until linked and are not judged by value.

## Suppressing a finding

```asm
    lda $0101,x         ; NOLINT(mega65-page1-stack): the 8-bit stack here
    ; NOLINTNEXTLINE(mega65-unreachable)
    inx
    sta $20             ; NOLINT (every rule on this line)
```

A reason after the comment is a good habit; the library's suppressions
carry one.

## Configuration: `.cc45-lint.yml`

The first `.cc45-lint.yml` found from the source file's directory upward,
over `~/.config/m65/cc45-lint.yml`; the command line over both (#278):

```yaml
profile: standalone
asm_rules:
  - id: mega65-dma-trigger-order
    severity: error
  - id: mega65-unused-label
    severity: off
  - id: mega65-unreachable
    message: "dead code"          # replaces the built-in message
overrides:
  mega65-no-bp-mode: error
```

`c_checks` (the C linter's) is read and left to it. `pattern:` (user-written
rules) is not supported yet and is an error.

The keys (a key not listed is an error, *"unknown key 'x' (profile, c_checks,
asm_rules, overrides, options)"*, and so is one inside `c_checks` or an
`asm_rules` entry):

| Key | Value |
|-----|-------|
| `profile` | `cc45` or `standalone` (as `--profile=`) |
| `c_checks.enabled` | cl45's rules on or off: globs, `-` removes, in order (as `--checks=`) |
| `c_checks.options` | Rule options, `name: value` |
| `asm_rules` | A list of al45's rules by `id`, each with `severity`, `message` (the text that replaces the built-in one) and `options` |
| `overrides` | `rule-id: off`, `info`, `warning` or `error`, for either linter (as `--severity=`) |
| `options` | Rule options, `name: value`, for either linter |

The three `options` maps (top-level, `c_checks.options`, an `asm_rules`
entry's) fill one table: an option is named by the rule it belongs to, and
the last one read wins. The only option so far is `mega65-stack-frame-limit`
(cl45: the largest stack frame not reported, default 256 bytes).

ca45's own configuration is read too, as al45 is ca45: `~/.config/m65/ca45.conf`,
`./.ca45rc`, `CC45_INCLUDE` (its `-I`, `-D` and `--cpu` matter; the optimizer
and output options have no effect).

## Notes

- In an editor: the language server (`tools/ide/lsp-server`) runs al45 on the
  text being edited (`al45 --format=json <file>`, so the `standalone` profile
  unless `.cc45-lint.yml` sets one) and shows its findings as diagnostics, the
  rule as the code. Settings: `m65.lint.enabled` (on by default) and
  `m65.al45Path` (else the `al45` beside ca45); `tools/ide/IDE-SETUP.md`.
- User-written rules (`pattern:`) and the style rules (`mega65-style-*`)
  are not implemented.
- The library's assembly lints clean: `src/test/test_al45.sh`. The rules on data flow found, in the library, 45
  `.flag_clobbers` / `.reg_clobbers` lists that left out a flag or register
  the proc changes (`_dl_push_back`: X; `___tgi_n_glyph`: Y), 13 loads of a
  value the register already held and one of a value never used. cc45's own output for the C library was
  checked when the rules were written (phase 2 found the `rts` cc45 left
  after an interrupt handler's `rti`).
