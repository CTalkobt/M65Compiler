# al45 — MEGA65 assembly linter

`al45` checks ca45 assembly for MEGA65-specific mistakes and reports them by
rule (#64, #199). It is the same program as `ca45` (`bin/al45` is a link to
`ca45`) started under another name: it parses exactly what ca45 assembles
(the preprocessor, `#include`, macros, ca45's addressing modes), runs no
optimizer and writes no output file. The design and the planned rules are in
`doc/architecture/lint.md`.

Hand-written assembly is the primary target: no rule needs cc45's
`proc`/`.func_flags` scaffolding, and common idioms (falling through between
routines, data after a `jsr`, `bit` to skip a byte, self-modified operands)
are not reported.

## Usage

```bash
al45 [options] file.s45
al45 -c -Ilib/stdlib_asm file.s45     # a relocatable object: the cc45 profile
al45 --format=sarif file.s45 > out.sarif
al45 --list-rules
al45 --explain=mega65-rom-call-bp
```

| Option | Description |
|--------|-------------|
| `-c` | Lint as a relocatable object (what `ca45 -c` assembles): the default profile is `cc45`. |
| `-I<path>`, `-D<name>[=<val>]`, `--cpu 6502` | As for ca45. |
| `--checks=LIST` | Rule globs, applied in order: `mega65-*`, `-mega65-unused-label`. |
| `--disable=ID[,ID]` | Turn rules off (as `--checks=-ID`). |
| `--severity=ID=LEVEL` | A rule's level: `off`, `info`, `warning`, `error`. |
| `--profile=cc45` / `standalone` | The profile (see below). |
| `--config=FILE` | Read this configuration instead of the default files. |
| `--format=text` / `json` / `sarif` | Output format (default text). |
| `--list-rules` | The rules, their level in force and their profile. |
| `--explain=ID` | A rule's description. |
| `-v` … `-vvvv` | Diagnostics of al45 itself on stderr (the configuration files read); the findings do not change. |

Findings go to stdout. Text lines are
`file:line:col: warning: message [mega65-rule-id]`. JSON is an array of
`{file, line, column, severity, rule, message}`; SARIF is version 2.1.0, for
GitHub Code Scanning and the VS Code SARIF viewer. The exit status is 1 when
a finding has the level `error` (or the source does not assemble), else 0.
ca45's own warnings (e.g. `-Woverflow`) still go to stderr.

## Profiles

- **`cc45`**: code linked with crt0 and c45.lib (ln45): rules about cc45's
  conventions apply (the relocated base page, the 16-bit stack). The default
  for `-c`.
- **`standalone`**: a flat binary (demos, a program not linked with
  c45.lib): CPU and hardware rules only. The default without `-c`.

## Rules

| Rule | Default | Profile | What |
|---|---|---|---|
| `mega65-unreachable` | warning | all | Code after `jmp`/`bra`/`lbra`/`rts`/`rti`/`rtn` with no label in between. Data (`.byte`, …) is not code. |
| `mega65-unused-label` | info | all | A local label (`@name`) nothing refers to. Global labels are not reported, nor cc45's block labels (`@entry`, `@for_inc3`, … in a proc with `.var cc45.fp`). |
| `mega65-no-bp-mode` | warning | all | `ldz $xx`, `lda`/`sta $xx,y`, `jmp ($xx)`, `phw $00xx`: no base-page form, assembled as absolute `$00xx` (ignores B). ca45 warns about these when assembling. |
| `mega65-page1-stack` | warning | all | A page-1 stack access (`lda $0101,x`) in the cc45 profile or a file that selects the 16-bit stack (`cle`). |
| `mega65-dma-trigger-order` | warning | all | `$D701`/`$D702`/`$D704` (the DMA list address) written after `$D700`/`$D705` (the trigger) in the same straight-line code, with no later trigger (which would make them the next job's). |
| `mega65-io-personality` | info | standalone | A VIC-III/IV register (`$D030`-`$D07F`) written in a file that never writes the `$47 $53` knock to `$D02F`. |
| `mega65-rom-call-bp` | warning | cc45 | `jsr` to the ROM (`$E000` and up) not between `jsr __bp_rom` and `jsr __bp_prog` (or `__rom_call`). A routine that sets B itself (`tab`) and a call whose address a store patches (`sta label+1`) are not reported. |
| `mega65-unnamed-proc-attrs` | warning | all | `.func_flags` in an unnamed `proc` (ignored: name it `proc <name>`). ca45 warns about it when assembling. |

Operands that name a relocatable symbol (a label of a segment, BSS, an
`.extern`) have no address until linked and are not judged by value.

## Suppressing a finding

```asm
    lda $0101,x         ; NOLINT(mega65-page1-stack): the 8-bit stack here
    ; NOLINTNEXTLINE(mega65-unreachable)
    inx
    sta $20             ; NOLINT (every rule on this line)
```

A reason after the comment is a good habit; the library's suppressions
carry one.

## Configuration: `.cc45-lint.yml`

The first `.cc45-lint.yml` found from the source file's directory upward,
over `~/.config/m65/cc45-lint.yml`; the command line over both (#278):

```yaml
profile: standalone
asm_rules:
  - id: mega65-dma-trigger-order
    severity: error
  - id: mega65-unused-label
    severity: off
  - id: mega65-unreachable
    message: "dead code"          # replaces the built-in message
overrides:
  mega65-no-bp-mode: error
```

`c_checks` (the C linter's) is read and left to it. `pattern:` (user-written
rules) is not supported yet and is an error.

## Notes

- Rules on data flow (stale flags, stack balance, dead stores, declared
  clobbers) are planned (`doc/architecture/lint.md`, phase 3).
- The library's assembly lints clean: `src/test/test_al45.sh`. So does
  cc45's own output for the C library and the examples (checked when the
  rules were written; it found the `rts` cc45 left after an interrupt
  handler's `rti`).
