HOW IT WORKS
================================================================================

Traditional Approach (OLD - Memory Dumps):
  xemu runs with -dumpmem
  Script polls memory at $4000 every 100ms
  Waits for marker byte to appear
  Timeout after 40+ seconds
  Unreliable, slow, limited

New Approach (SERIALTCP):
  Python listener starts, binds to port 27513
  Listener waits for connection
  xemu starts with -serialtcp 127.0.0.1:27513
  xemu connects to listener
  printf() output → UART → TCP → Listener
  Listener parses output, detects "RESULT:" line
  Test completes immediately when done
  No polling, no timeout, automatic completion

WHAT'S BLOCKING FULL SUCCESS
================================================================================

XEM U Buffer Overflow in ethernet65.c:
  - xemu boot sequence initializes ethernet
  - Hypervisor writes MAC address to registers
  - Buffer overflow in xemu's ethernet handler
  - Causes: "*** buffer overflow detected *** terminated"
  - Connection closes before printf() executes
  - Solution: Apply fixes from dev-buffer-fixes branch

Needed xemu Fixes:
  1. ethernet65.c line 539-548:
     Add bounds checking for MAC address array access
     Validate mac_idx is in range [0, 5]

  2. inject.c line 141-142, 167-168:
     Increase buffer size from strlen(arg)+1 to CMDBUF_MAX
     Use strncat() instead of strcat()

Current xemu Status:
  - System xemu at /usr/local/bin/xemu-xmega65 (Sep 25, 2026)
  - Does NOT have buffer overflow fixes
  - Crashes during hypervisor initialization
  - Solution: Use fixed xemu or apply patches
