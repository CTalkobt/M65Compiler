# m65compiler Examples

These examples demonstrate different features of the m65compiler. [doc/examples](../doc/examples/README.md) shows each one's screen. `python3 examples/capture_screens.py` (from the project root, after building) remakes those pictures.

## Available Examples

### The examples disk

- **disk/** - All the examples on one D81 disk image with a menu: `make -C examples/disk` (disk45 `create`/`add`/`validate`; the menu is a basic45 program saved as `AUTOBOOT.C65`, so the MEGA65 runs it at start, and as `MENU`; a key `DLOAD`s an example). `make -C examples/disk run` starts xemu with it.

### C Examples

- **hello_world/** - Classic hello world program that prints to console
- **unit_convert/** - Unit conversion example demonstrating arithmetic operations
- **stdlib/string_h/** - String library examples (strlen, strcmp, strcpy, etc.)
- **stdlib/stdlib_h/** - Standard library examples (atoi, itoa)
- **stdlib/ctype_h/** - Character type examples for classification and conversion
- **palette_fade/** - Demonstrates mixed C and assembly code with calling conventions and MEGA65 hardware register access. C controls fade timing while assembly manipulates the palette.
- **hello_linked/** - Minimal linked C program showing the `cc45 -c` + `ln45` relocatable build workflow.
- **multi_module/** - Multi-file project with shared header, separate compilation of 3 modules, and linking. Demonstrates extern, struct pass/return, and the standard build workflow.
- **bitfield_registers/** - MEGA65 VIC-III/VIC-IV register access using C bitfield structs: `$D031` and `$D054` (layouts per the MEGA65 Book and mega65-core's `iomap.txt`), sprite enables, and VIC-III extended attributes (blink/reverse/bold/underline in colour RAM).
- **game_of_life/** - Conway's Game of Life on the 80x25 text screen (`$0800`) with wrapping edges. Demonstrates 2D arrays, nested loops, `signed int` arithmetic (plain `int` is unsigned in cc45), and direct screen RAM access.
- **memset_screen/** - Fill screen with character codes 0-255, demonstrating memset with direct screen RAM writes.
- **text_scroller/** - Horizontal text scroller demonstrating mixed C and assembly (arguments through shared variables, so both calling conventions work), with a bouncing ball (hardware sprite 0, VIC-IV 16-bit sprite pointers) that passes in front of and behind the reverse-video message.
- **far_scroller/** - A 400x25 landscape map allocated with `far_malloc` in bank 4, scrolled with one `dma_copy_far` per row each frame (parallax sky), colours written straight into colour RAM at `$FF80000` with `dma_fill_far`.
- **invaders/** - A Space Invaders game: game objects as structs with inheritance and virtual `update()`/`draw()` and an operator-overloaded `Vec2`; the character set copied to bank 4 with `dma_copy_far` and redefined (aliens, shields); 16-colour VIC-IV sprites (cannon, UFO); joystick or keyboard input (`key_pressed`); SID sound effects and the marching beat. An attract mode plays by itself; FIRE/SPACE starts a game, RUN/STOP quits. The high score is kept on disk (`INVADERS.HI`, a SEQ file on device 8, written with `fopen`/`fwrite` after a game that beat it and read at the start). The art is generated by `gen.py` from ASCII pictures.
- **mandelbrot/** - A Mandelbrot set viewer: VIC-IV full-colour character mode as a 320x192 bitmap (one byte per pixel in bank 4), a 240-colour palette cycled through the palette registers, the iteration in 45GS02 assembly (32-bit Q register, the hardware multiplier, 4.28 fixed point), progressive rendering with border checks, cells copied with DMA, scrolling by moving the cell pointers (only the exposed edge renders). Keys come from the hardware typing queue ($D610, ASCII, with key repeat): cursor keys/WASD (or a joystick) move, Z/1 and X/2 (or fire) zoom, +/- cycling speed, I/O iterations, P palette, C cycling on/off, R reset, ? or H a help screen, RUN/STOP quits.
- **musicgen/** - A random music generator: seven styles (pop, rock, blues, jazz, classical, ambient, chiptune), each with its own chords and a Markov table of chord changes (cadences fixed: a half cadence at bar 4, dominant-tonic at the end), AABA form (12-bar blues with call and response), melodies from rhythm cells and a reused motif with chord tones on the strong beats, steps between, leaps resolved by a step back and an arch contour, voice-led chords, per-style bass lines (walking, boogie, Alberti) and drums with swing and fills. 14 SID instruments (ADSR, pulse-width modulation, vibrato) on four SIDs (stereo). Keys: 1-7 style, +/- tempo, N new song, L/C/B instruments, D drums, SPACE pause, RUN/STOP quit. `make check` composes songs of every style in a test build and checks the melodies against the chords and scales (`check_songs.py`).
- **calc_graph/** - A scientific calculator that plots: expressions with + - * / ^, parentheses, implicit multiplication, x, pi, e, ans and sin cos tan atn sqrt log exp abs int, compiled to bytecode (shunting-yard) and run by an evaluator that dispatches with computed goto, in cc45's (ROM) floats; expressions with x are plotted (up to four curves) on a full-colour 320x128 graph below the text. A raster interrupt (an `__interrupt` handler behind a stub at the KERNAL's `$0314` vector that also works while the float routines have the BASIC ROM mapped in) changes the colours at the split and counts frames. Uses GCC extensions: computed goto, nested functions, statement expressions with `typeof`, case ranges, designated initializers, `?:`, attributes. Commands `clear` and `range N`; RUN/STOP quits. `make check` runs a test build (32 checks at `$C0C0`).
- **rtc_clock/** - The real-time clock in big digits (a 5x7 font of reverse spaces) with the weekday, date, a seconds bar and a stopwatch counted in video frames. The RTC's BCD registers at `$FFD7110`-`$FFD7116` are outside the 16-bit address space: a `dma_copy_far` copies them each frame. Keys: H 12/24 hours, S stopwatch start/stop, R reset, C colours, RUN/STOP quit. `make check` reads the RTC twice, a second apart, in xemu.
- **rogue/** - A mini rogue-like: a random dungeon per level (a 3x3 grid of rooms joined along a random spanning tree), rooms lit when entered and an explored-map memory, monsters by depth that chase you when they see you, bump-to-attack combat, potions, gold, weapons and armour, experience levels; find the amulet on depth 8. Monsters and items are structs inheriting a position (`struct Monster : Thing`). Keys: cursor keys or h/j/k/l and y/u/b/n, `.` wait, `>` down, R new game, RUN/STOP quit; a joystick in port 2 too. `make check` tests levels from fixed seeds, scripted moves and a random walk.
- **hanger/** - Hangman with a different victim on the gallows each level: a human, a cat, a duck, a giraffe, an elephant and an octopus, a part added for each wrong letter. One player against the computer (3 lives) or two players setting words for each other. The words are the 500 most common English words of 3+ letters (`words.txt`), sorted by how hard they are to guess, harder each level. The pictures are drawn in Python with PIL shapes (`gen_gfx.py`) and cut into character cells: each level's glyphs are copied into a character set in bank 4 with `dma_copy_far` when it starts, and each stage of the drawing is stored as the cells it changes. Tried letters change shape, not only colour. The sounds are tune45 text (`sounds.txt`) played by `<audio_tune.h>`. `make demo` builds a version that plays by itself.
- **fcm_graphics/** - Full-colour characters (64 bytes, a byte a pixel, each pixel a palette entry): conio's full-colour mode gives every character its own background (`fcm_enable`, `fcm_putch`, `fcm_cputs`, `fcm_cprintf`, `fcm_fill_rect`: a title and a table of the 16 colours), and the program's own characters make a 36x21-character plasma (the screen's left half) and a bar of the palette entries it uses (`fcm_putglyph`, glyphs made in bank 4 with `dma_copy_far`). The plasma moves by palette cycling alone: each frame the 64 entries are rewritten one step further round. Keys: SPACE pause, RUN/STOP quit. `make check` builds a test that runs 100 frames and reports on the screen.
- **tunes/** - The pfest game's music (12 tunes, its `music.txt` as it is) played by the library's tune player (`<audio_tune.h>`) from a raster interrupt, as a game plays its music: `tune_update` in an `__interrupt` handler (behind a small stub at the KERNAL's `$0314` vector), the main loop only drawing and reading keys. `tune45 convert` makes `music.c` of the text in the build. Shows each voice's note (`tune_note`) as a bar; keys for the tune, stop/play, tempo, vibrato, transpose and the game's "sick" music (faster, a wobble, a voice out of tune: `tune_tempo`, `tune_vibrato`, `tune_detune`). `make play` plays it on the PC (`tune45 play`); `make check` builds a test that plays from the interrupt and reports.
- **forth/** - A tiny Forth, a calculator you can program: `: name ... ;` definitions, `if`/`else`/`then`, `do`/`loop`, `begin`/`until`, variables and constants, `*/`, `sqrt`, hex/decimal. Definitions compile to threaded code run by an inner interpreter that dispatches with GCC's computed goto (`goto *ops[code[ip++]]`); also statement expressions, case ranges and a nested function. `make check` runs a test script in xemu. Keys: type a line and RETURN; BYE or RUN/STOP quits.
- **vic4_colors/** - Steps the border and background colours through a struct overlay on `$D020`/`$D021`, ending on white with black text.
- **stdlib/math_h/** - Math library examples (min/max, gcd/lcm)

### BASIC Examples

- **basic/c_routines/** - A BASIC 65 program (basic45 source with labels) calling C functions: `basic45 --link routines.c menu.bas`, `SYS {name}, a, x, y` and `RREG`.

### Assembly Examples

- **asm/zpcall_prototype.s45** - Prototype for zero-page calling convention

## Building Examples

### Build all examples
```bash
make -C examples all
```

### Build a specific example
```bash
make -C examples/<example>
```

### Run an example
Individual example directories contain Makefiles with a `run` target:
```bash
make -C examples/<example> run
```

This launches the example in the xemu-xmega65 emulator (if available).

## Emulator

Examples can be executed using the **xemu-xmega65** emulator. The emulator allows you to see the program output and interact with MEGA65 hardware features.
